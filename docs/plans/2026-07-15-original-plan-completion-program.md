# Original Plan Completion Program Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `original_plan.pdf`의 연구개발 기능을 빠짐없이 구현하고, `wellnessbox-rnd`의 연구 엔진을 `wellnessbox` 프로덕션 서비스가 얇은 계약으로 호출하도록 통합한다.

**Architecture:** `wellnessbox-rnd`는 입력 계약, 지식, 안전, 효과 추정, 최적화, 상태기계, 상담, 기기 파서와 평가 근거를 소유한다. `wellnessbox`는 인증, 사용자 화면, 상품, 주문, 결제, 약국, 소분, 배송을 소유하고 R&D API 또는 버전이 고정된 생성 스냅샷만 사용한다. 기능 완료는 코드 존재가 아니라 입력부터 저장된 사후조건까지 재현되는 통합 테스트로 판정한다.

**Tech Stack:** Python 3.12, FastAPI, Pydantic, pytest, Next.js 15, React, TypeScript, Prisma, PostgreSQL, Vercel

---

## 현재 판정

- 두 저장소는 현재 프로덕션에서 함께 실행되지 않는다.
- `wellnessbox-rnd` FastAPI는 배포 대상과 프로덕션 URL이 없다.
- `wellnessbox` Vercel 프로덕션에는 `WB_RND_*` 환경변수가 없다.
- `/tips` 평가 화면은 `wellnessbox` 내부 TypeScript 연구 엔진을 사용한다.
- `/api/tips`, `/api/tips/profile`, `/api/tips/connector`, `/api/tips/agent`에는 R&D FastAPI 프록시 코드가 있지만 비활성 상태다.
- KPI 계산, 프록시 데이터, 일부 안전·추천·상태기계·기기 파서는 구현되어 있다.
- 실제 상품 카탈로그, 실제 주문·소분·배송 루프, 프로덕션 R&D 배포, 실기기·실사용 데이터는 완료되지 않았다.

## 완료 판정 규칙

- `IMPLEMENTED`: 단위 테스트와 계약 테스트가 실제 분기를 실행한다.
- `INTEGRATED`: 두 저장소 사이 요청과 응답이 실제 프로세스에서 왕복한다.
- `OPERATED`: 프로덕션에서 저장 결과와 사후조건을 다시 조회할 수 있다.
- `EXTERNAL`: 외부 기관, 실제 약사 라벨, 실제 기기 또는 법적 승인이 필요한 항목이다.
- 모든 비외부 단계가 완료되고 외부 단계에는 교체 가능한 동일 계약과 명확한 증거가 있을 때만 전체 완료로 판정한다.

## 첫 실행 범위

첫 실행은 OP-031과 OP-032를 완료했다. `wellnessbox-rnd`가 알레르기와 응급 위험 신호를 구조화 입력으로 받고, 추천 후보 생성 전에 결정론적으로 제외 또는 차단한다. `wellnessbox`의 원격 추천 클라이언트도 두 필드를 손실 없이 전달한다. OP-015는 식이 패턴 입력이 아직 없으므로 완료 처리하지 않는다.
