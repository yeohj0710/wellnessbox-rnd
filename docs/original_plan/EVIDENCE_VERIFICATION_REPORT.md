# OP-031~OP-119 증거 검증 보고서

## 검증 결과

연구 보고서 53편에 등록된 파일 경로와 보고서의 핵심 주장을 현재 저장소에서 다시 확인했다. manifest에 등록된 경로는 중복 포함 492건이고, OP 번호와 경로의 고유 조합은 447건이며, 실제 고유 파일은 189개다. 등록 경로 492건은 모두 존재한다. 최종 보고서의 내용 불일치는 0건이다.

내용 불일치 0건은 운영·배포·사람 승인까지 완료됐다는 뜻이 아니다. 저장 증거가 오래됐거나 직접 운영 기록이 없는 경우에는 보고서가 그 제한과 현재 증거 단계를 명시했다. 제한을 사실대로 기록한 항목은 보고서 내용 불일치로 세지 않았다.

## 검증 방법

각 OP의 manifest에서 `evidence.files`를 추출하고 저장소 루트를 기준으로 경로를 해석했다. 이어서 등록 파일의 현재 내용, 테스트, 저장 JSON, 해시, 실행 단계 표현을 보고서 본문과 대조했다. 마지막으로 53편의 제목, 절 수, 절별 최소 분량, 등록 경로 원문 인용, 금지 꼬리말, 반복 문장과 반복 문단을 검사했다.

447개 OP-경로 판정은 `data/original_plan/evidence/evidence_verification_ledger_v1.json`에 행별로 보존했다. 각 행에는 OP, 인용 경로, 존재 여부, 파일 SHA-256, 내용 일치 여부, 판정 비고와 보고서의 경로 원문 인용 여부가 있다. 원장 SHA-256은 `21d1388ed3912174126ae435a85aa80baa991ebd65d1b6aeb3ad0b9816319257`이다. `python scripts/verify_evidence_verification_ledger.py`는 현재 manifest·53개 보고서·189개 파일의 SHA-256을 원장과 대조하고 아래 요약을 447개 상세 행에서 다시 계산한다.

- 대상 보고서: 53편
- 등록 경로: 492건
- 고유 OP-경로 조합: 447건
- 고유 파일: 189개
- 존재하지 않는 등록 경로: 0건
- 근거 재검증에서 명시적으로 바로잡은 보고서: 32편
- 최종 내용 불일치: 0건
- manifest 등록 경로를 원문 그대로 1개 이상 인용한 보고서: 53/53편
- 3편 이상에서 반복된 문장 또는 문단: 0건
- 정확한 문자열 `확인되지 않음`: 0건

OP-039 본문에 적힌 외부 검토 자료와 사전 승인 신뢰 기준은 저장소 파일 경로가 아니라 아직 충족되지 않은 외부 의존 조건이다. 두 조건은 경로 존재 집계에서 제외했고, OP-039가 미충족 상태를 명시하도록 유지했다.

## 다시 확인하며 바로잡은 핵심 내용

- OP-034는 코드에 없는 건강 상태 별칭을 제거하고 현재 규칙의 정확한 조건 문자열로 교체했다.
- OP-038은 잘못 적힌 커밋 식별자를 `8b5f6dd`로 고쳤다. OP-039는 구현·테스트 파일 5개와 대체 계약 파일 2개를 합친 등록 경로 7개로 바로잡았다.
- OP-040은 일반 추천 실행 기록이 최종 안전 차단의 운영 증거가 아니므로 직접 확인 단계를 `INTEGRATED`로 낮췄다.
- OP-043은 현재 소스 해시가 저장 스모크와 일치하는 사실을 반영했다. OP-044는 CGM bridge와 직접 점수 경로를 분리하고 유전자 변이 출처와 점수 태그가 자동으로 결속되지 않는 제한을 명시했다.
- OP-050은 오래된 저장 증거의 매핑 8개와 현재 코드의 매핑 10개를 구분하고, QA의 합성 상품 ID를 실제 판매 증거로 해석하지 않도록 고쳤다. OP-051은 원시값과 표준화된 값을 구분했다.
- OP-052는 기존 점수 파일의 이력을 바로잡았다. OP-053은 필요한 이벤트 유형과 출처를 고쳤고 직접 확인 단계를 `IMPLEMENTED`로 낮췄다.
- OP-057은 실제 수정 원장 필드와 QA의 검증 범위를 바로잡았다. OP-058은 암시적 계획 ID와 함수명을 고치고 직접 확인 단계를 `INTEGRATED`로 낮췄다.
- OP-059~OP-065는 실제 제약 조건, 선언된 성분량, 데이터 분류, `READY` 상품 필터와 저장 스모크의 범위를 현재 코드에 맞췄다.
- OP-071~OP-078은 저장 스모크나 현재 운영 영수증이 직접 운영을 입증하지 못하므로 직접 확인 단계를 `IMPLEMENTED`로 제한했다.
- OP-105와 OP-106은 직접 확인 단계를 `INTEGRATED`로, OP-117~OP-119는 `IMPLEMENTED`로 제한했다. 검토 대기열 불일치, 오래된 집계, registry 충돌도 보고서에 남겼다.

## 남은 증거 제한

현재 보고서가 명시하는 주요 제한은 실제 배포·운영 관찰, 사람 승인, 외부 독립 검토, 오래된 스모크의 현행 소스 재생성, DB 스키마 14로 저장된 정본 계보 증거와 현재 스키마 15의 차이다. OP-039의 독립 외부 자료와 사전 승인 신뢰 기준도 아직 없다. 이 제한 때문에 manifest의 `OPERATED` 표기가 직접 확인 단계보다 높은 OP가 있으며, 각 보고서는 manifest 단계와 직접 확인 단계를 분리했다.

따라서 이 보고서가 확인하는 결론은 좁다. 등록 경로는 모두 존재하고, 최종 연구 보고서의 설명은 현재 파일과 저장 증거의 범위에 맞으며, 남은 내용 불일치는 0건이다. 운영 완료, 임상 타당성, 약사 승인 또는 사람 세션 완료는 별도 증거가 필요하다.
