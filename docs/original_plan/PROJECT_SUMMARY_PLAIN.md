# 웰니스박스 TIPS 연구개발 한눈에 보기

## 이 과제는 무엇을 해결하려는가

웰니스박스 연구개발 과제는 사용자에게 건강기능식품을 한 번 추천하고 끝내는 시스템이 아니다. 사용자의 건강 상태와 복용 정보를 바탕으로 위험한 성분을 먼저 제외하고, 남은 후보에서 목적에 맞는 조합을 고른다. 복용을 시작한 뒤에는 설문과 생활 자료를 다시 받아 효과와 이상 징후를 확인하고, 유지·조정·중단 같은 다음 행동을 정한다. 이 반복 과정을 `closed-loop`라고 부른다.

건강기능식품 선택에는 세 가지 현실적인 문제가 있다. 첫째, 임신·수유, 질환, 알레르기와 복용 약물에 따라 같은 성분도 위험할 수 있다. 둘째, 여러 제품에 든 같은 성분을 합산하지 않으면 상한을 넘기기 쉽다. 셋째, 복용 전후 상태를 같은 기준으로 재지 않으면 사용자가 실제로 좋아졌는지 알기 어렵다. 이 과제는 세 문제를 각각 구조화된 입력, 규칙 기반 안전 검사, 표준화된 복용 전후 평가로 다룬다.

연구개발의 기준은 계획서에 적힌 구현 모양이 아니라 계획서 25~26쪽의 일곱 성능 지표다. 추천 성분 포함률 80% 이상, 복용 전후 평균 개선도 0백분위 포인트 초과, 다음 행동 정확도 80% 이상, 상담 답변 정확도 91% 이상, 안전 규칙과 근거의 일치율 95% 이상, 연간 이상반응 보고 5건 이하, 웨어러블·연속혈당·유전자 자료 연동률 90% 이상을 측정하도록 설계했다.

## 사용자가 입력한 정보는 어떻게 처리되는가

시스템은 나이, 성별, 임신·수유 상태, 키와 체중을 구조화한다. 질환, 증상, 응급 위험 신호, 복용 약물, 건강기능식품, 알레르기, 식사와 생활 습관도 정해진 형식으로 받는다. 검사값에는 검사 코드, 값, 단위, 기준 범위와 측정 시각을 함께 저장한다. 설문, 건강보험, 웨어러블, 연속혈당과 유전자 자료의 이용 동의도 각각 분리한다.

같은 입력은 같은 정규화 결과와 내용 지문을 만들어야 한다. 지원하지 않는 값은 조용히 버리지 않고 오류나 추가 정보 요청으로 돌려보낸다. 서비스 사용자 식별자는 원래 값을 알아내기 어려운 가명으로 바꾼 뒤 R&D 서버에 전달한다. 사용자가 브라우저에서 임의의 식별자를 보내더라도 서버에 로그인한 사용자의 식별자가 우선한다.

저장된 자료에는 어떤 동의를 받았는지, 어떤 규칙과 모델을 썼는지, 어떤 코드와 설정에서 실행했는지를 함께 남긴다. 추천, 안전 판정, 후속 평가와 상담 사건은 공통 실행 ID로 연결된다. 같은 사건이 두 번 들어오면 중복 기록을 막는다. 수정이나 삭제 요청이 와도 무엇이 바뀌었는지 확인할 수 있는 감사 기록은 보존한다.

## 안전 검사는 추천보다 먼저 작동한다

안전 판정은 대형 언어 모델의 자유로운 답변에 맡기지 않는다. 구조화된 규칙이 알레르기, 응급 신호, 임신·수유, 질환, 약물과 성분의 상호작용을 검사한다. 사용자가 먹는 여러 제품의 성분 용량을 합치고, 단위를 맞춘 뒤 상한과 비교한다. 단위를 바꿀 수 없거나 필수 정보가 부족하면 안전하다고 추정하지 않고 보수적으로 제외하거나 검토를 요청한다.

예를 들어 생선 알레르기가 있으면 오메가3 후보를 제외한다. 임신 상태와 와파린 복용 정보가 저장된 사용자가 오메가3를 요청하면 추천 목록을 비우고 차단 상태를 반환한다. 응급 위험 신호가 있으면 추천 전체를 중단한다. 이런 최종 차단 권한은 모델의 점수보다 우선한다. 모델이 후보를 높게 평가해도 안전 규칙이 거부한 성분은 최종 추천으로 나갈 수 없다.

각 안전 결과에는 적용한 규칙 버전, 규칙 ID와 근거 ID가 붙는다. 이 연결은 왜 성분을 제외했는지 다시 확인하고 같은 입력을 재현하기 위한 장치다. 다만 현재 등록된 일부 외부 검증 자료는 독립 검토 요건을 충족하지 않는다. 내부 시험을 통과했다는 사실과 외부 기관이 안전성을 승인했다는 주장은 분리해야 한다.

## 추천과 상품 조합은 어떤 기준으로 만들어지는가

안전 검사를 통과한 후보는 건강 목표, 증상, 검사값, 생활 습관, 식사 정보와 선택적으로 연결된 센서 자료에 따라 점수를 받는다. 시스템은 점수 합계만 보여 주지 않고 어떤 신호, 규칙과 참고문헌이 점수에 영향을 줬는지 구조화된 사유를 남긴다. 상위 후보의 점수 차이가 작거나 중요한 정보가 빠졌다면 결과를 확실한 추천으로 꾸미지 않고 추가 입력을 요청한다.

추천 성분은 실제 상품 후보와 연결할 수 있다. 상품 계약에는 성분, 함량, 가격, 재고와 제형이 들어간다. 조합기는 예산, 제품 수, 복용 부담과 선호 제형을 함께 고려한다. 한 제품에 여러 성분이 들어 있으면 복합 상품을 재사용하고, 서로 다른 제품에 같은 성분이 있으면 총량을 다시 계산한다. 재고나 함량 자료가 부족한 상품은 정상 후보처럼 취급하지 않는다.

학습 모델은 기본 안전 판정을 바꾸지 못한다. 학습 산출물이 없거나 손상됐거나 허용 범위를 벗어나면 결정론적 기본 결과로 돌아간다. 현재 비교 자료는 고정 평가 사례에서 학습 재정렬이 일부 순위와 선택을 바꿨지만 안전 상태와 다음 행동은 바꾸지 않았음을 보여 준다. 이 결과는 학습 기능의 제한된 재현 시험이지 실제 사용자의 건강 개선 증거가 아니다.

## 복용 후 효과와 다음 행동은 어떻게 판단하는가

복용 전후 설문은 같은 설문명, 채점 버전과 시작 분포를 사용한다. 수면과 스트레스 같은 설문 점수를 표준점수와 백분위로 바꾸고, 같은 계획 ID에 연결된 전후 한 쌍에서 변화량을 계산한다. 개인 결과와 집단 평균은 별도 필드로 보존한다. 한 사람의 변화가 집단 효과로 둔갑하거나 평균만 남아 개인의 악화가 사라지는 일을 막기 위해서다.

집단 결과에는 표본 수, 해석 가능한 개인 수, 평균 변화와 신뢰구간이 포함된다. 100명의 합성 사례로 개인 결과 보존, 입력 순서 독립성과 평균 계산을 시험했다. 이 100명은 규칙으로 만든 대체 자료다. 평균 개선값이 양수여도 실제 사용자가 좋아졌거나 추천 성분이 원인이라고 결론 내릴 수 없다. 실제 효과 지표를 확정하려면 같은 조건으로 수집한 실제 복용 전후 자료가 필요하다.

다음 행동은 자유형 에이전트가 아니라 상태 전이 규칙으로 고른다. 순응도가 충분하고 문제가 없으면 유지할 수 있다. 복용 누락, 효과 부족, 이상 징후나 심각한 이상사례가 있으면 재검사, 상담, 조정 또는 중단으로 보낸다. 같은 결정이 두 번 적용되지 않도록 멱등성 규칙을 두고, 실패한 작업은 재시도 횟수와 검토 필요 상태를 기록한다.

상담 기능은 허용된 건강기능식품·복용·안전·추적 결과 범위에서 근거를 검색하고 답변을 검증한다. 모르는 내용은 추측하지 않고 답변 범위를 제한한다. 자동 생성한 초안은 약사가 승인하거나 수정 승인하기 전에는 학습, 평가, 추천과 지식 자료로 사용할 수 없다.

## 현재 저장소가 실제로 입증한 범위

현재 요구사항 장부는 계획서 요구사항 120건을 모두 등록했다. 자동 생성 완료 현황은 비외부 요구사항 119건을 완료, OP-039 한 건을 외부 검증으로 표시한다. 현재 manifest의 주장 단계는 `IMPLEMENTED` 54건, `INTEGRATED` 24건, `OPERATED` 41건, `EXTERNAL` 1건이다. 여기서 구현 검증은 코드와 집중 시험, 통합 검증은 실제 구성요소 사이의 왕복, 운영 검증은 실제 세션에서 남긴 관찰 기록을 뜻한다.

2026-07-27에 현재 파일로 다시 만든 OP-120 감사는 요구사항과 보고서 120/120, 누락·단계·외부 격차 0, `READY`를 반환했다. 별도 근거 검증에서는 대상 보고서 53편에 연결된 파일 경로 492건을 모두 확인했고 최종 내용 불일치는 0건이었다. 이 결과는 등록 경로와 현재 감사 정책을 통과한 장부 상태다.

자동 감사만으로 사람 행동의 진위를 알 수는 없다. 이번 보고서 재조사에서는 일부 범용 운영 영수증이 개별 요구 행동을 직접 보여 주지 않는다는 사실을 확인했다. 예를 들어 추천 행 한 건의 증가가 브라우저의 세 역할 업무, 에이전트 단계와 모든 후속 작업을 각각 실행했다는 증거가 되지는 않는다. DB에 서로 다른 프로필이 5개 있다는 사실도 실제 참여자 자료, 동의, 추천, 후속평가와 약사 검토가 다섯 계보에서 모두 끝났다는 증거가 아니다. 따라서 감사 `READY`와 프로필 5/5를 상용 서비스의 모든 기능이 실제 사용자 환경에서 끝까지 운영됐다는 뜻으로 읽으면 안 된다.

지금 강하게 말할 수 있는 성과는 다음과 같다. 구조화 입력과 동의 계약, 규칙 기반 안전 엔진, 추천 후보와 설명, 상품 조합 제약, 설문 채점과 복용 전후 계산, 상태기계, 상담 근거 검색, FastAPI 서버와 서비스 연결 코드가 구현돼 있다. 주요 기능에는 집중 시험과 고정 사례가 있다. 로컬 프로세스 사이의 HTTP 왕복, 임시 데이터베이스 저장, 일부 로컬 브라우저 화면과 서명된 연구 세션 영수증도 존재한다.

반대로 공개 배포, 장기간 상용 운영, 실제 사용자 집단의 건강 개선, 실제 약사의 전체 화면 업무, 독립 외부기관의 안전성 승인까지 입증됐다고 말할 수는 없다. 합성·규칙 생성 자료는 계산과 실패 경계를 재현하는 데 유용하지만 실제 임상 효과를 대신하지 않는다.

## 사람이 직접 마쳐야 하는 검증

가장 먼저 H-005 검토 화면과 자격 검증을 바로잡아야 한다. 현재 화면은 고위험 10건을 모두 `타당`으로 골라 두고 의견도 채워 둔다. 오너 차단은 정확한 이름 두 개만 비교하고, 면허 ID는 `not_collected`도 통과하며, 자격 확인 방법은 검사하지 않는다. 서명도 별도 전자서명이 아니라 이름 문자열을 복사한다. 프로젝트 공동연구자와 `independent_of_implementation_team=false`를 기록하는 규칙 자체는 현재 체크리스트와 맞지만, 외부 의존성 원장이 요구하는 자료·신뢰 기준과 manifest의 `EXTERNAL` 표시는 서로 맞지 않는다. 사람이 검토하기 전에 중립 입력, 실제 자격 확인, 별도 서명과 정책 충돌을 해결해야 한다.

H-003 승인 초안 이후의 학습·평가 명령도 아직 이어지지 않는다. 현재 코드는 승인·수정 승인 행의 수를 기록할 수 있지만 초안 ID를 학습 데이터셋과 후보 모델로 연결하지 않는다. 평가 스크립트도 후보 모델 artifact를 받지 않고, 비교 스크립트는 안전 지표 악화를 실패로 판정하지 않는다. approved-only 데이터셋 manifest, 후보 학습 명령, 후보 모델 고정 평가, 안전 회귀 gate, 교체·유지와 rollback 기록을 먼저 구현해야 한다. 학습 gate는 아직 `NO-GO`이므로 그 전에는 훈련하지 않는다.

두 결함을 고친 뒤 한 번의 통제된 최종 세션에서 실제 행동과 데이터 변화를 직접 연결해야 한다. 서로 다른 위험과 목표를 가진 실제 사용자 프로필 5개를 저장하고, 추천 결과와 안전 차단을 확인한다. 약사 화면에서는 미리 선택하지 않은 10개 판단 사례를 실제로 결정하고, 관리자 화면에서는 배포·비밀값·보안·개인정보·rollback 정책을 항목별로 확인한다. 사용자 후속 평가, 이상사례, 실패 재시도, 상담과 관리자 조회도 요구사항별로 관찰값을 남겨야 한다.

각 영수증에는 실행 시각, 입력 사례 ID, 응답 상태, 변한 데이터 행, 사용한 코드 커밋과 설정 지문을 함께 기록해야 한다. 여러 요구사항을 한 개의 범용 카운터에 묶지 말고, 요구 문장과 관찰 신호를 직접 대응시켜야 한다. 이 절차가 끝나면 현재 장부의 `OPERATED` 41건을 내용 단위로 다시 감사하고, 구현·통합·운영·외부 검증의 경계를 최종 보고서에 그대로 반영할 수 있다.

## 최종 판단

이 저장소는 개인 건강 입력부터 안전 검사, 추천, 상품 조합, 복용 전후 평가와 다음 행동까지 이어지는 연구용 시스템을 갖췄다. 안전 판정을 규칙으로 고정하고, 학습 모델과 상담 기능의 권한을 제한했으며, 결과를 재현할 수 있도록 자료와 코드의 계보를 남겼다는 점이 핵심 성과다.

남은 일은 더 많은 기능을 무작정 추가하는 것이 아니다. H-005의 중립 입력과 자격 검증을 고치고, H-003 승인 초안의 실제 학습·평가 계보를 만든 뒤, 실제 세션에서 요구 행동과 관찰값을 일대일로 연결해야 한다. 합성 결과와 실제 사용자 결과도 구분해 성능 지표를 다시 측정해야 한다. 이 과정을 마쳐야 “연구 기능이 구현됐다”는 결론을 넘어 “계획서의 운영·외부 검증 기준까지 충족했다”고 말할 수 있다.
