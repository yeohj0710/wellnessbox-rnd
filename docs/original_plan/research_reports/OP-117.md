# OP-117 브라우저에서 사용자, 약사, 관리자 핵심 경로를 재현한다

## 어떤 경로를 재현했는가

로컬 WellnessBox를 실제 Next.js 서버로 실행하고 Playwright Chromium에서 사용자, 약사, 관리자 경로를 열었다. 사용자는 `/survey` 본문까지 접근했다. 로그인하지 않은 약사는 `/pharm`에서 `/pharm-login`으로 이동했으며, 관리자는 실제 비밀번호 확인 API가 성공한 뒤 `/admin` 본문에 접근했다. 화면 파일의 존재만 세는 대신 브라우저가 받은 주소와 표시 내용을 증거로 남겼다.

## 검증은 무엇을 확인했는가

고정 평가 세트 `wellnessbox-rnd/data/original_plan/op117_op118_browser_operational_evidence_cases_v1.json`은 OP-117과 OP-118을 합쳐 8개 조건을 정의한다. 실행 증거 `wellnessbox-rnd/data/original_plan/evidence/op117_op118_browser_operational_evidence_smoke_v1.json`에는 브라우저 3건의 실제 주소, 화면 표시 여부, 로그인 상태와 두 저장소의 소스 식별자가 기록돼 있다. 임시 비밀번호 값은 증거 파일에 남기지 않았다.

## 완료 단계와 한계는 무엇인가

브라우저 핵심 경로의 로컬 재현은 `IMPLEMENTED`다. 이 결과는 사용자 화면이 열리고 인증 경계가 작동한다는 뜻이다. 실제 약사 계정으로 로그인한 세션, 실제 주문 자료, 공개 배포 주소와 운영 트래픽은 확인하지 않았다. 따라서 세 역할의 운영 환경 사용을 뜻하는 `OPERATED`는 주장하지 않으며, 운영 확인은 H-007에서 별도로 처리한다.
