# OP-063 실제 상품을 성분 조합 후보로 변환한다.

manifest가 지정한 구현 경로 `wellnessbox/lib/server/wb-rnd-product-candidates.ts`와 R&D 검증 모델 `wellnessbox-rnd/src/wellnessbox_rnd/optimizer/product_combinations.py`를 직접 읽었다. 정본 결과는 `wellnessbox-rnd/data/original_plan/evidence/op063_op064_product_combination_dose_smoke_v1.json`이다. 이 자료가 입증한 단계는 `INTEGRATED`다. 여기서 실제 상품은 서비스 상품 계약 형식의 상품을 뜻하며, smoke가 운영 상품 DB를 조회했다는 뜻은 아니다.

## 성분 추천만으로 구매 후보가 되지 않는 이유

성분 여덟 개가 추천돼도 여덟 상품을 각각 사야 하는 것은 아니다. 하나의 복합 상품이 여러 추천 성분을 함께 담을 수 있고, 반대로 같은 성분에 여러 판매 상품이 있을 수 있다. 상품별 선택지를 단순히 이어 붙이면 같은 복합 상품이 추천 성분마다 중복되고 비용과 복용 수가 부풀려진다. OP-063은 추천 성분마다 상품 후보를 찾은 뒤, 서로 다른 상품 선택 조합으로 바꾸는 역할을 맡는다.

상품 후보는 이름 또는 분류 검색어가 맞고, 목표 성분의 정규화된 함량이 실제로 있어야 한다. 판매 옵션에는 가격과 양수 재고가 필요하다. 추천 중 하나라도 후보가 없으면 완전한 조합을 만들지 않는다. 모르는 상품 ID를 지어내는 대신 결과를 비우는 선택이다.

## 조합을 만들고 중복 상품을 합치는 방법

서비스는 추천 순서대로 후보 하나씩을 선택하는 탐색을 수행한다. 같은 상품이 여러 추천을 만족하면 `product_id`를 기준으로 한 번만 남긴다. 선택 상품은 ID 순으로 정렬하고, 각 상품의 최저가 판매 옵션을 붙인다. 상품 ID와 판매 옵션 ID 목록에서 SHA-256 지문을 계산해 `combo_` 식별자를 만든다. 같은 입력과 같은 상품이면 같은 조합 ID가 나오도록 한 것이다.

탐색이 끝없이 커지는 것도 막았다. `wellnessbox/contracts/wb-rnd/product-candidate-match-v1.json`은 성분당 후보 다섯 개, 탐색 상태 4,096개, 반환 조합 64개를 상한으로 둔다. 같은 진행 단계와 같은 선택 상품 집합을 다시 만나면 재탐색하지 않는다. 4,096개 상태에 닿으면 더 진행하지 않고 검색이 잘렸다고 표시하며, 완전한 순위를 내놓지 않는다.

## 서비스 경계를 통과한 결과

등록 smoke는 서비스 route 함수와 상품 어댑터가 만든 조합을 R&D의 `ProductCombinationEvidenceV1`로 다시 읽었다. 당시 고정 상품 일곱 개와 추천 성분 여덟 개에서 조합 네 개가 만들어졌고, 그중 두 조합을 세부 검증했다. 복합 상품을 재사용한 조합은 추천 성분 여덟 개를 상품 다섯 개로 충족했으며 같은 상품이 중복되지 않았다. 아연 단일 상품을 더 고른 조합은 여섯 상품으로 남아 별도의 조합 ID를 받았다.

현재 서비스 QA에는 L-테아닌과 차전자피 자료가 더해져 열 개 성분이 모두 연결됐다. 조합은 여전히 네 개였고, 여러 성분을 함께 맡은 조합은 상품 일곱 개로 구성됐다. 고정 자료의 순서를 바꿔도 결과 지문과 순위가 유지됐으며, 동일 상품의 재사용은 한 번으로 합쳐졌다. 반대로 후보가 없는 추천은 조합 생성을 멈췄다. 어댑터, Python 모델, 두 시험과 기준 증거에는 처음 발생한 조합 오류와 수정 순서가 없어 `확인되지 않음`으로 남긴다.

## 믿을 수 있는 범위와 남은 검증

이 통합은 `POST /api/tips`의 실제 서비스 함수에서 상품 후보와 조합을 붙이고, Python 모델이 그 구조와 파생값을 재계산할 수 있음을 보여 준다. 실제 Prisma 조회는 실행하지 않았고 상품 가격·재고의 운영 최신성도 입증하지 않았다. 상품 선택 결과는 장바구니에 쓰이지 않았으며 주문과 결제를 만들지 않았다.

기준 증거가 기록한 소스 결합 지문은 현재 소스에서 다시 계산한 값과 달랐다. 최신 서비스 QA와 Python 집중 시험은 성공했으나 두 결과의 상품 수와 추천 수가 이미 다르므로 정본 수치와 최신 수치를 섞어 하나의 실행처럼 말하면 안 된다. OP-063의 단계는 등록된 통합 실행에 근거한 `INTEGRATED`이고, 운영 상품 DB를 이용한 최신 통합 실행은 `확인되지 않음`으로 남는다.
