# OP-060 data_class 교체만으로 실제 결과 데이터를 같은 API에서 처리한다.

## 이 요구가 해결하는 문제

핵심 요구는 다음과 같다. data_class 교체만으로 실제 결과 데이터를 같은 API에서 처리한다. 후속 평가는 같은 계획의 시작점과 관찰값을 연결하고, 순응도와 불확실성을 숨기지 않아야 한다. 기준 요구 목록과 등록 증거를 대조했으며, 현재 단계는 `INTEGRATED`다. 이 보고서는 코드와 테스트가 보여 주는 범위만 다룬다. 실제 사용자 자료나 외부 전문가 판단이 없는 부분을 운영 완료로 넓혀 말하지 않는다.

## 구현 근거를 어떻게 읽었는가

첫 구현 근거는 `wellnessbox-rnd/src/wellnessbox_rnd/orchestration/pro_plan_service.py`다. 파일을 직접 읽었을 때 크기는 11,840바이트였고, 내용 지문인 SHA-256 앞 12자리는 `dc672f01d409`였다. 이 경로의 최근 관련 커밋은 `8448cec`이다. 파일명만 인용하지 않고 현재 저장소의 실제 내용을 읽어 요구 제목과 책임 범위를 맞췄다. 등록된 나머지 구현 경로도 모두 열 수 있는지와 내용 지문을 함께 계산했다.

## 어떤 테스트와 증거가 남아 있는가

자동 검증 근거로 `wellnessbox-rnd/tests/test_pro_plan_service.py`를 읽었다. 이 파일은 19,986바이트이며 SHA-256 앞 12자리는 `0d48c903ed25`다. 최근 관련 커밋은 `b668644`이다. 기준 감사는 이 경로가 존재하는지만 보지 않고 등록된 원본 내용과 현재 파일의 일치 여부도 확인한다. 따라서 이후 코드가 바뀌면 테스트와 기준 증거를 함께 갱신해야 같은 주장을 유지할 수 있다.

## 완료 단계와 한계

`INTEGRATED`는 저장소 내부 구현을 넘어 서비스 경계의 연결까지 증거가 있다는 뜻이다. 공개 운영 환경에서 사용했다는 뜻은 아니다. 이 보고서는 증거 경로, 파일 내용, 커밋 이력을 현재 시점에서 다시 읽어 작성했다. 약사 승인, 독립 외부 검증, 공개 배포가 필요한 주장은 별도 사람 일 원장과 운영 증거에서 다룬다. 나중에 단계가 바뀌면 기준 목록을 먼저 수정하고 감사기를 다시 실행해야 한다.
