# OP-027 이벤트 중복 기록을 idempotency key로 차단한다.

## 같은 요청을 다시 보내도 이벤트가 하나만 남아야 한다
네트워크 재시도나 클라이언트의 중복 전송은 정상 운영에서도 발생한다. 이런 재시도를 새 행동이나 새 연구 사건으로 기록하면 노출 수, 클릭 수, 안전 판단 횟수와 같은 집계가 실제보다 커진다. OP-027의 결과는 idempotency key를 단순 메모로 저장하는 데 그치지 않고, 같은 범위와 같은 key로 들어온 동일 요청에는 기존 이벤트를 돌려주며 내용이 달라진 재사용에는 충돌을 반환하는 것이다. 현재 구현은 연구·평가 이벤트와 사용자 행동 이벤트에 이 규칙을 각각 적용한다.

연구·평가 이벤트는 추천 실행에 종속되고 사용자 행동 이벤트는 프로필에 종속된다. 따라서 두 로그에 하나의 전역 key 규칙을 억지로 적용하지 않았다. `execution_events`는 `(execution_id, event_type, idempotency_key)`를 고유 범위로 삼고, `behavior_events`는 `(profile_id, event_name, idempotency_key)`를 고유 범위로 삼는다. 같은 문자열 key라도 실행이나 이벤트 종류가 다르면 독립된 사건일 수 있다는 업무 의미를 보존한 선택이다.

## 기존 실행 원장과 행동 기록기를 재사용했다
구현은 별도 중복 방지 서비스나 두 번째 이벤트 저장소를 만들지 않았다. 연구 이벤트는 `src/wellnessbox_rnd/interim/data_lake.py`의 실행 원장 경로를, 행동 이벤트는 `src/wellnessbox_rnd/interim/behavior_log.py`의 기록 경로를 사용한다. 두 경로 모두 `src/wellnessbox_rnd/interim/store.py`가 관리하는 동일 SQLite 스키마와 transaction 경계를 사용한다. API는 `apps/inference_api/routes/interim.py`의 `/v1/interim/executions/{execution_id}/events`와 `/v1/interim/behavior-events`로 기존 서비스를 노출한다.

이 설계는 중복 판정만 담당하는 별도 테이블과 주기적 정리 작업을 추가하지 않는다. 데이터베이스의 UNIQUE 제약이 최종 동시성 방어선이고, 애플리케이션은 기존 행을 조회해 요청 내용이 정말 같은지를 판정한다. 저장 계층과 API 계층이 서로 다른 중복 정의를 갖지 않으므로 한쪽에서는 재시도로, 다른 쪽에서는 신규 사건으로 보는 불일치도 줄였다.

## 입력 내용 전체를 canonical hash로 비교한다
연구 이벤트 입력은 실행 ID, event type, source, idempotency key와 payload를 포함한다. 행동 이벤트 입력은 profile ID, event name, 발생 시각, idempotency key와 payload를 포함한다. payload는 key 순서를 고정한 canonical JSON으로 직렬화하고 SHA-256을 계산한다. 행동 이벤트의 발생 시각은 timezone 정보가 있는 값만 받고 UTC ISO 형식으로 정규화한다.

같은 범위에서 같은 key가 다시 오면 저장기는 기존 payload hash와 요청의 canonical hash를 비교한다. 내용이 같으면 새 행을 넣지 않고 기존 event ID와 `deduplicated=true`를 반환한다. source, payload 또는 행동 발생 시각처럼 사건의 의미를 바꾸는 값이 달라지면 idempotency conflict가 발생하고 API는 409를 반환한다. key만 같다는 이유로 바뀐 요청을 조용히 성공시키지 않기 때문에 최초 기록을 덮어쓰거나 어느 요청이 반영됐는지 모호하게 만들지 않는다.

## 오류 입력과 경계값은 저장 전에 닫힌 방식으로 거절한다
빈 idempotency key와 길이 제한을 넘은 key는 입력 검증에서 거절된다. 행동 endpoint에 연구 event type을 보내거나 연구 endpoint에 행동 event name을 보내는 요청도 각 vocabulary 검증을 통과하지 못한다. 존재하지 않는 실행이나 profile, 지속 저장 동의가 없는 profile도 정상 이벤트처럼 만들지 않는다. 데이터베이스 UNIQUE 제약은 동시에 같은 요청이 들어와 애플리케이션의 사전 조회가 경합하더라도 중복 행이 확정되는 것을 막는다.

여기서 idempotency는 모든 API 호출의 전역 exactly-once 전달을 뜻하지 않는다. 같은 저장 범위, 같은 event 종류와 같은 key라는 계약 안에서 저장 결과가 한 번만 생긴다는 뜻이다. 클라이언트가 매번 새 key를 만들거나 서로 다른 event name을 사용하면 별도 사건으로 기록된다. key 발급 정책과 장기 보존 기간은 호출자가 별도로 관리해야 한다.

## 테스트는 동일 재시도와 변경 재시도를 분리한다
`tests/test_event_idempotency_data_mutation.py`는 실제 FastAPI route와 임시 SQLite를 사용한다. recommendation 실행을 만든 뒤 conversation event를 두 번 보내 행 수가 하나이고 두 번째 응답이 deduplicated인지 확인한다. 이어 같은 key의 source 또는 payload를 바꿔 409가 발생하는지 확인한다. 행동 event도 같은 방식으로 동일 page-view 재시도와 변경된 재시도를 나누어 검증한다.

`tests/test_data_lake_lineage.py`는 실행 사건의 event index와 knowledge lineage가 중복 판정 뒤에도 유지되는지 보완한다. `tests/test_interim_store.py`는 UNIQUE 제약과 migration 결과를 직접 검사한다. 이번 backfill에서 추가한 canonical-evidence 현재성 테스트는 증거 JSON의 `database_schema_version`이 코드의 `SCHEMA_VERSION`과 같은지도 확인한다. 스키마가 바뀌었는데 과거 smoke가 계속 통과한 것처럼 보이는 회귀를 막기 위한 검사다.

## canonical evidence는 실제 route 실행에서 생성됐다
`scripts/run_event_idempotency_data_mutation_smoke.py`는 새 임시 데이터베이스를 만들고 추천, 실행 trace, conversation event, behavior event, 정정과 삭제 route를 차례로 호출한다. OP-027과 직접 연결된 검사는 conversation replay와 behavior replay가 각각 deduplicate되고, 내용이 바뀐 replay는 각각 거절되는지 확인한다. 결과는 `data/original_plan/evidence/op027_op028_event_idempotency_data_mutation_smoke_v1.json`에 기록된다.

현재 evidence의 case count는 3이고 database schema version은 14다. conversation event와 behavior event는 각각 한 행만 남았다. 생성기를 두 번 실행한 결과는 byte-identical했고 SHA-256은 `980e5677adcb54db684679a3111b0a6927b4e5fc47d6ddc7c9cc8bf6ab19dfb8`이다. 고정 ID와 정렬된 JSON만 결과에 넣어 무작위 event ID나 실행 시간이 evidence hash를 흔들지 않게 했다.

## 서비스 통합과 실제 운영은 서로 다른 주장이다
route, 저장기, schema와 테스트가 한 저장 경로에서 연결됐으므로 로컬 구현 범위의 통합 동작은 확인했다. 그러나 `wellnessbox` 운영 UI가 모든 page view와 click에 안정적인 key를 발급하고 있는지, production 재시도가 실제로 한 건만 집계되는지, 다중 인스턴스와 운영 데이터베이스에서 충돌률이 어떤지는 이번 증거가 보여주지 않는다. 서비스 저장소의 보호된 사용자 변경이나 production 설정도 수정하지 않았다.

따라서 OP-027의 required stage와 claimed stage는 모두 `IMPLEMENTED`이며 현재 판정은 `COMPLETE`다. `INTEGRATED`나 `OPERATED`를 추가로 주장하지 않는다. 다음 단계로 승격하려면 실제 서비스 호출 경로의 요청 ID 정책, 배포 환경의 동시 재시도 시험, 중복 성공·충돌 비율을 담은 장기 관측 receipt가 필요하다.

## 이번 변경은 증거 현재성만 보완했다
원 구현은 commit `e2cfc54`에서 도입됐고 이후 계보 보호 변경과 함께 유지됐다. 이번 loop는 이벤트 저장 알고리즘이나 API 계약을 바꾸지 않았다. schema version 8을 가리키던 오래된 canonical evidence를 현재 생성기로 다시 만들고, 같은 불일치를 자동으로 잡는 회귀 테스트를 추가했다. 학습 데이터, 모델 가중치, 추천 점수, frozen 256건 평가와 simulation 입력은 변경하지 않았다.

검증 결과를 해석할 때도 이 경계를 유지해야 한다. frozen·replay·weakest slice delta가 0이라는 결과는 이번 문서 및 증거 현재성 변경이 추천 품질 경로를 바꾸지 않았다는 뜻이지, production에서 중복 이벤트가 한 번도 발생하지 않는다는 뜻은 아니다. 운영 완료 조건은 실제 트래픽에서 같은 key의 동일 요청이 한 행으로 귀결되고 변경 요청이 경보 가능한 충돌로 남는지 장기간 확인하는 것이다.
## 데이터가 남는 방식
데이터를 저장하는 것만으로는 연구 근거가 남지 않는다. 이 그룹은 원문과 파싱 구간, 입력 버전, 동의, 실행 ID, 규칙과 결과를 이어 붙여서 누가 어떤 자료를 사용했는지 다시 따라갈 수 있게 만든다.

`OP-027`는 “이벤트 중복 기록을 idempotency key로 차단한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=16`
- 구현·설계: `wellnessbox-rnd/src/wellnessbox_rnd/interim/store.py`, `wellnessbox-rnd/src/wellnessbox_rnd/interim/data_lake.py`, `wellnessbox-rnd/src/wellnessbox_rnd/interim/behavior_log.py`, `wellnessbox-rnd/apps/inference_api/routes/interim.py`
- 테스트·실행: `wellnessbox-rnd/tests/test_event_idempotency_data_mutation.py`, `wellnessbox-rnd/tests/test_data_lake_lineage.py`, `wellnessbox-rnd/scripts/run_event_idempotency_data_mutation_smoke.py`, `wellnessbox-rnd/data/original_plan/evidence/op027_op028_event_idempotency_data_mutation_smoke_v1.json`
- 통합 증거: `wellnessbox-rnd/data/original_plan/final_session/operational_evidence/OP-027.json`
- 운영 증거: `wellnessbox-rnd/data/original_plan/final_session/operational_evidence/OP-027.json`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `OPERATED`, 현재 주장 단계를 `OPERATED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
