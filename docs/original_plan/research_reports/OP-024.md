# OP-024 지식 원문의 시행일, 만료일, 출처 유형, 라이선스를 저장한다

## 같은 문장이라도 언제 어디서 가져왔는지에 따라 쓸 수 있는 범위가 달라진다

원본 계획 16쪽은 공개 데이터뿐 아니라 유료 의약학 데이터베이스와 전문 문헌을 라이선스로 들여오는 경우를 구분한다. 문헌 내용을 저장했다는 사실만으로 엔진이 그 내용을 안전 근거로 사용할 수 있는 것은 아니다. 어떤 종류의 출처인지, 사용 허가가 무엇인지, 언제부터 유효하고 언제 폐기됐는지를 함께 알아야 한다.

OP-024는 source마다 `source_type`, `license_status`, `effective_at`, `retired_at`을 필수 메타데이터로 보존한다. 원래 문헌을 가리키는 upstream URI와 실제 parser가 읽은 로컬 URI도 따로 둔다. 이 정보는 reference artifact, runtime knowledge DB, SQLite source registry와 실행 trace까지 같은 의미로 전달돼야 한다.

## reference frontmatter가 수명과 권한의 최초 계약이다

`src/wellnessbox_rnd/ingestion/reference_ingestion.py`의 `ReferenceMetadata`는 reference ID와 제목 외에 source type, page·section, upstream `reference_uri`, `parsed_source_uri`, license status, effective date와 선택적 retired date를 요구한다. `data/raw_references/*.md`의 frontmatter에 필드가 없거나 형식이 다르면 Pydantic parsing 단계에서 실패한다.

시행일은 claim 작성 시각이나 파일 수정 시각으로 추정하지 않는다. 원문 metadata의 `effective_at`을 사용한다. 만료되지 않은 자료는 `retired_at: null`이다. 파싱 파일은 저장소 안의 실제 파일이어야 하고 경로가 repository 밖으로 나가거나 파일이 없으면 registry sync가 실패한다.

`tests/test_reference_ingestion.py`는 대표 상호작용 문헌의 source type `interaction_reference`, license `APPROVED_INTERNAL`, 시행일 `2026-03-10T00:00:00Z`, null retired date와 두 URI를 검사한다. 전체 artifact의 19개 reference가 모두 시행일을 가지고 허용된 license 집합 안에 있는지도 확인한다.

## runtime DB가 실행 단계에서도 같은 메타데이터를 유지한다

`src/wellnessbox_rnd/knowledge/runtime_db.py`의 `KnowledgeReferenceRecord`는 reference artifact와 같은 lifecycle 필드를 가진다. `build_runtime_knowledge_db`는 19개 reference와 24개 span을 생성하면서 원문 metadata를 실행용 DB에 옮긴다. 안전 규칙이나 후보 점수만 남기고 source 정보를 버리지 않는다.

`data/knowledge/runtime_knowledge_db_v1.json`은 reference ID로 규칙·span이 참조할 수 있는 source inventory다. `tests/test_runtime_knowledge_db.py`는 reference 19개가 유지되고, license와 시행일이 존재하며, 현재 정본에는 retired source가 없고 parsed URI가 `data/raw_references/` 아래를 가리키는지 검사한다.

runtime DB는 원문의 라이선스 자체를 새로 부여하지 않는다. reference artifact의 값을 전달할 뿐이다. 따라서 원천 metadata를 바꾸려면 raw frontmatter, 정본 artifact, runtime artifact와 검증을 함께 갱신해야 한다. 결과 JSON 한 곳만 고쳐 source가 승인된 것처럼 보이게 할 수 없다.

## source registry가 라이선스와 만료를 실행 전에 판정한다

`src/wellnessbox_rnd/interim/evidence.py`의 `EvidenceRegistry.register_source`는 license를 대문자로 정규화하고 `OPEN`, `PUBLIC_DOMAIN`, `APPROVED_INTERNAL`만 승인한다. 목록 밖 license는 `license_not_approved` 이유로 quarantine한다. `retired_at`이 있으면 license가 승인돼도 `source_retired`로 quarantine한다.

quarantine된 source의 passage를 safety-approved로 등록하려 하면 실패한다. 즉 시행일·만료일·license를 보관만 하고 실행에서 무시하지 않는다. `tests/test_interim_evidence.py`는 UNKNOWN license가 safety passage를 만들지 못하는지, retired source가 격리되는지, 허용된 공개 license가 정상 등록되는지 검사한다.

source type도 checksum envelope에 포함된다. 같은 source ID의 tier나 license가 바뀌면 단순 metadata 수정으로 넘기지 않는다. 원문 내용 checksum이 달라지면 `content_changed_requires_review`로 격리하고, 같은 변경 payload를 다시 sync해도 격리 상태를 유지한다. legacy checksum 형식을 현재 envelope로 올리는 예외만 명시적으로 처리한다.

## 원문 URI와 파싱 URI를 구분해 저장한다

대표 source `REF-KNOWLEDGE-ANTICOAG-001`의 upstream URI는 `data/knowledge/supplements/supplement_overdose_and_drug_interactions_expert.md`다. parser가 실제 줄 범위를 읽은 URI는 `data/raw_references/supplement_warfarin_interaction.md`다. 두 경로를 하나로 합치면 원래 지식 문서와 정규화·발췌한 감사 파일을 구분할 수 없다.

`KnowledgeLineageRegistry`는 parsed URI를 `source_registry.canonical_uri`에 저장하고 upstream URI를 metadata의 `upstream_reference_uri`에 넣는다. 또한 parsed file bytes의 `content_checksum`, artifact version, page·section과 날짜 의미 `local_artifact_effective_at`을 metadata로 보존한다. 실행 trace는 source URI와 upstream URI를 별도 필드로 반환한다.

이 설계가 외부 웹페이지를 실시간으로 다시 가져와 동일성을 보장한다는 뜻은 아니다. 로컬에 승인해 보존한 원문 bytes와 upstream 위치를 함께 추적한다는 뜻이다. 외부 원문 변경 여부를 판단하려면 별도의 수집·검토 절차가 필요하다.

## claim과 rule도 source 수명을 이어받는다

registry는 claim의 `effective_at`과 `retired_at`을 reference에서 가져와 `knowledge_claims`에 저장한다. rule의 `valid_from`과 `valid_to`도 같은 source lifecycle을 사용한다. source가 retired 상태면 rule status는 `RETIRED`, 승인되지 않았거나 변경 검토가 필요하면 `QUARANTINED`, 그 외에는 `ACTIVE`가 된다.

이렇게 해야 만료된 source에서 나온 rule이 active인 모순을 줄일 수 있다. claim이나 rule JSON이 별도 날짜를 임의로 주장하지 않는다. 한 source의 lifecycle 변경이 그 source에 연결된 실행 가능 규칙 상태로 이어진다. 다만 이미 생성된 과거 execution trace를 삭제하지는 않으므로 당시 판단 근거와 현재 사용 가능 상태를 구분할 수 있다.

## 검증은 저장과 사용 금지를 함께 확인한다

`tests/test_knowledge_lineage.py`는 정본 sync 뒤 SQL join으로 source, passage, claim, rule을 한 행에서 읽는다. 대표 source의 type, license, 시행일, retired date, content checksum, page·section, 13~33줄 span, upstream URI가 원문 artifact와 같은지 검사한다. 실제 추천 trace에서도 같은 값이 반환되는지 확인한다.

변경된 non-blocking source를 같은 ID로 다시 sync하는 테스트는 연결된 rule이 quarantine되는지 확인한다. 승인되지 않은 source와 retired source 테스트는 passage를 안전 근거로 승격하지 못하게 한다. parser, runtime DB, normalized SQLite와 API trace의 네 경계를 각각 검사해 한 계층의 metadata만 맞는 상태를 막는다.

## canonical smoke는 한 실제 차단 실행에서 lifecycle을 재생한다

`scripts/run_knowledge_lineage_smoke.py`는 현재 schema 14의 임시 SQLite에 정본 artifact를 sync하고 warfarin–glucosamine 요청을 보낸다. `data/original_plan/evidence/op023_op024_knowledge_lineage_smoke_v1.json`은 case count 1, source 19개, passage·claim 각 24개, rule·link 각 5개와 execution lineage 2개를 기록한다.

대표 lineage의 license는 `APPROVED_INTERNAL`, effective date는 `2026-03-10T00:00:00Z`, retired date는 null이다. parsed·upstream URI, 13~33줄 span, 64자리 content checksum이 모두 맞아야 `source_lifecycle_and_span_match`가 true가 된다. 이번 loop에서 smoke가 정본 count를 직접 계산하도록 바꿔 이후 source·claim 확장을 오래된 숫자로 오판하지 않게 했다.

## IMPLEMENTED 완료는 외부 라이선스 감사를 대신하지 않는다

manifest의 required·claimed stage는 `IMPLEMENTED`다. metadata schema, parser, runtime 전달, quarantine gate, normalized 저장, 실제 route trace와 회귀 테스트가 있으므로 OP-024는 `COMPLETE`다. 이 판정은 등록된 local reference의 lifecycle과 license 상태를 보존하고 적용한다는 뜻이다.

실제 상용 DB 계약의 법적 권리, 갱신 비용, 지역별 재배포 조건을 독립 법률 검토했다는 주장은 아니다. 현재 artifact의 license 값은 승인된 내부 개발 자료의 운영 계약이다. 이번 loop는 production, 외부 문헌 계약, 지식 원문 내용, frozen·학습 데이터, 모델과 simulation을 바꾸지 않았다. 공식 frozen 일곱 지표, replay와 weakest slice delta는 0이다. 운영 승격에는 실제 license 갱신·만료 이벤트와 배포 환경의 quarantine receipt가 필요하다.
