# OP-037 단위를 변환해 상한을 비교하고 불명확한 용량은 안전하게 제외한다.

`wellnessbox-rnd/src/wellnessbox_rnd/safety/service.py`는 질량 단위 `ng`, `mcg`, `mg`, `g`를 변환하고 비타민 D3에 한해 질량과 IU를 `1 mcg = 40 IU`로 환산한 뒤 일일 상한과 비교한다. 사용자가 용량을 제공했지만 총량을 확정할 수 없으면 상한 초과를 거짓으로 단정하지 않고 해당 성분을 추천 후보에서 제외한다. 구현, 규칙 데이터, 실행용 산출물, 회귀 테스트와 대표 시나리오 증거를 확인한 단계는 `IMPLEMENTED`다.

## 요구사항의 두 실패 경계

OP-037에는 서로 다른 위험이 있다. 첫째, 변환 가능한 용량을 원래 숫자만 비교하면 1 g과 1 mg을 같은 크기로 오판할 수 있다. 둘째, 변환할 수 없거나 어떤 성분의 용량인지 모호한 값을 조용히 건너뛰면 “상한을 넘지 않았다”는 잘못된 인상을 줄 수 있다. 구현은 완전한 값에는 정규화 후 비교를, 사용자가 용량을 냈지만 해석이 불완전한 값에는 성분 후보 제외를 적용한다.

커밋 `8b5f6dd` 전의 `_find_triggered_dose_limits`는 집계 합계가 `None`이면 해당 성분을 그대로 건너뛰었다. 제목에만 있는 마그네슘 용량이나 여러 성분에 걸린 구조화되지 않은 제품 용량은 안전 규칙 없이 통과할 수 있었다. 커밋은 `dose_input_count`와 적용 사유를 추가하고, 기존 테스트 이름도 `skips`에서 `fails_closed`로 바꿨다. 예를 들어 제목 전용 마그네슘과 모호한 복합 성분 테스트가 조용한 생략 대신 `dose_evidence_incomplete`를 기대하도록 수정됐다. 이 diff는 실제 결손과 회귀 방지를 보여 주며 당시 실패 출력 자체는 없다.

## 변환 규칙과 상한 데이터

입력 계약은 `wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation.py`의 양수 `DoseAmount`와 허용 단위 열거형으로 시작한다. 안전 서비스는 질량을 mg 중간값을 거쳐 대상 질량 단위로 변환한다. 비타민 D3만 mcg와 IU 사이의 전환 계수를 사용한다. 비타민 C에 IU처럼 성분별 변환 규칙이 없는 단위가 들어오면 숫자가 있더라도 총량을 만들지 않는다.

`wellnessbox-rnd/data/rules/safety_rules.json`과 `wellnessbox-rnd/data/knowledge/runtime_knowledge_db_v1.json`에는 비타민 D3 4,000 IU, 비타민 C 2,000 mg, 아연 40 mg, 마그네슘 350 mg, 칼슘 2,000 mg의 구조화된 상한 규칙이 있다. `wellnessbox-rnd/src/wellnessbox_rnd/knowledge/runtime_db.py`는 이 다섯 레코드의 성분 키, 최대 일일량, 단위, 심각도를 런타임 DB로 옮긴다. 현재 다섯 규칙의 reference ID와 claim ID는 모두 비어 있으므로 숫자가 외부 문헌 claim에 연결되었다고 말할 수 없다.

완전한 합계가 상한보다 크면 적용 사유는 `upper_limit_exceeded`, 심각도는 `blocker`, 안전 상태는 `blocked`가 된다. 합계와 상한이 같은 단위로 변환되지 않거나 일부 용량이 빠졌지만 `dose_input_count`가 1 이상이면 `dose_evidence_incomplete`를 가진 정보 규칙을 남기고 해당 성분을 제외한다. 이 경우 전체 상태는 다른 차단 사유가 없으면 `ok`다. 따라서 제목의 “보수적으로 차단”은 불명확한 성분 후보를 차단한다는 뜻이며 모든 요청을 `blocked`로 만든다는 뜻은 아니다.

용량 입력이 전혀 없을 때는 상한을 평가했다고 주장하지 않는다. 집계의 완전성은 거짓이지만 상한 규칙 참조도 만들지 않는다. “자료가 없음”과 “자료를 받았지만 해석할 수 없음”을 `dose_input_count`로 나누는 이유다. 기존 문자열 파서는 쉼표가 있는 단일 숫자는 읽되 범위, `twice`, `BID`, `2 x` 같은 복용 일정 표현, 여러 성분에 걸린 복합 문맥은 일일 총량으로 추정하지 않는다.

## 정상 변환과 불완전 입력 테스트

`wellnessbox-rnd/tests/test_medication_supplement_input_contracts.py`의 `test_complete_mass_doses_are_normalized_before_upper_limit_comparison`는 비타민 C 1.0 g과 1.2 g을 2,200 mg으로 합쳐 `upper_limit_exceeded`를 적용하고, 0.5 g과 1.0 g은 1,500 mg으로 합쳐 상한 규칙을 적용하지 않는 두 경계를 검사한다. `test_structured_daily_dose_units_are_converted_before_limit_comparison`은 비타민 D3 0.125 mg, 125,000 ng, 5,000 IU가 모두 4,000 IU 상한을 넘는 동일 결과를 내는지 확인한다.

`test_nonconvertible_dose_evidence_fails_closed`는 비타민 C 500 IU처럼 변환할 수 없는 값에서 완전성 거짓, 성분 제외, `dose_evidence_incomplete`, 전체 상태 `ok`를 요구하고 상한을 넘었다는 차단 문구는 없어야 한다고 단언한다. `test_optional_absent_dose_does_not_claim_an_upper_limit_evaluation`은 용량 없는 비타민 D에서 `dose_input_count=0`이며 `SAFETY-DOSE-VITD3-001`이 나타나지 않는지 확인한다. `test_legacy_dose_parser_handles_thousands_and_rejects_ranges`와 `test_title_or_ingredient_schedule_context_fails_closed`는 쉼표 숫자, 범위, 복용 일정 문맥의 파서 경계를 고정한다.

`wellnessbox-rnd/tests/test_runtime_knowledge_db.py`의 `test_runtime_knowledge_db_builds_structured_dose_limits`에서는 런타임 레코드가 다섯 규칙 ID, 비타민 D3 4,000 IU와 차단 심각도를 포함해야 한다. `test_assess_safety_fails_closed_for_title_only_magnesium_dose_evidence`는 `Magnesium Glycinate 400 mg`이라는 제목만 있고 성분 줄이 없을 때 상태를 `ok`로 두되 마그네슘을 제외하고 불완전 적용 사유를 남기도록 요구한다. `test_structured_supplement_dose_fails_closed_for_ambiguous_ingredient_mapping`은 5,000 mg이라는 제품 용량 하나를 비타민 C와 아연의 총량으로 나눠 넣는 동작을 막고 두 성분을 모두 제외한다.

## 저장 증거와 단계 한계

`wellnessbox-rnd/scripts/run_dose_limit_fail_closed_rule_metadata_smoke.py`는 대표 시나리오를 빠르게 확인하는 스모크 스크립트다. 결과 파일 `wellnessbox-rnd/data/original_plan/evidence/op037_op038_dose_limit_rule_metadata_smoke_v1.json`에는 비타민 C 2,200 mg 차단, 1,500 mg 비적용, 단위 불일치, 부분 용량, 비타민 D 결측 사례가 있다. 불완전 사례의 규칙에는 `application_reason="dose_evidence_incomplete"`가 있고 reference와 claim 목록은 비어 있다. 완전 초과 사례는 `upper_limit_exceeded`와 `blocked`를 기록한다.

manifest에 등록된 구현 경로 다섯 개와 테스트·증거 경로 네 개는 모두 존재하고 현재 내용이 단위 변환 및 보수적 후보 제외와 일치한다. 자동화된 정상·경계·불완전 사례가 있어 `IMPLEMENTED`로 판정한다. 그러나 상한 수치의 외부 근거 ID 연결, 실제 제품 라벨의 복용 횟수 해석, 임상 전문가 승인, 배포 환경과 운영 데이터는 검증하지 않았다. 특히 불완전 용량이 전체 요청을 차단한다고 해석하면 현재 코드와 다르므로 그보다 높은 수준의 안전 보장을 주장하지 않는다.
## 안전 판단에서 놓치면 안 되는 경계
안전 그룹의 기준은 추천을 많이 만드는 것이 아니라 위험한 결과를 통과시키지 않는 것이다. 입력 단계와 후보 생성 뒤에 안전 판단을 두고, 중대한 위험이나 불명확한 용량이 나오면 fail-closed로 멈추는 경계를 확인한다.

`OP-037`는 “단위 변환 후 상한을 비교하고 불명확하면 보수적으로 차단한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=17`
- 구현·설계: `wellnessbox-rnd/src/wellnessbox_rnd/safety/service.py`, `wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation.py`, `wellnessbox-rnd/src/wellnessbox_rnd/knowledge/runtime_db.py`, `wellnessbox-rnd/data/rules/safety_rules.json` 외 1개
- 테스트·실행: `wellnessbox-rnd/tests/test_medication_supplement_input_contracts.py`, `wellnessbox-rnd/tests/test_runtime_knowledge_db.py`, `wellnessbox-rnd/scripts/run_dose_limit_fail_closed_rule_metadata_smoke.py`, `wellnessbox-rnd/data/original_plan/evidence/op037_op038_dose_limit_rule_metadata_smoke_v1.json`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `IMPLEMENTED`, 현재 주장 단계를 `IMPLEMENTED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
