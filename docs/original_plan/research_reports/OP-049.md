# OP-049 추천 모델과 결정 규칙 기준선의 차이를 재생 평가에서 비교한다

## 결론과 비교 범위

OP-049는 같은 고정 입력을 추천 모델 적용 전후에 각각 실행하고, 선택·순위·점수의 변화와 안전 응답의 불변성을 사례별로 비교하도록 요구한다. 현재 재생 평가는 256개 고정 사례를 모두 기준선과 학습 재정렬 설정으로 실행한다. 학습 재정렬은 12개 사례에 적용되었고, 선택 변경은 4개, 순위 또는 점수 변경은 5개였다. 응답 상태, 다음 행동, 안전 요약은 한 건도 바뀌지 않았다.

이전 위험은 집계 정확도만 보고 모델을 판단하거나, 모델이 적용되지 않은 사례를 개선·악화가 없는 성공 사례로 세는 것이었다. 현재 보고서는 각 사례에 학습 결정 상태와 기준선·학습 결과를 함께 보존하고 집계값을 사례 배열에서 다시 계산한다. 따라서 “적용 12건”과 “기준선 유지 244건”을 구분하고, 선택 변화와 안전 변화도 별도 지표로 본다.

매니페스트에 등록된 핵심 경로는 `wellnessbox-rnd/src/wellnessbox_rnd/evals/recommendation_replay_compare.py`이다. 구현, 오케스트레이션, 재생 전용 산출물, 단위 테스트, 스모크 스크립트와 JSON 영수증이 모두 존재한다. 추가로 증거가 참조하는 `data/frozen_eval/frozen_eval_v1.jsonl`도 실제 저장소에 있으며 256개 평가 입력을 제공한다.

## 사례 비교와 변조 방지

`build_recommendation_replay_comparison`은 고정 평가 입력마다 먼저 결정 규칙 기준선 응답을 만들고, 같은 요청에 등록된 재생 전용 산출물을 적용해 두 번째 응답을 만든다. 각 사례는 선택 성분, 후보 순위와 점수, 응답 상태, 다음 행동, 안전 지문을 비교한다. 적용 상태도 함께 저장해 모델이 실제로 작동한 사례와 적격하지 않아 기준선을 유지한 사례를 분리한다.

안전 지문은 단순 상태 코드 하나가 아니다. 안전 요약, 플래그, 최상위 근거를 포함하며 실행 시각 `applied_at`만 비교에서 제외한다. 따라서 같은 차단 상태를 유지하면서 규칙 ID나 근거가 달라진 경우도 안전 변화로 잡힌다. `RecommendationReplayCaseComparison.validate_exact_replay_delta`는 저장된 변화 표시가 실제 두 응답의 차이와 같은지 검증한다. `RecommendationReplayComparisonReport.validate_aggregate_counts`는 적용·기준선·실패 수와 각 변화 건수를 사례 목록에서 다시 세어 위조된 집계를 거부한다.

`wellnessbox-rnd/data/original_plan/fixtures/op049_learned_replay_artifact_v1.json`은 `baseline_candidate::vitamin_c` 특성에 0.2 가중치를 둔 명시적 재생 전용 산출물이다. 코호트 버전도 `original_plan_op049_replay_fixture_v1`로 고정되어 있다. 이 파일은 운영 승격 후보가 아니라 두 실행 경로의 차이가 실제로 나타나는지 확인하기 위한 시험 장치다. 추천 오케스트레이션은 OP-048의 적격성·복귀 규칙을 그대로 사용하므로, 재생 평가가 안전 경계를 우회하지 않는다.

## 테스트와 확인한 수치

`wellnessbox-rnd/tests/test_recommendation_replay_product_candidates.py`의 `test_replay_fixture_is_valid_but_explicitly_replay_only`는 산출물 형식이 유효하면서도 재생 전용임을 확인한다. `test_paired_frozen_replay_compares_every_case_and_preserves_safety`는 정확히 256건, 적용 12건, 결정 규칙 유지 244건, 실패 복귀 0건을 확인한다. 같은 테스트가 선택 변경 4건, 순위 또는 점수 변경 5건, 응답 상태·다음 행동·안전 변경 각 0건을 고정한다.

`test_safety_replay_fingerprint_covers_full_summary_and_top_level_evidence`는 안전 지문이 전체 안전 요약과 근거를 포함하는지 시험한다. `test_replay_comparison_schemas_reject_forged_deltas`는 사례 변화 표시, 집계 건수, 학습 상태를 조작한 보고서를 거부한다. `test_service_product_match_contract_covers_mapped_ingredient_contract`는 재생 결과의 성분 식별자가 서비스 상품 변환 계약에서 처리 가능한지도 확인하지만, 실제 서비스 변환의 통합 단계는 OP-050의 범위다.

`wellnessbox-rnd/scripts/run_learned_replay_product_candidates_smoke.py`는 재생 건수가 256인지, 적용과 선택 변화가 0이 아닌지, 응답 상태·다음 행동·안전 변화가 0인지 먼저 검사한 뒤 서비스 상품 QA 결과와 함께 증거를 기록한다. `wellnessbox-rnd/data/original_plan/evidence/op049_op050_replay_product_candidates_smoke_v1.json`의 현재 값도 256·12·244·0, 선택 4, 순위 또는 점수 5, 안전 관련 변화 0으로 테스트와 일치한다. 이번 재실행에서 관련 집중 테스트를 포함한 74개가 통과했다.

## 증거 단계와 해석 제한

현재 단계는 `IMPLEMENTED`다. 증거 파일의 연구 코드 커밋 `94b0374a3599973ba5201a3cc751912f07bb146a` 이후 등록된 OP-049 소스와 테스트에는 차이가 없으므로 JSON 수치가 현재 연구 코드와 맞는다. 고정 평가 세트에서 두 경로를 쌍으로 비교하고 안전 변화가 없음을 재현했다는 주장까지는 근거가 있다.

그러나 256건은 `data/frozen_eval/frozen_eval_v1.jsonl`의 고정 재생 사례이고, 학습 산출물도 의도적으로 만든 시험 파일이다. 선택 변경 4건이 더 좋은 추천이라는 임상 판단은 포함하지 않으며, 순위 변화 5건도 사용자 효용 개선을 뜻하지 않는다. 실제 트래픽 분포, 운영 지연, 장기 결과, 전문가 판정, 생산 배포는 검증하지 않았고 증거에도 `production_operation_proven=false`가 기록되어 있다. 따라서 재생 비교를 운영 효과나 임상 우월성으로 확대 해석하면 안 된다.
## 추천 후보를 점수로 바꿀 때
추천 후보를 잘 고르는 일과 특정 후보를 복용했을 때의 효과를 추정하는 일은 다르다. 이 그룹은 입력 신호가 어떤 점수로 바뀌는지, 안전 차단 전후의 후보가 어떻게 보존되는지, 불확실성을 어디에 표시하는지를 분리해 설명한다.

`OP-049`는 “추천 모델과 deterministic baseline 차이를 replay에서 비교한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=18`, `docs/context/original_plan.pdf#page=19`
- 구현·설계: `wellnessbox-rnd/src/wellnessbox_rnd/evals/recommendation_replay_compare.py`, `wellnessbox-rnd/src/wellnessbox_rnd/orchestration/recommendation_service.py`, `wellnessbox-rnd/data/original_plan/fixtures/op049_learned_replay_artifact_v1.json`
- 테스트·실행: `wellnessbox-rnd/tests/test_recommendation_replay_product_candidates.py`, `wellnessbox-rnd/scripts/run_learned_replay_product_candidates_smoke.py`, `wellnessbox-rnd/data/original_plan/evidence/op049_op050_replay_product_candidates_smoke_v1.json`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `IMPLEMENTED`, 현재 주장 단계를 `IMPLEMENTED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
