# OP-055 개인 개선도와 집단 평균 개선도를 분리한다.

## 개인 관찰값과 집단 추정치를 다른 필드에 보존해야 한다

OP-055는 각 사용자의 시작 대비 변화와 여러 사용자의 평균 변화를 같은 숫자처럼 취급하지 않도록 요구한다. 매니페스트의 정식 정책 파일은 `wellnessbox-rnd/data/contracts/pro_group_effect_summary_v1.json`이다. 계약은 동일한 계획에 묶인 시작·추적 점수 쌍에서 개인별 관찰 변화를 먼저 만들고, 그 개인 변화들의 산술평균으로 집단 추정치를 계산하도록 정한다. 집단 계산의 최소 인원은 2명이다.

개인 결과에는 `plan_id`, 시작·추적 `assessment_id`, 데이터 등급, 평가 도구, 시점, 점수 계약 버전, 시작 분포 해시가 남는다. 집단 결과는 개인 결과 목록과 별도로 원점수 변화 평균, 건강 방향 Z 점수 변화 평균, 백분위 변화 평균, 표본 수를 보관한다. 결과 모델의 인과 해석 허용값은 `false`다. 집단 평균이 양수여도 모든 개인이 개선됐거나 추천 성분이 개선을 일으켰다는 뜻으로 바꾸지 않는다.

도입 전 부모 커밋에는 개인 효과와 집단 효과를 구분하는 계약·모델·집계 함수가 없었다. 따라서 이전 상태의 문제는 화면 라벨 하나가 모호한 정도가 아니라, 집계 결과에서 개인별 관찰 계보를 잃거나 개인 변화 하나를 집단 효과처럼 전달할 수 있는 구조적 공백이었다.

## 집계 함수는 개인 결과를 보존한 채 집단 필드만 다시 계산한다

`wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_group_effects.py`의 `PROGroupEffectSummaryV1`은 `personal_effects`와 `group_estimate`를 서로 다른 필드로 강제한다. 모델 검증기는 저장된 평균, 표본 수, 해석 상태별 수, 불확실성 사유를 개인 결과에서 다시 계산해 비교한다. 호출자가 평균이나 표본 수만 임의로 바꾼 결과 모델은 유효하지 않다.

`build_pro_group_effect_summary_v1`은 개인 결과를 `plan_id` 기준으로 정렬해 입력 순서에 상관없는 결과를 만든다. 중복 계획, 중복 시작 또는 추적 평가, 서로 다른 데이터 등급·시점·평가 도구·점수 계약·시작 분포를 한 집단에 섞으면 실패한다. `_derive_summary_fields`는 정렬된 개인 변화에서 세 평균과 해석 상태별 개수를 계산하고, OP-056의 신뢰구간과 불확실성 사유도 같은 입력에서 파생한다. 개인 결과 목록을 제거한 집단 평균만 반환하지 않기 때문에, 집단 수치가 어떤 개인 관찰값에서 나왔는지 사후에 확인할 수 있다.

이 분리는 익명 집계라는 이유로 계보를 버리지 않는다는 뜻이지, 화면이나 외부 응답에 개인 식별자를 공개한다는 뜻은 아니다. 현재 모듈은 연구 계산 모델을 정의하며 서비스의 접근 제어와 표시 범위는 별도 계층의 책임이다.

## 구현 뒤 증거 출처가 빠진 문제가 소스 경로 보강으로 수정됐다

커밋 `5b9dedc`은 집단 효과 계약, `PROGroupEffectSummaryV1`, 집계 함수, 통계 보조 함수, 단위 테스트와 스모크를 추가했다. 초기 스모크는 결과 계산에는 성공했지만 증거의 소스 식별자 목록에 직접 참조하는 계약 파일과 중간 계약 모듈이 충분히 포함되지 않았다. 커밋 `56d0542`는 스모크의 `SOURCE_PATHS`에 직접 계약 의존성과 `interim/contracts` 경로를 추가하고, 같은 누락이 재발하지 않는 회귀 테스트를 넣었다. 커밋 `0a1f102`는 보강된 결과를 정식 증거로 등록했다.

이 수정은 집단 평균 공식 자체를 바꾼 것이 아니라, 어떤 코드와 계약으로 결과를 만들었는지 증거가 빠짐없이 지칭하도록 한 출처 계보 수정이다. 따라서 이전 증거의 계산값이 틀렸다고 단정할 근거는 없지만, 누락된 출처 목록을 완전한 정식 증거로 취급해서도 안 된다.

## 테스트는 분리된 결과, 순서 독립성, 혼합 집단 거부를 각각 확인한다

`wellnessbox-rnd/tests/test_pro_group_effects.py`의 `test_group_summary_separates_personal_effects_from_group_estimate`는 개인 결과 목록과 집단 추정치가 동시에 존재하고 서로 다른 의미를 유지하는지 확인한다. `test_group_summary_is_order_independent`는 같은 개인 집합의 입력 순서를 바꿔도 정렬된 개인 결과와 집단 수치가 같음을 확인한다. `test_group_summary_rejects_mixed_or_duplicate_cohort_members`는 중복 계획·평가와 서로 다른 집단 식별자의 혼합을 막는다.

`test_group_summary_rejects_derived_output_mutation`은 계산된 평균·표본 수·상태 집계 등을 바꾼 결과 모델이 거부되는지 확인한다. `test_group_effect_contract_rejects_policy_drift`는 최소 표본 수와 집계 정책 등 계약 변조를 막고, `test_smoke_source_identity_includes_direct_contract_dependencies`는 앞서 발견된 증거 출처 누락이 다시 생기지 않도록 한다. 현재 이 파일에서 수집된 18개 테스트는 모두 통과했고, 점수·추적·집단효과·계획 서비스 핵심 네 파일의 79개 테스트도 모두 통과했다.

## 등록 스모크는 100명의 개인 변화와 한 집단 평균을 함께 기록한다

`wellnessbox-rnd/scripts/run_pro_personal_group_uncertainty_smoke.py`와 정식 결과 `wellnessbox-rnd/data/original_plan/evidence/op055_op056_pro_personal_group_uncertainty_smoke_v1.json`은 `plan_000`부터 `plan_099`까지 합성 계획 100개를 집계한다. 모든 개인 결과는 해석 가능 상태로 보존되고, 집단 건강 방향 Z 점수 변화 평균은 0.67, 95% 부트스트랩 구간은 0.616666~0.723333이다. 건강 백분위 변화 평균은 25.779542, 해당 구간은 23.82636~27.745993다.

스모크는 중복 계획, 시점 혼합, 시작 분포 혼합, 파생 결과 변조를 실제 실행에서 거부한다. 단위 테스트는 여기에 중복 평가와 데이터 등급 혼합까지 보완한다. 결과 파일의 소스 해시 `2964b1d…`는 현재 같은 소스 집합에서 다시 계산한 값과 일치하고, 기록된 커밋 `06031bee`도 조사한 경로의 최신 커밋과 일치한다. 따라서 이 증거는 현재 구현과 연결되는 합성 재현 결과다.

## 현재 단계는 IMPLEMENTED이며 집단 대표성과 서비스 노출은 미검증이다

매니페스트의 OP-055 요구 단계와 현재 단계는 `IMPLEMENTED`다. 계약, 구현, 단위 테스트, 결정적 스모크가 있고 현재 소스 식별자도 맞으므로 코드 수준 분리는 확인됐다. 그러나 이 기능을 호출하는 서비스 API, 사용자 화면, 실제 연구 데이터의 집단 구성, 운영 세션, 프로덕션 배포를 입증하는 등록 경로는 없다.

100명은 KPI 경계를 실행하기 위한 합성 표본일 뿐 실제 모집단을 대표하지 않는다. 선택 편향, 중도 탈락, 도구별 분포 차이, 계획 간 독립성, 개인정보 비식별화, 작은 하위집단 노출 위험은 검증되지 않았다. OP-055의 완료 경계는 동일한 계약을 따르는 개인 관찰 변화들을 보존하면서 별도의 집단 평균을 결정적으로 계산하는 구현까지다.
## 효과를 측정할 때 분리한 것
효과를 말하려면 예측값과 실제 복용 전후 관측값을 섞지 않아야 한다. 이 그룹은 PRO 원점수, 표준화, 개인별 변화, 집단 평균, 신뢰구간, 순응도와 이상사례를 각각 기록해 숫자가 무엇을 의미하는지 확인한다.

`OP-055`는 “개인 개선도와 집단 평균 개선도를 분리한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=18`, `docs/context/original_plan.pdf#page=19`
- 구현·설계: `wellnessbox-rnd/data/contracts/pro_group_effect_summary_v1.json`, `wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_group_effects.py`
- 테스트·실행: `wellnessbox-rnd/tests/test_pro_group_effects.py`, `wellnessbox-rnd/scripts/run_pro_personal_group_uncertainty_smoke.py`, `wellnessbox-rnd/data/original_plan/evidence/op055_op056_pro_personal_group_uncertainty_smoke_v1.json`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `IMPLEMENTED`, 현재 주장 단계를 `IMPLEMENTED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
