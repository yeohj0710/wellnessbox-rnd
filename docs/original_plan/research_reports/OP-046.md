# OP-046 추천 이유를 입력 신호, 점수 항목, 근거 ID로 분해해 반환한다.

manifest가 지정한 증거 `wellnessbox-rnd/data/original_plan/evidence/op045_op046_candidate_pool_structured_reasons_smoke_v1.json`에는 한 후보의 입력, 점수, 근거가 별도 구조로 기록돼 있다. 현재 구현은 이 구분을 응답 계약에서 강제하므로 OP-046은 `IMPLEMENTED`다.

## 한 문장짜리 추천 이유가 부족한 까닭

“수면에 도움이 될 수 있어 추천했다”는 문장만으로는 어떤 사용자 입력이 영향을 줬고 점수의 어느 부분이 변했으며 그 판단이 어느 자료에 기대는지 알 수 없다. 특히 안전 조정과 효과 근거가 한 문장에 섞이면, 안전 경고가 효능을 입증한 것처럼 오해될 수 있다. 추천 이유를 입력 신호, 점수 항목, 근거 식별자로 나누는 이유는 점수 계산과 설명 문장을 서로 대조할 수 있게 하기 위해서다.

이 구조는 추천 점수가 임상 효과 확률이라는 주장도 막는다. 현재 점수는 후보 순서를 정하는 규칙·점수 결과이며, 근거의 제한 문구까지 함께 반환한다. 사용자는 어떤 성분이 더 높은 순서에 놓였는지는 볼 수 있지만, 점수 68을 효과 확률 68%로 읽어서는 안 된다.

## 입력·점수·근거를 연결한 구현

`wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation.py`의 `RecommendationReasonBreakdown`은 세 묶음을 요구한다. `input_signals`에는 목표, 증상, 검사, 생활 습관, 식이, 기기, 유전자, 안전 신호를 넣는다. `score_terms`에는 카탈로그 우선순위부터 목표·증상·생활 습관 정합도, 안전 조정, 보수적 조정, 학습 효과 가산점까지 14개 항목을 빠짐없이 둔다. `evidence_links`는 목표 prior, 입력 신호, 안전 규칙을 근거 ID와 주장 ID, 제한 문구에 연결한다.

`wellnessbox-rnd/src/wellnessbox_rnd/optimizer/service.py`는 목표 prior를 `wellnessbox-rnd/src/wellnessbox_rnd/knowledge/goal_priors.py`에서 읽는다. 증상과 생활 습관에 실제로 적용된 점수 규칙도 따로 모은다. 안전 검토로 감점이 생기면 안전 규칙을 입력 신호와 근거 연결에 추가한다. 마지막에는 점수 항목의 합과 후보 총점이 같은지 확인하고, 근거 연결에서 모은 ID 집합과 응답의 요약 ID 집합도 일치시킨다.

## 잘못된 설명을 차단한 시험

설명 자료는 일부 필드만 채워도 통과하지 않는다. `wellnessbox-rnd/tests/test_candidate_pool_structured_reasons.py`는 점수 항목 하나를 지우거나 총점을 1만큼 바꾸거나 중복 근거 연결을 넣었을 때 검증 오류가 나는지 확인한다. `wellnessbox-rnd/tests/test_recommendation_contracts.py`는 다른 목표의 근거 ID를 후보 설명에 끼워 넣는 조작, 학습 가산점은 넣고 `OPT-LEARNED-001` 표시를 빼는 조작, 세부 점수와 총점이 맞지 않는 조작을 거부한다.

기준 증거의 마그네슘 글리시네이트 사례는 요구가 실제 출력에 어떻게 나타나는지 보여 준다. 입력 신호는 `sleep_support`, `high_stress`, `sleep_deficit`, `difficulty_falling_asleep`로 분리돼 있다. 14개 점수 항목의 합은 68.0이고, 목표 prior와 입력 신호 근거에는 `REF-MC-GOAL-PRIOR-001`, `REF-NCCIH-MAGNESIUM-SLEEP-001`, `REF-MC-CANDIDATE-SIGNAL-001`이 연결된다. 근거 제한에는 연구 품질과 성분 제형의 한계가 그대로 남는다. 현재 집중 시험에서도 이 계약 검사가 통과했다.

## 증명된 범위와 설명의 한계

OP-046은 `IMPLEMENTED`로 판단한다. 응답 구조, 합계 대조, 근거 소유 관계는 자동으로 확인되지만, 사람이 이 설명을 실제로 이해하는지 또는 근거 선택이 외부 전문가 검토에서 타당한지는 확인되지 않았다. 조사 범위인 이유 스키마, 목표 prior, 계약 시험과 기준 증거에서 사용자 이해도와 외부 타당성은 `확인되지 않음`이다. 현재 점수는 결정론적 후보 정렬 자료이고 근거 ID는 저장소의 등록 자료를 가리킨다. 실제 임상 효과, 개인별 성공 확률, 운영 중 설명 품질을 주장하려면 별도의 외부 검토와 사용자 관측이 필요하다.
