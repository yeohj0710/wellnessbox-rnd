# OP-046 추천 이유를 입력 신호, 점수 항목, 근거 ID로 분해해 반환한다

## 결론과 해결하려던 문제

OP-046은 사람이 읽는 한 문장만 반환하지 않고 추천 이유를 세 부분으로 분리하도록 요구한다. 현재 응답은 사용자의 어떤 입력이 작용했는지 나타내는 `input_signals`, 계산에 더하거나 뺀 값을 나타내는 `score_terms`, 문헌·주장·안전 규칙을 연결하는 `evidence_links`를 별도 필드로 반환한다. 세 부분은 최종 점수와 다시 대조되므로 설명 문구만 바꾸어 계산 근거를 위조할 수 없다.

이전에는 “수면 목표에 도움이 될 수 있다”와 같은 설명이 있어도 목표 사전점수, 생활 신호, 안전 감점, 근거 문서가 어느 계산 항목에 속하는지 기계적으로 판별하기 어려웠다. 감사자는 총점만 보고 어떤 신호가 몇 점을 만들었는지 재계산하기 어려웠고, 참고문헌 ID를 다른 목표의 근거처럼 붙여도 구조 수준에서 막기 어려웠다. OP-046은 설명을 표시용 문자열이 아니라 검증 가능한 계약으로 바꾼다.

매니페스트에 적힌 구현 경로 `wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation_contracts.py`를 포함해 등록된 소스 5개, 테스트 3개, 스모크 스크립트와 JSON 증거 파일을 모두 열어 확인했다. 각 파일은 입력·점수·근거의 분리와 교차 검증이라는 요구사항을 직접 구현하거나 시험한다.

## 이유 계약과 점수 생성

`wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation.py`의 `RecommendationReasonScoreTerm`은 점수 항목을 임의 문자열로 받지 않는다. 목표 정렬, 연령, 식이, 활동, 스트레스, 수면 부족, 증상, 약물·임신·질환 안전 조정, 현재 복용·사용자 회피 조정, 학습 효과 보너스 등 정확히 14개 항목을 허용한다. `RecommendationReasonBreakdown.validate_reason_partition`은 14개가 빠짐없이 한 번씩 존재하는지, 합계가 `score_total`과 같은지, 입력 신호와 근거 링크의 ID가 요약 ID와 정확히 같은지 검사한다.

`wellnessbox-rnd/src/wellnessbox_rnd/optimizer/service.py`의 `build_recommendation_reason_breakdown`은 목표, 생활 정보, 증상, 안전 결과를 각각 입력 신호로 만들고 점수 항목을 채운다. 예를 들어 목표 일치 점수와 스트레스·수면 부족 점수는 서로 다른 항목으로 남고, 안전 규칙이 작용하면 안전 조정 항목과 규칙 ID가 함께 기록된다. `wellnessbox-rnd/src/wellnessbox_rnd/knowledge/goal_priors.py`의 `load_goal_prior_registry`와 `validate_goal_prior_registry`는 목표별 성분 점수뿐 아니라 참고문헌 ID, 주장 ID, 근거 방향·강도, 한계를 검증한다. 표준 목표 점수 척도는 35, 일반 건강 목표는 18로 고정되어 있다.

`RecommendationReasonEvidenceLink`는 근거 소유자를 `goal_prior`, `input_signal`, `safety_rule`로 구분한다. 목표·입력 근거에는 참고문헌과 주장 ID가 필요하고, 링크의 ID 전체가 이유 요약의 ID 전체와 정확히 일치해야 한다. `build_recommendation_set_contract_v1`이 외부 계약을 만들고, `validate_recommendation_set_contract_v1`과 `_validate_reason_evidence_contract`가 선택 점수, 규칙, 목표 사전점수, 근거 소유권을 다시 대조한다. 내부 모델을 통과한 값도 외부 계약 경계의 재대조 대상이다.

## 테스트가 고정한 정상값과 실패값

`test_structured_reason_separates_inputs_terms_and_evidence_ids`에서는 마그네슘 추천의 수면 목표, 높은 스트레스, 수면 부족, 잠들기 어려움이 개별 신호로 남고 14개 점수 항목의 합계가 68이어야 한다. 같은 사례의 근거 링크는 참고문헌·주장 ID와 제한 문구를 보존해야 한다. `test_candidate_trace_and_reason_contracts_fail_closed_on_mismatch`는 점수 합계, 항목 누락, 링크 ID 불일치 같은 변조를 거부한다.

`wellnessbox-rnd/tests/test_recommendation_contracts.py`에는 외부 계약 회귀 검사가 더 있다. `test_recommendation_set_contract_flags_reason_score_and_rule_mismatch`는 이유 총점과 규칙 참조 변조를 검출한다. `test_recommendation_set_contract_rejects_forged_evidence_ownership`은 `REF-FAKE-001`과 `CLM-FAKE-001`을 다른 목표 근거처럼 추가한 계약을 거부한다. `test_recommendation_set_contract_rejects_unmarked_learned_bonus`는 학습 보너스가 있는데 `OPT-LEARNED-001` 표시가 없는 결과를 거부하고, `test_recommendation_set_contract_rejects_component_signal_sum_mismatch`는 입력 신호의 부분합과 점수 항목이 어긋나는 결과를 잡는다.

`wellnessbox-rnd/data/original_plan/evidence/op045_op046_candidate_pool_structured_reasons_smoke_v1.json`은 마그네슘 사례의 신호, 14개 항목, 총점 68, 참고문헌·주장·제한 정보를 직렬화해 보존한다. 스모크 스크립트는 링크에서 모은 ID와 이유 요약의 ID가 일치하는지도 실행 중 확인한다. 이번 재검증에서는 이 테스트들을 포함한 집중 테스트 74개가 모두 통과했다.

## 현재 증거 단계와 해석 범위

OP-046은 `IMPLEMENTED` 단계다. 입력 신호가 점수 항목을 만들고 점수 항목이 근거 소유권과 연결되는 구조가 코드, API 계약, 단위 테스트, 재현 가능한 JSON 영수증에 구현되어 있다. 증거 파일의 소스 커밋은 `94b0374a3599973ba5201a3cc751912f07bb146a`이며, 그 뒤 등록된 OP-046 구현·시험 경로에는 차이가 없어 영수증과 현재 연구 코드가 같은 동작을 가리킨다.

다만 이 구조는 추천 이유의 추적 가능성을 검증한 것이지, 근거 문헌의 임상적 타당성을 새로 입증한 것이 아니다. 근거 레지스트리에 제한 문구가 있어도 실제 사용자가 이를 이해했는지, 운영 상담자가 이유 분해를 사용했는지, 설명이 건강 결과를 개선했는지는 확인되지 않았다. 증거 파일 역시 `production_operation_proven=false`이므로 `INTEGRATED`나 `OPERATED`로 올릴 근거는 없다.
