# OP-067 Top-k 조합과 선택되지 않은 이유를 반환한다.

manifest의 등록 증거 `wellnessbox-rnd/data/original_plan/evidence/op067_op068_product_combination_top_k_smoke_v1.json`에는 상위 조합 세 건과 평가했지만 고르지 않은 조합 한 건의 사유가 함께 남아 있다.

## 한 개의 정답만 주면 생기는 문제

상품 재고와 가격은 바뀌고, 사용자는 복용 개수나 비용에 서로 다른 우선순위를 둔다. 최상위 조합 하나만 반환하면 두 번째 선택지가 얼마나 비슷한지 알 수 없고, 첫 조합을 사용할 수 없을 때 전체 계산을 다시 설명하기도 어렵다. OP-067의 Top-k는 조건을 통과한 조합 중 앞에서부터 k개를 뜻한다. 이 요구는 후보 여러 개를 보여 주는 데서 끝나지 않고, 평가한 나머지 조합마다 왜 선택되지 않았는지도 구조화해 반환하게 한다.

`src/wellnessbox_rnd/optimizer/product_combinations.py`는 먼저 안전, 예산, 최대 상품 수 조건을 적용한다. 통과한 조합은 총비용이 낮은 순서, 상품 수가 적은 순서, 조합 식별자 순서로 정렬한다. 마지막 식별자 비교는 비용과 상품 수가 같을 때도 순위가 실행할 때마다 흔들리지 않게 하는 최종 기준이다. 호출자가 정한 `max_ranked_combinations`만큼만 `top_k`에 넣고, 각 항목에는 순위와 실제 정렬 기준값을 함께 기록한다.

선택되지 않은 조합에는 한 개 이상의 사유가 반드시 붙는다. 예산을 넘으면 `OVER_BUDGET`, 상품 수 제한을 넘으면 `OVER_MAX_PRODUCTS`, 차단 성분을 포함하면 `SAFETY_EXCLUDED_INGREDIENT`다. 조건을 통과했지만 상위 k개 밖이라면 더 비싼지, 상품 수가 더 많은지, 두 값이 같아 식별자로 순서가 갈렸는지를 `HIGHER_COST`, `MORE_PRODUCTS`, `DETERMINISTIC_ID_TIE_BREAK`으로 구분한다. 이 정보는 단순 설명 문구가 아니라 조합과 정책에서 다시 계산되는 값이다.

## 결과 위조와 누락을 막은 방법

`ProductCombinationRankingEvidenceV1`은 받은 순위표를 그대로 믿지 않는다. 원래 조합과 필터 정책으로 상위 목록과 제외 사유를 다시 만들고, 전달된 결과와 한 항목씩 비교한다. 입력 조건과 카탈로그 내용, 최종 순위 결과에는 각각 SHA-256 지문 값이 붙는다. 순위 숫자, 제외 사유, 추천 점수, 카탈로그 상품명, 결과 지문 가운데 하나라도 바꾼 자료는 입력 구조와 값을 함께 확인하는 Pydantic 자료형 검증에서 거부된다.

`wellnessbox-rnd/tests/test_product_combinations.py`는 네 조합을 평가해 한 건만 상위로 남기는 사례를 사용한다. 선택되지 않은 조합 중 한 건은 더 비싸다는 사유를 받고, 두 건은 예산 초과 사유를 받는다. 이어서 순위를 2로 바꾸거나 사유 배열을 비우는 변조를 넣어 오류가 나는지 확인한다. 이 시험은 “사유 필드가 존재한다”가 아니라 사유가 실제 비용·상품 수·안전 조건과 맞는지를 다룬다.

## 서비스 연결에서 관측한 수치

기준 실행은 서비스 쪽 상품 후보 함수가 만든 조합 네 건을 R&D 순위 함수로 다시 계산했다. 상위 세 건의 정렬 기준은 각각 63,000원·5개, 76,000원·6개, 78,000원·6개였다. 남은 한 건에는 `HIGHER_COST`가 기록됐다. R&D가 다시 만든 `top_k`, `non_selection`, 입력·카탈로그·결과 지문이 서비스 보고와 모두 같았다.

같은 서비스 보고를 반복했을 때 상위 목록과 제외 사유가 같았고, 카탈로그 행 순서를 바꾼 경우에도 결과가 유지됐다. 생성 스크립트 `wellnessbox-rnd/scripts/run_product_combination_top_k_reproducibility_smoke.py`는 이 비교를 통과해야만 기준 증거를 작성한다. 실패를 고친 시간순 기록은 이 증거와 테스트에 남아 있지 않아 확인되지 않았다. 대신 누락 사유와 조작된 순위가 어떤 오류로 차단되는지는 현재 회귀 시험에서 직접 확인할 수 있다.

## 현재 단계와 해석 범위

기준 증거는 서비스 경로 함수에서 만든 자료를 R&D 순위 모델이 독립 재계산한 사실을 근거로 OP-067을 `INTEGRATED`로 판정한다. `service_route_function_integration_proven=true`가 이 범위를 나타낸다. 이 작업에서는 저장소 경계 때문에 manifest에 적힌 `wellnessbox/lib/server/wb-rnd-product-candidates.ts`와 서비스 시험 파일을 직접 열지 않았고, 기준 증거에 고정된 서비스 커밋과 파일 목록을 확인했다.

운영까지 증명된 것은 아니다. 같은 증거에 `actual_ready_rnd_http_path_proven=false`, `actual_prisma_query_executed=false`, `production_operation_proven=false`가 명시돼 있다. 따라서 현재 단계는 `INTEGRATED`이며, 실제 데이터베이스에서 읽은 최신 상품과 공개 서비스 요청에서도 같은 상위 목록과 제외 사유가 나오는지는 확인되지 않았다.
