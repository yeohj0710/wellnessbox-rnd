# OP-067 Top-k 조합과 선택되지 않은 이유를 반환한다.

## 요구사항이 요구한 결과의 모양

조건을 통과한 상품 조합 가운데 상위 k개와 나머지 조합의 비선택 사유를 함께 반환해야 한다. 최상위 한 건만 주면 재고가 바뀌거나 첫 선택지를 사용할 수 없을 때 대안을 설명할 수 없다. 반대로 여러 건을 순서 없이 나열하면 어떤 기준으로 앞선 조합을 골랐는지 감사할 수 없다. OP-067은 순위, 순위 기준값, 비선택 사유를 모두 구조화한 결과를 요구한다.

초기 순위 구현은 커밋 `16a079f`에서 들어왔다. 이 구현은 비용, 상품 수, 조합 식별자를 순서대로 비교해 상위 목록을 만들고, 평가했지만 고르지 않은 조합에 사유를 붙였다. 그러나 초기 비선택 사유는 조건을 통과했지만 상위 k개 밖에 있다는 사실을 `LOWER_RANKED` 하나로만 표현했다. 또한 R&D 검증 함수는 호출자가 넘긴 입력 지문과 카탈로그 버전을 그대로 받아 결과 지문을 만들었다. 순위 결과만 그럴듯하게 맞추고 원래 입력이나 카탈로그 내용을 다른 값으로 붙일 수 있는 증거 공백이 있었다.

커밋 `0476ac5`는 두 문제를 함께 고쳤다. `LOWER_RANKED`를 `HIGHER_COST`, `MORE_PRODUCTS`, `DETERMINISTIC_ID_TIE_BREAK`으로 나누고, R&D가 `optimization_input`과 `catalog_identity`에서 지문을 직접 계산하도록 바꿨다. 커밋 `dc8e145`는 한 단계 더 나아가 실제 필터 정책이 지문에 들어간 제약과 일치하는지 검사했다. 서비스 저장소의 커밋 `1e5fe20`은 출력 상한에 먼저 도달했다고 탐색을 멈추던 방식을 고쳐 전체 탐색 범위에서 적격 조합을 정렬한 뒤 최대 64건만 보관하게 했다. 탐색 상태 상한 4,096을 넘긴 경우에는 불완전한 순위표를 내지 않고 `SEARCH_TRUNCATED`를 남긴다.

## 함수와 자료형이 순위를 고정하는 방법

구현 중심은 `wellnessbox-rnd/src/wellnessbox_rnd/optimizer/product_combinations.py`의 `_derive_ranking()`이다. 함수는 먼저 `_derive_filter_identities()`로 예산, 최대 상품 수, 안전 제외 조건을 적용한다. 통과 조합은 `total_cost_krw`, `product_count`, `combination_id` 순으로 정렬된다. 앞의 두 값이 같은 때에도 16자리 조합 지문이 마지막 비교 기준이 되므로 배열의 우연한 입력 순서가 순위를 바꾸지 않는다.

`max_ranked_combinations`만큼의 앞부분은 `RankedProductCombinationV1`이 된다. 각 항목은 1부터 시작하는 `rank`와 세 값의 `ranking_tuple`을 보존한다. 상위 목록에 들지 않은 모든 평가 조합은 `ProductCombinationNonSelectionV1`로 이동한다. 예산과 상품 수를 모두 넘었다면 두 사유가 함께 남고, 안전 제외 성분도 별도 코드로 추가된다. 조건을 통과했으나 절단선 밖이면 절단선 조합과 값을 비교해 더 비싼지, 상품 수가 많은지, 두 값이 같아 식별자로 갈렸는지 정한다.

`ProductCombinationRankingEvidenceV1.validate_ranking_evidence()`는 받은 `top_k`와 `non_selection`을 그대로 승인하지 않는다. 원본 조합, 정책, k값에서 두 배열을 다시 만든다. 이어 실제 정책과 `replay_identity.optimization_input.constraints`의 비용·상품 수·제외 성분·안전 규칙을 대조한다. 추천 성분·순위·점수·근거 식별자와 제약을 묶은 입력 지문, 상품 내용 전체의 카탈로그 버전, 순위와 사유를 포함한 결과 지문도 재계산한다. 이 검증을 통과해야 순위 증거가 성립한다.

서비스에서는 `wellnessbox/lib/server/wb-rnd-product-candidates.ts`의 `buildProductCombinations()`가 탐색한 조합과 제외 집계를 만들고, `rankProductCombinations()`가 같은 세 값으로 순위를 매긴다. 계약 파일 `wellnessbox/contracts/wb-rnd/product-candidate-match-v1.json`은 `max_ranked_product_combinations`를 3으로, 전체 출력 조합 상한을 64로, 탐색 상태 상한을 4,096로 고정한다. `wellnessbox/lib/server/wb-rnd-interim-route.ts`는 R&D 안전 응답과 최적화 조건을 먼저 검증한 후에 이 함수를 부른다.

## 구체적인 시험과 관측 결과

`wellnessbox-rnd/tests/test_product_combinations.py`의 `test_combination_ranking_recomputes_top_k_reasons_and_result_identity`는 비용이 다른 네 조합에서 k를 1로 둔다. 19,000원·2개 조합이 1위가 되고, 비선택 사유는 `HIGHER_COST` 한 건과 `OVER_BUDGET` 두 건이어야 한다. 같은 함수를 두 번 호출한 객체와 결과 지문도 같아야 한다.

`test_combination_ranking_rejects_forged_outputs`는 다섯 종류의 조작을 각각 넣는다. 순위를 2로 바꾸기, 비선택 사유를 비우기, 결과 지문을 0으로 바꾸기, 추천 점수를 0.9에서 0.8로 바꾸기, 카탈로그 상품명을 바꾸기다. 모두 Pydantic 자료형 검증에서 실패한다. `test_combination_ranking_rejects_policy_outside_hashed_input`은 실제 정책의 예산을 1원으로 바꾸되 지문 입력에는 35,000원을 남겨 `ranking policy does not match canonical optimization input`이 나는지 본다.

서비스 시험 `wellnessbox/scripts/qa/check-rnd-product-candidates.cts`는 실제 `POST /api/tips` 경로에서 상위 3건, 모든 비선택 사유, 전체 적격 조합을 먼저 정렬하는 동작, 탐색 절단 시 빈 상위 목록을 확인한다. 생성기 `wellnessbox-rnd/scripts/run_product_combination_top_k_reproducibility_smoke.py`는 서비스 결과를 다시 R&D 순위 함수에 넣고 두 결과가 항목별로 같은 경우에만 증거를 작성한다.

등록 증거 `wellnessbox-rnd/data/original_plan/evidence/op067_op068_product_combination_top_k_smoke_v1.json`에는 네 조합이 기록돼 있다. 상위 세 건은 `combo_39b190324c7b00ff` 63,000원·5개, `combo_ef3df859d62c0163` 76,000원·6개, `combo_aeb9dff90d5edf7a` 78,000원·6개 순이다. 남은 `combo_b0b285099554b28d`에는 `HIGHER_COST`가 붙었다. 이 수치는 코드가 문구만 반환한 것이 아니라 실제 정렬 기준값과 사유를 보존한다는 것을 보여 준다.

## 현재 판단과 남은 검증

OP-067은 `INTEGRATED` 단계다. 서비스 경로 함수가 만든 네 조합을 R&D 모델이 독립적으로 재정렬했고, 상위 3건과 비선택 한 건의 사유가 모두 같았다. 매니페스트가 요구한 통합 단계와 증거 파일의 `op067_proven_stage`가 같은 것도 확인했다.

실제 Prisma 조회는 수행되지 않았다. 기준 파일의 `actual_ready_rnd_http_path_proven=false`, `actual_prisma_query_executed=false`, `production_catalog_freshness_proven=false`, `production_operation_proven=false`가 이 한계를 명시한다. 따라서 최신 운영 상품을 읽어 동일한 사유를 사용자에게 보여 주는 경로까지 증명한 것은 아니다. 현재 근거로 말할 수 있는 범위는 서비스 함수와 R&D 독립 검증기 사이에서 Top-k와 비선택 사유가 일치한다는 데까지다.
