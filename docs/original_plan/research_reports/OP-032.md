# OP-032 응급 위험 신호 규칙을 추가하고 모든 추천을 중단한다.

manifest의 등록 경로 `wellnessbox-rnd/src/wellnessbox_rnd/orchestration/recommendation_service.py`는 응급 위험 신호가 들어온 요청을 `blocked`로 끝내고 최종 추천 목록을 비우는 흐름을 구현한다. 규칙 원본에는 흉통과 심한 복통을 뜻하는 두 코드가 `SAFETY-URGENT-SYMPTOM-001`에 연결돼 있다.

## 응급 상황에서는 효능 비교가 답이 아닌 이유

흉통처럼 즉시 대응해야 할 신호가 있는데 건강기능식품 후보를 제시하면 사용자가 필요한 조치를 늦출 수 있다. 그래서 이 요구사항은 특정 성분만 빼는 일반 주의 규칙보다 강하다. 하나의 응급 코드라도 현재 입력에 있으면 안전 상태를 `blocked`로 만들고, 추천 대신 안전 재확인을 다음 행동으로 반환해야 한다.

입력 형식은 단순 문자열과 구조화된 `UrgentRiskSignal`을 모두 받는다. 구조화 입력에는 코드, 현재 존재 여부인 `present`, 정보 출처인 `source`가 있다. `normalize_request`는 `present=true`(현재 존재함)인 항목만 `risk_flag_set`에 넣는다. `wellnessbox-rnd/data/rules/safety_rules.json`의 응급 규칙은 `red_flag_chest_pain`과 `red_flag_severe_abdominal_pain` 가운데 하나가 있으면 전체 차단 등급과 “추천을 중단한다”는 사유를 남긴다.

## 중단 결과가 뒤 단계에서 바뀌지 않는 방식

`recommend`는 후보를 반환하기 전에 안전 요약을 먼저 만든다. 응급 규칙이 적용되면 최종 응답은 전체 차단 상태(`blocked`)가 되고, 다음 행동은 `trigger_safety_recheck`, 추천 목록은 빈 배열이 된다. 후보 추적 자료에도 `global_blocked=true`(요청 전체가 차단됨)가 남아 안전 중단을 정상 추천처럼 해석하지 못하게 한다. 임신이나 입력 부족만을 대상으로 한 제한적인 상태 완화 조건은 응급 규칙 ID를 없애지 못하므로 이 분기에 해당하지 않는다.

다만 구현은 차단 상태에서도 진단용 순위 자료를 만들기 위해 내부 후보 선별 함수를 한 번 호출한다. 최종 사용자에게 추천을 내보내지는 않지만, “응급 신호가 있으면 후보 계산 함수조차 호출되지 않는다”는 더 강한 의미까지 구현됐다고 쓰면 사실과 다르다. OP-032에서 직접 입증된 중단 경계는 추천 요청 응답과 실행 결정이다.

## 실패 경계를 확인한 시험

`wellnessbox-rnd/tests/test_inference_api.py`의 `test_recommend_endpoint_blocks_urgent_risk_flag_before_recommendation`은 정상 추천이 가능한 표본에 흉통 위험 코드를 추가한다. 응답은 HTTP 200으로 안전 판정을 전달하지만 본문 상태는 `blocked`이고, 추천은 0건이며, 규칙 참조에 `SAFETY-URGENT-SYMPTOM-001`이 포함된다. 적용 시각에 시간대가 있고 규칙 버전이 양수인지도 함께 본다.

재현 경로의 별도 구현은 `wellnessbox-rnd/src/wellnessbox_rnd/interim/safety.py`에 있다. 이 코드는 흉통, 아나필락시스, 자살 사고, 심한 출혈을 `STOP_AND_ESCALATE`로 올린다. `wellnessbox-rnd/tests/test_interim_safety.py`는 흉통, 임신, 와파린-오메가3 상호작용이 동시에 있어도 가장 강한 응급 조치가 유지됨을 확인한다. 어떤 시험이 처음 깨졌는지는 `확인되지 않음`으로 남긴다. 구현 전 실패 로그가 등록 증거에 없어서 현재 파일과 재발 방지 시험까지 조사했다.

## 현재 증거가 허용하는 판단

구조화 입력, 차단 규칙, 빈 추천 응답과 재현 경로가 로컬 코드와 시험으로 확인됐으므로 단계는 `IMPLEMENTED`다. 추천 요청 규칙은 현재 두 위험 코드만 받으며, 재현 경로의 네 증상과 목록이 완전히 같지 않다. 실제 응급 신고 체계 연결, 의료진 전달, 운영 경보 수신은 검증하지 않았다. 이 보고서는 추천 중단 구현을 설명할 뿐 실제 응급 대응이 운영된 `OPERATED` 또는 외부기관이 확인한 `EXTERNAL` 증거로 확대하지 않는다.
