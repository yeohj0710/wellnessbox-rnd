# OP-032 응급 위험 신호가 있으면 모든 추천을 중단한다.

manifest에 등록된 `wellnessbox-rnd/src/wellnessbox_rnd/orchestration/recommendation_service.py`는 구조화된 응급 신호가 적용되면 응답 상태를 `blocked`로 만들고 추천 목록을 비운다. 규칙 데이터, 안전 판정, 최종 응답 조립, API 테스트를 대조한 결과 OP-032는 `IMPLEMENTED`다.

## 요구사항과 과거 결손

OP-032의 핵심은 특정 성분만 제외하는 것이 아니라 추천 절차 전체를 안전하게 끝내는 것이다. manifest는 원문 요구 위치를 `docs/context/original_plan.pdf#page=17`로 가리킨다. 흉통처럼 즉시 대응이 필요한 신호가 있는 요청에서 건강기능식품 순위를 보여 주면 사용자가 필요한 조치를 늦출 수 있으므로, 위험 신호는 개인화 점수나 일반 경고보다 먼저 최종 결과를 지배해야 한다.

커밋 `1ef1cf3` 이전 코드에는 요청의 `risk_flags`, 정규화된 위험 신호 집합, 응급 규칙, 구조화된 안전 차단 판별이 없었다. 해당 커밋은 이 입력과 규칙을 추가하고, `SAFETY-URGENT-SYMPTOM-001`을 최종 추천의 구조화된 차단 사유로 인식하도록 추천 서비스를 바꿨다. 변경 기록에서 구현 전 기능 부재와 추가된 회귀 테스트는 확인했지만, 수정 당시 실패 출력은 저장소에 남아 있지 않다.

## 위험 신호를 읽고 차단하는 경로

`wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation.py`는 단순 문자열과 구조화된 `UrgentRiskSignal`을 모두 허용한다. 구조화된 값에는 `code`, 현재 존재 여부인 `present`, 입력 출처인 `source`가 있다. `wellnessbox-rnd/src/wellnessbox_rnd/domain/intake.py`는 `present=true`인 신호만 정규화된 `risk_flag_set`에 넣고, 문자열 입력은 기존 호환 출처를 가진 현재 신호로 취급한다. `present=false`인 과거 신호는 차단 조건이 되지 않는다.

`wellnessbox-rnd/src/wellnessbox_rnd/domain/models.py`는 응급 조건과 규칙 메타데이터를 가진 안전 규칙 모델을 정의한다. 실제 정책 파일 `wellnessbox-rnd/data/rules/safety_rules.json`의 `SAFETY-URGENT-SYMPTOM-001`은 `red_flag_chest_pain`과 `red_flag_severe_abdominal_pain` 중 하나가 있으면 적용된다. 규칙은 심각도 `blocker`와 전역 차단 사유를 만든다. `wellnessbox-rnd/src/wellnessbox_rnd/safety/service.py`는 다른 안전 규칙보다 먼저 위험 신호를 검사하고 적용 시각과 규칙 버전을 안전 요약에 기록한다.

추천 서비스는 안전 요약 뒤에도 후보 선택 함수를 한 번 호출한다. 이 호출은 차단 상황의 후보 진단 자료를 남기기 위한 것이며 사용자에게 추천을 반환한다는 뜻은 아니다. 구조화된 차단 사유가 있으면 최종 응답은 `status="blocked"`, `recommendations=[]`, `next_action="trigger_safety_recheck"`가 되고 후보 추적 자료는 `global_blocked=true`가 된다. 임신이나 신장 관련 설문 보정 분기가 일부 안전 상태를 완화할 수 있지만, `_has_structured_safety_blocker`가 응급 규칙 ID를 검사하므로 이 응급 차단은 보정 대상이 아니다.

## 두 안전 경로의 검증 범위

`wellnessbox-rnd/tests/test_inference_api.py`의 `test_recommend_endpoint_blocks_urgent_risk_flag_before_recommendation`은 정상적으로 추천 가능한 요청에 `red_flag_chest_pain`을 추가한다. 테스트는 HTTP 200으로 안전 판정 자체는 전달되지만 본문 상태가 `blocked`인지, 추천 수가 0인지, 다음 행동이 `trigger_safety_recheck`인지 확인한다. 또한 `SAFETY-URGENT-SYMPTOM-001`이 적용되었고 적용 시각에 시간대가 있으며 규칙 버전이 1 이상이라고 단언한다. 즉 오류 응답으로 숨기지 않고 구조화된 차단 결과를 반환하는 계약까지 검사한다.

별도 사전 점검 경로인 `wellnessbox-rnd/src/wellnessbox_rnd/interim/safety.py`는 증상 문자열에서 흉통, 아나필락시스, 자살 사고, 심한 출혈을 찾으면 `STOP_AND_ESCALATE`를 반환한다. `wellnessbox-rnd/tests/test_interim_safety.py`의 `test_emergency_and_hard_blocks_are_not_overridden`는 응급 증상이 임신이나 약물 상호작용과 함께 있어도 가장 강한 응급 조치가 유지되는지 확인한다. 이 사전 점검은 추천 API의 두 위험 코드와 입력 체계가 같지 않으므로, 두 테스트는 서로 다른 경로를 보완할 뿐 하나의 통합 응급 체계를 입증하지는 않는다.

## 현재 단계와 확인하지 못한 사항

manifest에 등록된 구현 파일 여섯 개와 `wellnessbox-rnd/tests/test_inference_api.py`는 모두 존재하며 현재 코드 내용이 OP-032의 추천 중단 요구와 일치한다. 이에 따라 단계는 `IMPLEMENTED`다. 저장소 밖의 신고 시스템 연동, 의료진 전달, 운영 경보 수신, 실제 응급 대응 시간은 이번 증거에 포함되지 않는다.

추천 API가 직접 인식하는 위험 코드는 현재 흉통과 심한 복통 두 개다. 사전 점검 경로가 더 많은 증상을 인식한다고 해서 추천 API도 같은 증상을 구조화된 위험 코드로 처리한다고 볼 수 없다. 또한 후보 선택 함수가 차단 뒤에도 진단 목적으로 실행되므로, “어떤 후보 계산도 전혀 수행하지 않는다”는 더 강한 주장도 근거와 맞지 않는다. 검증된 결과는 후보 계산의 유무가 아니라 사용자 응답에서 추천이 완전히 제거되고 안전 재점검 행동이 지정된다는 점이다.
## 안전 판단에서 놓치면 안 되는 경계
안전 그룹의 기준은 추천을 많이 만드는 것이 아니라 위험한 결과를 통과시키지 않는 것이다. 입력 단계와 후보 생성 뒤에 안전 판단을 두고, 중대한 위험이나 불명확한 용량이 나오면 fail-closed로 멈추는 경계를 확인한다.

`OP-032`는 “응급 위험 신호 규칙을 추가하고 모든 추천을 중단한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=17`
- 구현·설계: `wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation.py`, `wellnessbox-rnd/src/wellnessbox_rnd/domain/intake.py`, `wellnessbox-rnd/src/wellnessbox_rnd/domain/models.py`, `wellnessbox-rnd/src/wellnessbox_rnd/safety/service.py` 외 2개
- 테스트·실행: `wellnessbox-rnd/tests/test_inference_api.py`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `IMPLEMENTED`, 현재 주장 단계를 `IMPLEMENTED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
