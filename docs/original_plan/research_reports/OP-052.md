# OP-052 시작 분포를 사용한 Z 점수와 건강 백분위 변환을 고정한다.

## 요구사항은 원점수 계산과 표준화 계산을 한 계약으로 고정하는 것이다

OP-052는 PSQI, ISI, PSS-10 응답에서 원점수를 계산한 뒤, 같은 도구의 시작 분포로 건강 방향 Z 점수와 백분위를 만드는 절차를 재현 가능하게 고정한다. 매니페스트가 지정한 계약은 `wellnessbox-rnd/data/contracts/pro_instrument_scoring_v1.json`이고, 구현은 `wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_scoring.py`다. 계약은 PSQI 7개 구성요소를 각 0~3점으로 합산해 0~21점, ISI 7개 문항을 각 0~4점으로 합산해 0~28점, PSS-10 10개 문항 중 4·5·7·8번을 역채점해 0~40점으로 계산하도록 정한다. 세 도구 모두 원점수가 낮을수록 건강 상태가 좋다는 방향도 계약에 포함한다.

표준화에는 최소 2개의 시작 관측치, 산술평균, 표본 표준편차(`ddof=1`)를 사용한다. 건강 방향 Z 점수는 `(시작 평균 - 문제 원점수) / 시작 표본 표준편차`로 계산하고, 표준정규 누적분포를 백분위로 바꾼 뒤 Python의 half-even 반올림으로 소수점 여섯 자리까지 보존한다. 이 규칙 덕분에 원점수가 낮아진 사람의 Z 점수와 백분위가 함께 높아진다. 시작 분포가 0으로 퍼지지 않거나 도구·계약 버전·분포 해시가 맞지 않으면 결과를 만들지 않는다.

기능 도입 전 부모 커밋에도 `pro_scoring.py` 파일은 있었지만, 지금의 세 도구별 버전 채점 클래스·함수와 시작 분포 표준화 경계는 없었다. 위 JSON 계약, 전용 단위 테스트, 스모크 실행기도 없었다. 따라서 이전 문제는 알려진 계산식 하나의 산술 오류가 아니라, 도구별 채점법과 시작 분포 변환을 버전·해시와 함께 검증할 공통 경계가 없었다는 점이다.

## 클래스와 함수는 입력, 시작 분포, 변환 결과를 서로 바꿔 끼우지 못하게 한다

`PROInstrumentDefinitionV1`과 `PROBaselineStandardizationContractV1`은 도구 정의와 표준화 정책을 읽고 검증한다. `PROInstrumentScoringContractV1`은 두 정의를 하나의 버전 계약으로 묶는다. `PROInstrumentResponseV1`과 `PROInstrumentScoreV1`은 응답과 채점 결과를 구분하고, `PROBaselineScoreObservationV1`과 `PROBaselineDistributionV1`은 개인의 시작 점수와 집계된 시작 분포를 구분한다. `PROStandardizedScoreV1`은 원점수, 건강 방향 Z 점수, 백분위, 계약 버전, 시작 분포 해시를 한 결과에 보관한다.

`load_pro_instrument_scoring_contract_v1`은 정식 계약 파일만 읽고 계약 해시를 계산한다. `score_pro_instrument_response_v1`은 문항 수·정수 범위·역채점 위치를 다시 검증한 뒤 원점수를 낸다. `build_pro_baseline_distribution_v1`은 동일한 도구와 계약으로 채점된 시작 관측치만 모아 평균과 표본 표준편차를 계산한다. `standardize_pro_instrument_score_v1`은 점수와 분포의 도구, 버전, 계약 해시를 대조한 뒤 Z 점수와 백분위를 만든다. 공개 함수가 이미 생성된 Pydantic 모델도 다시 검증하므로, `model_construct` 등으로 검증을 우회한 객체를 정상 입력처럼 받을 수 없다.

## 커밋 이력은 계약 도입과 증거 식별자 보강을 구분한다

커밋 `fd7e4a3`은 세 도구 계약, 점수 모듈, 단위 테스트, 스모크 실행기를 함께 추가했다. 이 커밋의 차이는 계산 규칙을 한곳에 모으고 잘못된 문항 수, 범위 밖 값, 알 수 없는 도구, 계약 변조, 분포 불일치를 닫힌 실패로 바꾼 구현 근거다. 커밋 `3bfdfed`는 실행 결과를 `wellnessbox-rnd/data/original_plan/evidence/op051_op052_versioned_pro_scoring_smoke_v1.json`에 등록했고, `0e7ea31`은 증거의 소스 식별자를 현재 산출 방식에 맞게 갱신했다.

저장소에는 `fd7e4a3` 이전에 같은 기능을 실행해 실패한 테스트 로그가 없다. 그러므로 “기존 계산이 특정 값으로 실패했고 이 커밋이 그 값을 고쳤다”고 소급해 말할 근거는 없다. 확인 가능한 수정 이력은 계약이 없던 상태에서 버전 계약과 실패 차단 검사를 추가했고, 이후 증거의 출처 식별자를 보강했다는 범위다.

## 테스트는 계산 예시뿐 아니라 경계 위조와 순서 독립성을 증명한다

`wellnessbox-rnd/tests/test_versioned_pro_instrument_scoring.py`의 `test_instrument_contract_fixes_three_scoring_algorithms`는 세 도구의 문항 수, 범위, 역채점, 방향이 계약에 고정됐음을 확인한다. `test_raw_score_examples_match_existing_service_contract_examples`와 `test_raw_score_boundaries_are_exact`는 대표 입력과 최솟값·최댓값을 확인한다. `test_invalid_responses_fail_closed`, `test_unknown_instrument_and_contract_drift_fail_closed`, `test_model_instances_are_revalidated_at_every_public_boundary`는 잘못된 입력이나 위조 모델이 공개 함수 경계를 넘지 못함을 증명한다.

`test_baseline_distribution_uses_sample_statistics_and_is_order_independent`는 `ddof=1` 표본 통계와 입력 순서 독립성을 확인한다. `test_health_z_and_percentile_use_the_same_baseline_distribution`은 Z 점수와 백분위가 동일한 시작 분포를 공유함을 확인한다. `test_distribution_and_transform_reject_incompatible_or_forged_inputs`와 `test_output_models_reject_noncanonical_instrument_metadata`는 도구·버전·해시가 다른 분포와 결과 메타데이터 변조를 막는다. 현재 이 파일에서 수집된 18개 테스트는 모두 통과했고, OP-052·054·055·057 관련 핵심 테스트를 함께 실행한 79개 테스트도 모두 통과했다.

스모크 증거는 PSQI 원점수 6·9·12에 평균 9와 표본 표준편차 3, ISI 7·14·21에 평균 14와 표준편차 7, PSS-10 10·20·30에 평균 20과 표준편차 10을 기록한다. 세 묶음 모두 Z 점수 1·0·-1과 건강 백분위 84.134475·50·15.865525를 재현했다. 불리언·실수 입력, 계약과 제한사항 변조, 위조 분포, 추적 시점 점수의 시작 관측치 오용, 비정식 출력, 범위·문항 수·도구 오류, 분산 0 등 13개 실패 차단 항목도 모두 `true`다.

## 현재 단계는 IMPLEMENTED이며 실제 사용자 분포는 아직 검증하지 않았다

매니페스트의 현재 단계는 `IMPLEMENTED`다. 등록 증거의 `source_identity.source_sha256`은 현재 소스에서 다시 계산한 해시 `c160aea6…`와 일치하고, 기록된 소스 커밋 `b6b6c5d`도 해당 경로의 최신 커밋과 일치한다. 따라서 등록 스모크는 현재 계약과 구현을 대상으로 재현 가능한 코드 수준 증거다.

다만 스모크의 점수와 시작 분포는 합성 데이터다. 실제 사용자 집단의 분포 품질, 표본 대표성, 임상적 컷오프의 타당성, 서비스 API를 거친 저장·조회, 운영 세션, 외부 기관 검증은 이 증거가 확인하지 않는다. OP-052가 보장하는 완료 경계는 세 도구의 버전 채점과 시작 분포 변환이 저장소 안에서 결정적으로 계산되고 잘못된 입력을 거부한다는 데까지다.
## 효과를 측정할 때 분리한 것
효과를 말하려면 예측값과 실제 복용 전후 관측값을 섞지 않아야 한다. 이 그룹은 PRO 원점수, 표준화, 개인별 변화, 집단 평균, 신뢰구간, 순응도와 이상사례를 각각 기록해 숫자가 무엇을 의미하는지 확인한다.

`OP-052`는 “시작 분포를 사용한 Z 점수와 건강 백분위 변환을 고정한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=18`, `docs/context/original_plan.pdf#page=19`
- 구현·설계: `wellnessbox-rnd/data/contracts/pro_instrument_scoring_v1.json`, `wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_scoring.py`
- 테스트·실행: `wellnessbox-rnd/tests/test_versioned_pro_instrument_scoring.py`, `wellnessbox-rnd/scripts/run_versioned_pro_scoring_baseline_percentile_smoke.py`, `wellnessbox-rnd/data/original_plan/evidence/op051_op052_versioned_pro_scoring_smoke_v1.json`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `IMPLEMENTED`, 현재 주장 단계를 `IMPLEMENTED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
