# OP-051 PSQI, ISI, PSS-10 원점수 계산을 버전 고정한다

## 결론과 요구사항

OP-051은 세 가지 환자 보고 설문 도구의 원점수 계산 규칙을 코드 관행이 아니라 버전이 있는 계약으로 고정하는 요구사항이다. 현재 계약 버전 `2026-07-17.1`은 PSQI 7개 구성요소의 합, ISI 7개 문항의 합, PSS-10 10개 문항 중 4개 역채점의 합을 각각 정의한다. 입력 개수·범위·정수형과 계산 추적을 모두 검증하므로 잘못된 응답을 조용히 보정하지 않는다.

이전 위험은 구현자가 설문 이름만 보고 역채점 위치, 점수 범위, 구성요소 수를 다르게 해석하는 것이었다. 원점수가 같아 보여도 어떤 문항을 뒤집었는지 알 수 없으면 회귀 검증이 어렵다. 현재 응답은 원본 값, 채점 값, 역채점 위치, 합계를 `PROInstrumentScoreV1`에 함께 남겨 같은 계약으로 재계산할 수 있다.

매니페스트에 등록된 계약 경로는 `wellnessbox-rnd/data/contracts/pro_instrument_scoring_v1.json`이다. 이 파일과 `wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_scoring.py`, 단위 테스트, 스모크 스크립트, JSON 증거 파일이 모두 존재하며 원점수 규칙과 일치한다.

## 세 도구의 고정된 계산

PSQI는 7개 구성요소를 각각 0부터 3까지 받아 그대로 합산하며 범위는 0부터 21이다. 이 계약은 PSQI 전체 설문 문항을 구성요소 점수로 바꾸는 별도 알고리즘을 제공하지 않는다. 따라서 입력은 이미 계산된 7개 구성요소여야 한다.

ISI는 7개 문항을 각각 0부터 4까지 받아 합산하며 범위는 0부터 28이다. 역채점 문항은 없다. PSS-10은 10개 문항을 각각 0부터 4까지 받고, 1부터 세었을 때 4·5·7·8번 위치를 `4 - 원점수`로 바꾼 뒤 합산한다. PSS-10 범위는 0부터 40이다. 낮은 점수가 항상 좋은 결과라는 식의 임상 해석은 원점수 계산 계약에 포함하지 않는다.

`wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_scoring.py`의 `load_pro_instrument_scoring_contract_v1`은 JSON을 Pydantic 모델로 읽은 뒤 코드 내부의 기대 계약과 전체 사전을 비교한다. 파일 버전, 도구 이름, 문항 수, 문항 범위, 역채점 위치, 점수 범위, 출처와 제한 중 하나라도 바뀌면 계약 드리프트 오류로 닫힌다. 모델은 `extra="forbid"`, `revalidate_instances="always"`, `StrictInt`를 사용해 알 수 없는 필드, 불리언, 실수, 생성 뒤 변조된 인스턴스를 거부한다.

`score_pro_instrument_response_v1`은 도구 이름을 계약에서 찾고 응답 개수와 각 값의 범위를 검사한다. 역채점 위치만 변환한 뒤 합계를 계산하고, 결과 모델 검증기가 원본·변환 배열의 길이, 각 변환값, 합계와 허용 범위를 다시 확인한다. 알 수 없는 도구를 임의의 합산 방식으로 처리하지 않는다.

## 테스트가 고정한 값과 실패 경계

`wellnessbox-rnd/tests/test_versioned_pro_instrument_scoring.py`에서 OP-051을 직접 검증하는 테스트는 앞부분 여섯 개다. `test_instrument_contract_fixes_three_scoring_algorithms`는 세 정의와 역채점 위치를 확인한다. `test_raw_score_examples_match_existing_service_contract_examples`는 서비스 계약 예시와 같은 원점수를 재현한다. `test_raw_score_boundaries_are_exact`는 PSQI 0·21, ISI 0·28, PSS-10 0·40의 정확한 경계를 확인한다.

`test_invalid_responses_fail_closed`는 문항 개수 부족·초과, 범위 밖 값, 실수와 불리언을 거부한다. `test_unknown_instrument_and_contract_drift_fail_closed`는 알 수 없는 도구, 변경된 버전, 변조된 역채점 위치를 허용하지 않는다. `test_model_instances_are_revalidated_at_every_public_boundary`는 이미 생성된 모델을 복사·변조해 넘겨도 공개 함수가 다시 검증하는지 확인한다. 같은 파일의 이후 분포·z점수·백분위 테스트는 OP-052의 표준화 요구사항을 검증하며 OP-051 원점수 완료 근거와 구분해야 한다.

등록된 `wellnessbox-rnd/scripts/run_versioned_pro_scoring_baseline_percentile_smoke.py`는 세 도구의 원점수와 실패 경계를 실행한 뒤 OP-052 표준화 결과도 같은 영수증에 기록한다. `wellnessbox-rnd/data/original_plan/evidence/op051_op052_versioned_pro_scoring_smoke_v1.json`의 OP-051 사례는 PSQI 7, ISI 10, PSS-10 16을 정확한 채점 추적과 함께 보존한다. 잘못된 문항 수·범위·형식·계약 변조의 거부도 모두 `true`다. 계약 파일 SHA-256은 `73c5621bedcb30f00831d5dc37d157e1838cf7556a23f9bebdb19f89a52b9987`로 기록되어 있고 현재 계약 파일 해시와 같다. 이번 확인에서 이 파일의 테스트를 포함한 집중 테스트 74개가 통과했다.

## 증거 단계와 한계

현재 단계는 `IMPLEMENTED`다. 계약, 로더, 점수 함수, 실패 폐쇄 테스트와 재현 가능한 JSON 증거가 있다. 증거의 소스 커밋은 `b6b6c5d2bcc28da06fe2a2f0a8957a20ccd7b3b7`이고, 이 커밋 이후 매니페스트에 등록된 OP-051 계약·구현·테스트·스모크 경로에는 차이가 없다. 증거의 결합 소스 해시 `c160aea6e19116239c090f323c8a0c7a278f287130002bea44ea40c4f22c5536`과 현재 원점수 동작을 함께 확인했다.

증거 파일은 합성 입력 경계이며 `clinical_validation_proven=false`, `service_integration_proven=false`, `production_operation_proven=false`를 명시한다. 설문 원문과 사용 허가, PSQI 원문 응답에서 7개 구성요소를 계산하는 절차, 임상 절단점 해석, 실제 서비스 저장·조회는 이 요구사항에서 검증하지 않았다. 원점수 계약의 결정론적 구현을 임상 타당성이나 운영 사용 증거로 확대하지 않는다.
## 효과를 측정할 때 분리한 것
효과를 말하려면 예측값과 실제 복용 전후 관측값을 섞지 않아야 한다. 이 그룹은 PRO 원점수, 표준화, 개인별 변화, 집단 평균, 신뢰구간, 순응도와 이상사례를 각각 기록해 숫자가 무엇을 의미하는지 확인한다.

`OP-051`는 “PSQI, ISI, PSS-10 원점수 계산을 버전 고정한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=18`, `docs/context/original_plan.pdf#page=19`
- 구현·설계: `wellnessbox-rnd/data/contracts/pro_instrument_scoring_v1.json`, `wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_scoring.py`
- 테스트·실행: `wellnessbox-rnd/tests/test_versioned_pro_instrument_scoring.py`, `wellnessbox-rnd/scripts/run_versioned_pro_scoring_baseline_percentile_smoke.py`, `wellnessbox-rnd/data/original_plan/evidence/op051_op052_versioned_pro_scoring_smoke_v1.json`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `IMPLEMENTED`, 현재 주장 단계를 `IMPLEMENTED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
