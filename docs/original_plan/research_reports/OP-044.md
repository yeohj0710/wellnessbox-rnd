# OP-044 웨어러블, CGM, 유전자 관측값을 수치로 점수에 반영한다.

## 관측값을 그대로 신뢰하지 않는 이유

웨어러블, 연속혈당측정기(CGM), 유전자 자료는 수치와 출처 형식이 서로 다르고 민감도도 높다. 수면 시간이 분 단위인지 시간 단위인지, 혈당이 mg/dL인지 mmol/L인지, CGM 목표 범위가 무엇인지 확인하지 않고 점수를 계산하면 같은 관측값이 다른 결과를 만든다. 유전자 태그도 검사 기관과 측정 근거 없이 문자열만 받으면 사용자가 임의로 넣은 값과 검증된 관측값을 구분할 수 없다.

이 요구사항은 원자료를 표준 단위와 구조로 바꾸고, 사용 동의와 입력 가용성을 확인한 뒤에만 후보 정렬 점수에 반영한다. 점수는 질병 진단이나 치료 효과가 아니라 후보 간 순서를 정하는 제한된 값이다. 규칙 버전과 적용 신호를 응답에 남겨 관측값이 어떤 계산을 만들었는지도 추적한다.

## 웨어러블·CGM·유전 점수 규칙

`wellnessbox-rnd/data/rules/candidate_signal_scoring_rules_v1.json`은 웨어러블 수면 시간이 7시간보다 짧을 때 부족한 시간당 마그네슘에 2점, L-테아닌에 1.5점을 더한다. 최대 증가는 각각 6점과 4.5점이다. 예를 들어 5.5시간 수면은 1.5시간 부족이므로 마그네슘에 3점을 더한다.

CGM은 정확히 70~180 mg/dL로 정의된 범위의 목표 범위 내 비율(TIR)이 70%보다 낮을 때만 사용한다. 식이섬유는 부족한 1%포인트당 0.2점, 최대 6점이고 베르베린은 0.1점, 최대 3점이다. 이 규칙은 당뇨 상태가 명시되고 임신 중이 아닌 경우로 제한된다. TIR 55%라면 식이섬유는 3점을 받지만 범위가 다르거나 임신 상태이면 0점이다. 유전자 태그는 `CYP1A2`가 L-테아닌에 4점, `LPL`이 오메가3에 4점을 더한다.

## 동의·단위·범위 오류를 막는 방식

`wellnessbox-rnd/src/wellnessbox_rnd/domain/sensor_parser.py`는 수면 분을 시간으로, 혈당 mmol/L를 mg/dL로 변환한다. 표준 TIR 별칭을 사용하면 하한 70과 상한 180을 고정하고, 서로 충돌하는 별칭이나 범위는 거부한다. 유전자 변이는 검사실, 판정 근거, 측정일 같은 출처 정보를 보존하며 필수 정보가 없거나 형식이 잘못되면 점수 입력으로 만들지 않는다.

센서 값은 자료 출처별 동의와 입력 가용성이 모두 명시되어야 한다. 동의가 거부된 출처는 정규화된 입력 스냅샷에서 값이 제거되고 점수는 0이 된다. 시험은 거부된 민감 정보 때문에 정규화 입력 해시가 달라지지 않는지도 확인한다. 데이터 레이크 계보 시험에서는 웨어러블 저장 동의만 허용했을 때 웨어러블 자료만 저장되고 CGM과 유전자 원자료는 남지 않았으며, 민감한 원문 문자열도 저장 결과에서 발견되지 않았다.

CGM 이벤트 연결 계층은 파서가 만든 값을 평가와 재생 입력으로 전달하고, 동일 관측값을 서로 다르게 표현한 필드가 충돌하면 실패시킨다. 이 검사는 API 입력, 평가 입력, 재생 입력이 서로 다른 수치를 사용해 같은 세션을 다르게 계산하는 일을 막는다.

## 검증 결과와 남은 한계

스모크 증거 `wellnessbox-rnd/data/original_plan/evidence/op043_op044_candidate_signal_scoring_smoke_v1.json`은 수면 5.5시간에서 마그네슘 3점, TIR 55%에서 식이섬유 3점, 잘못된 CGM 범위와 임신 상태에서 0점, `LPL` 태그에서 오메가3 4점을 확인한다. 센서 파서, CGM 이벤트, 데이터 저장 계보 시험은 단위 변환과 동의 거부, 출처 보존 경계를 별도로 검증한다.

현재 완료 단계는 **IMPLEMENTED**다. 파서, 입력 계약, 동의 차단, 수치 규칙, 후보 점수 연결과 자동 시험은 구현되어 있다. 그러나 확인한 자료에는 실제 웨어러블·CGM 기기 API 연결, 외부 검사기관 유전자 자료의 진위 검증, 프로덕션 운영 기록이 없다. 또한 점수 증가는 임상 효능이나 치료 권고를 의미하지 않는다. 실제 기기 연동 단계에서는 공급자별 단위·시간대·결측 처리와 동의 철회 후 삭제가 같은 기준을 유지하는지 추가 검증해야 한다.
