# OP-115 두 저장소의 단위·통합·E2E·인코딩·빌드 검사를 통과한다.

## 결론

OP-115는 요구 단계 `INTEGRATED`에 도달했다. R&D 저장소의 FastAPI 배포 계약 테스트 15건과 실제 프로세스 재시작 smoke 8건이 통과했다. WellnessBox 저장소에서는 R&D health alias QA, TypeScript 타입 검사, 인코딩 감사, Next.js 프로덕션 빌드가 모두 통과했다. 검사는 구현 파일을 읽는 정적 확인에 그치지 않고 FastAPI 프로세스, HTTP health 응답, Next.js route가 사용하는 서버 함수를 실행했다.

## 검사 범위와 기존 시스템 재사용

R&D는 기존 `tests/test_deployment_contract.py`와 `scripts/run_deployment_contract_endpoint_smoke.py`를 재사용했다. 이 경로는 health, 추천, 상태 기계, 기기, 상담 API를 한 프로세스에 마운트하고 영속 SQLite를 사용한 재시작까지 검사한다. WellnessBox는 기존 환경 계약 `lib/server/wb-rnd-environment.ts`를 그대로 사용했다. 새 health 기능만 별도 클라이언트로 추가했으며 추천·관리자 API 클라이언트를 복제하지 않았다.

단위·통합·E2E라는 이름만 붙인 빈 검사는 사용하지 않았다. 배포 계약의 실패 폐쇄 조건은 pytest가 검증하고, 프로세스 smoke는 실제 HTTP 소켓과 재시작 데이터 보존을 검증한다. WellnessBox health QA는 임시 HTTP 서버를 세워 실제 fetch 요청 경로와 정상·비활성 응답을 검증한다. `npm run build`는 새 `/api/internal/rnd/health` route를 포함한 프로덕션 번들을 생성했다.

## 오류 입력과 경계 동작

R&D 배포 계약은 짧은 내부 토큰, 상대 DB 경로, 다중 SQLite worker, 누락된 provider secret reference를 거부한다. WellnessBox alias는 R&D 연동이 꺼져 있으면 503 `disabled`, upstream 호출이나 JSON 처리가 실패하면 503 `unavailable`을 반환한다. 공개 응답에는 토큰, upstream URL, 예외 stack을 넣지 않는다. 정상 응답도 upstream의 전체 health 문서를 그대로 노출하지 않고 상태, 환경, 배포 준비 여부만 전달한다.

## canonical evidence 생성과 재현 범위

동결 데이터셋 `data/original_plan/op115_op116_test_matrix_health_alias_cases_v1.json`은 두 저장소의 검사 계층과 health 왕복을 8건으로 고정한다. canonical evidence는 실행한 검사 결과, 관측값, WellnessBox 커밋과 관련 Git blob을 기록한다. 같은 커밋에서 각 명령을 다시 실행하면 코드와 결과의 대응을 확인할 수 있다. 로컬 `.env` 값이나 토큰은 evidence에 기록하지 않았다.

## 단계 경계와 남은 조건

OP-115의 필수 단계는 저장소 간 통합 검사 통과이므로 현재 증거로 충족한다. 다만 이 보고서는 장기간 부하, 실제 provider 장애, 프로덕션 트래픽을 증명하지 않는다. 그 항목은 OP-116 이후의 운영 증거로 별도 관리한다.
