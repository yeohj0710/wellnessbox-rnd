# OP-058 추천 성분과 관찰 효과 계보를 같은 계획 ID로 연결한다.

## 왜 계획 ID가 연결의 중심인가

관찰 점수가 좋아지거나 나빠졌다는 사실만으로는 어느 추천을 따른 결과인지 알 수 없다. 같은 사람이 여러 조합을 차례로 복용했다면 사용자 ID와 날짜만으로 추천 성분을 정확히 찾기도 어렵다. OP-058은 추천 요청, 선택 성분, 복용 전 점수와 후속 효과를 하나의 계획 ID로 묶어 조사 가능한 계보를 남긴다. 여기서 계보는 한 결과가 어떤 추천과 입력에서 이어졌는지 추적하는 연결 기록을 뜻한다.

매니페스트에 등록된 `wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation.py`는 추천 요청에 계획 ID를 받는다. 호출자가 값을 주지 않으면 요청 ID의 SHA-256 지문 앞 32자로 결정적인 `plan_...` 값을 만든다. `src/wellnessbox_rnd/orchestration/recommendation_service.py`는 차단 응답과 정상 응답 모두 같은 계획 ID를 반환한다. 이어 `ExecutionLedger.record_recommendation`이 요청과 응답의 계획 ID가 다르면 저장하지 않는다.

## 추천부터 효과까지 같은 값을 전달한 방법

`src/wellnessbox_rnd/interim/data_lake.py`는 추천 사건과 최적화 사건에 계획 ID를 각각 저장한다. 최적화 사건에는 실제 선택된 성분 키 목록도 남긴다. PRO 계획을 등록할 때 `src/wellnessbox_rnd/orchestration/pro_plan_service.py`는 같은 ID로 복용 전 사건을 만든다. 이후 2주·4주·중단 기록은 기존 복용 전 사건의 계획 ID와 요청값이 같은지 확인하고, 다르면 `pro_followup_plan_id_mismatch`로 거부한다.

효과 결과에는 ID 한 개만 복사하지 않는다. `src/wellnessbox_rnd/metrics/pro_correction.py`의 `PRORecommendationEffectLineageV1`은 실행 ID, 계획 ID, 추천 사건 ID, 최적화 사건 ID, 선택 성분 키, 복용 전 사건 ID와 후속 사건 ID를 함께 반환한다. 이 구조 덕분에 “어떤 성분을 골랐는가”에서 “어느 후속 점수로 효과를 계산했는가”까지 같은 실행 원장에서 양방향으로 찾을 수 있다. 관찰 효과는 원인으로 확정할 수 없으므로 `causal_effect_claim_allowed`는 항상 거짓이다.

## 다른 계획이 섞이는 실패를 차단한 시험

`tests/test_data_lake_lineage.py`는 추천과 최적화 사건의 계획 ID가 요청값과 같은지 검사하고, 응답 계획 ID를 다른 값으로 바꾸면 `recommendation_plan_id_mismatch`가 나는지 확인한다. `tests/test_pro_plan_service.py`는 복용 전 사건까지 세 사건이 같은 ID를 갖는지, 재등록이 기존 실행과 복용 전 사건을 재사용하는지 본다. 후속 요청에서 다른 계획 ID나 다른 설문을 보내는 경우도 저장 전에 거부한다.

보정 시험은 연결 정보가 완성되기 전에 원자료를 바꾸지 않는다. 추천 또는 최적화 사건이 없으면 보정을 중단하고 기존 후속 사건을 그대로 보존한다. 반대로 정상 보정은 원래 후속 사건 ID를 유지하면서 새 점수와 계획 연결 정보를 반환한다. 보고서 재작성 중 관련 R&D 시험과 서비스 QA를 다시 실행했으며, 계획 ID 유지·불일치 거부·서비스 경로 전달 시험이 통과했다. 서비스 QA를 처음 직접 실행했을 때는 서버 전용 Node 조건이 빠져 실패했지만, `package.json`의 공식 실행 조건을 적용하자 통과했다.

## 통합 증거가 보여 주는 실제 연결

기준 통합 증거 `wellnessbox-rnd/data/original_plan/evidence/op057_op058_pro_correction_plan_lineage_smoke_v1.json`은 `plan_0974bca3a038aabfccd5f5ccc0ed9b8b` 계획을 기록했다. 선택 성분은 `magnesium_glycinate`와 `l_theanine`이었다. 추천 사건과 최적화 사건에 계획 ID가 있었고, 복용 전·후 두 PRO 사건도 모두 같은 값을 사용했다. 추천과 효과는 같은 실행 ID에 속했으며 서비스 TypeScript 경로에서 로컬 R&D HTTP API까지 실제로 통과했다.

이 기준 실행 증거가 생성됐을 때 확인된 단계는 `INTEGRATED`였다. 증거 파일도 `op058_proven_stage`를 `INTEGRATED`, 요구 단계를 `OPERATED`로 구분하고 상용 운영은 거짓으로 기록한다. 따라서 성분과 관찰 효과의 구체적인 연결을 직접 보여 주는 가장 강한 자료는 로컬 통합 실행이다. 이 결과는 실제 사용자 결과나 성분의 인과 효과를 증명하지 않는다.

## 운영 단계가 추가된 근거와 한계

현재 매니페스트는 이후 추가된 `wellnessbox-rnd/data/original_plan/final_session/operational_evidence/OP-058.json`을 근거로 OP-058을 `OPERATED`로 표시한다. 이 영수증은 실제 자료 등급의 `wellnessbox-local-research-pc` 세션에서 `followup` 경로를 실행했고 `followups`가 1건 늘었다고 기록한다. `data/original_plan/operational_action_coverage_v1.json`은 이 운영 행동을 OP-058에 연결한다. 파일에는 발급자와 Ed25519 서명 값도 들어 있지만, 이 보고서 작업에서 서명을 별도로 재검증하지는 않았다.

운영 영수증은 사건별 계획 ID나 선택 성분 목록을 펼쳐 보여 주지 않는다. 그러므로 `OPERATED` 주장은 “로컬 실제 세션에서 OP-058에 대응하는 후속 경로가 실행됐다”는 매니페스트의 운영 정의에 한정한다. 구체적인 계획 계보는 앞선 통합 실행으로 보완된다. 공개 서비스, 상용 데이터베이스, 장기 보존·삭제 뒤의 연결 복구와 외부 검증은 `확인되지 않음`으로 남긴다. 조사 범위는 등록된 R&D 구현·시험·통합 실행 증거, 서비스 연결 파일, OP-058 운영 영수증과 운영 경로 대응표까지였다. 현재 단계는 `OPERATED`지만 `EXTERNAL`이나 상용 운영으로 넓혀 말할 수 없다.
