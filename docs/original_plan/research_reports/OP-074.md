# OP-074 CronJob이 만기 계획을 찾아 재평가 작업을 생성한다.

## 무엇을 해결했는가

후속 예정일이 지나면 재평가가 자동으로 시작돼야 하지만, 반복 실행되는 스케줄러가 같은 일을 여러 번 만들면 안 된다. 만기 전에는 작업을 만들지 않고, 만기 뒤에는 계획별 재평가 작업을 정확히 한 번 저장하도록 했다.

## 어떻게 구현했는가

`WorkflowJobQueue.enqueue_due_plan_reevaluations()`는 열린 후속 기록 가운데 기준 시각이 지난 항목만 고른다. 작업 식별자는 계획과 후속 기록에서 결정적으로 계산한다. 같은 스케줄러가 다시 실행돼도 기존 작업을 되돌려주므로 중복 실행 후보가 늘지 않는다.

## 무엇으로 확인했는가

등록 증거 `wellnessbox-rnd/data/original_plan/evidence/op073_op074_followup_job_queue_cron_smoke_v1.json`은 만기 전 0건, 만기 뒤 계획별 1건, 뒤이은 재시도에서도 동일 건수를 기록한다. 명령행 스케줄러도 같은 큐 서비스를 호출한다.

## 어디까지 믿을 수 있는가

결정적 시각을 사용한 로컬 테스트는 완료됐다. 실제 운영 CronJob의 장기 실행과 장애 복구 기록은 없으므로 `OPERATED` 단계는 주장하지 않는다. 운영 확인 항목은 H-007에서 한 번에 처리한다.
