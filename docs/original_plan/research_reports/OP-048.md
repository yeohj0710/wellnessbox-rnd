# OP-048 learned artifact가 없거나 의심스러우면 deterministic baseline으로 복귀한다.

manifest 증거 `wellnessbox-rnd/data/original_plan/evidence/op047_op048_decision_uncertainty_learned_fallback_smoke_v1.json`은 학습 모델 파일(learned artifact)의 여러 실패 상태에서 같은 입력·같은 기준 추천이 유지됐음을 기록한다. 여기서 deterministic baseline은 같은 입력에 같은 규칙과 점수를 적용하는 기준 추천 로직이다. OP-048의 현재 단계는 `IMPLEMENTED`다.

## 학습 결과를 선택 기능으로 둔 이유

학습 모델 파일은 없을 수 있고, 파일 형식은 맞아도 현재 코드가 모르는 특성을 포함할 수 있다. 숫자가 지나치게 크거나 예측 도중 오류가 나면 후보 순서 일부만 바뀐 채 응답이 만들어질 위험도 있다. 건강기능식품 추천에서 이런 실패가 안전 규칙이나 기준 추천을 우회해서는 안 된다. 따라서 학습 재정렬은 낮은 위험의 동률 후보를 가르는 선택 기능이고, 기준 경로는 항상 남아 있어야 한다.

적용 대상도 제한했다. `wellnessbox-rnd/src/wellnessbox_rnd/optimizer/service.py`는 안전 상태가 `OK`이고 후보가 있으며 임신, 질환, 약물 입력이 없고 목표가 `general_wellness` 하나일 때만 학습 재정렬을 허용한다. 항응고제처럼 고위험 입력이 있는 사례는 모델 파일이 정상이어도 기준 로직을 사용한다.

## 파일 검증과 전체 복귀 절차

`wellnessbox-rnd/src/wellnessbox_rnd/models/efficacy_model_v0.py`는 모델 이름, 목표 이름, 학습 집단 버전, 특성 이름, 가중치 개수를 검사한다. 현재 실행 경로가 지원하지 않는 특성, 카탈로그에 없는 후보, 공백이 붙은 이름, 닫힌 값 목록에 없는 목표·성별·활동 수준도 문제로 분류한다. 계수는 유한해야 하며 절댓값 10을 넘을 수 없다. 후보별 특성이 하나도 없는 파일도 의심 자료로 거부한다.

경로가 없으면 `fallback_missing_path`, 파일이 없으면 `fallback_missing_file`, JSON이나 스키마가 깨지면 `fallback_invalid_artifact`, 내용이 실행 정책과 맞지 않으면 `fallback_suspicious_artifact`를 반환한다. 예측 중 예외가 나면 `fallback_artifact_runtime_error`다. 모든 복귀 상태에서 이미 계산한 기준 후보 목록을 그대로 반환하고 실행 모드를 `deterministic_baseline_v1`로 유지한다. 학습 규칙 표시와 학습 가산점도 남기지 않는다.

이 방식은 부분 결과를 채택하지 않는다. 여러 후보 중 첫 후보 예측만 성공하고 다음 예측이 실패해도 첫 후보의 가산점을 버리고 전체 목록을 원래 기준 결과로 되돌린다. 오류 난 한 후보만 빼는 방식보다 보수적이지만, 응답이 어떤 계산 경로를 거쳤는지 모호해지는 일을 막는다.

## 실패 주입과 경계 검증

`wellnessbox-rnd/tests/test_decision_uncertainty_learned_fallback.py`는 잘못된 JSON, 특성·가중치 개수 불일치, 알 수 없는 실행 특성, 카탈로그에 없는 후보, 비정상적으로 큰 가중치를 각각 넣는다. 예측 함수를 두 번째 호출에서 실패시키는 시험은 첫 번째 후보에 잠시 적용된 변경까지 모두 폐기되는지 확인한다. `wellnessbox-rnd/tests/test_learned_optimizer_integration.py`는 낮은 위험의 근접 후보에서만 비타민 C가 비타민 D3보다 앞설 수 있고, 항응고제 사례에서는 학습 가산점이 0으로 남는지 다룬다.

기준 증거에는 누락·무효·의심·실행 오류를 포함한 12개 복귀 상태가 들어 있다. 학습 예측 함수가 두 번 호출된 뒤 오류가 난 사례도 기준 추천을 그대로 보존했다. 별도의 `wellnessbox-rnd/tests/test_learned_runtime_boundary_audit.py`는 공개 추천 경로가 기본값으로 학습 재정렬을 끄며, 안전 엔진이 학습 모듈을 가져오지 않는지 확인한다. 현재 관련 집중 시험은 모두 통과했다.

## 증명된 단계와 제한

OP-048은 `IMPLEMENTED`다. 누락·손상·의심 파일과 실행 오류에서 결정론적 복귀가 자동 시험으로 입증됐다. 그러나 실제 운영에서 배포된 학습 모델 파일의 교체, 감시, 장애 빈도는 확인되지 않았다. 모델 검사기, 추천 경로, 실패 주입 시험과 기준 증거를 살폈으며 배포 환경의 경보·복구 기록은 `확인되지 않음`으로 분류한다. 현재 모델은 합성 자료의 효과 대용값을 다루며 임상 효과를 입증하지 않는다. 기준 증거도 `production_operation_proven=false`다. 운영 단계 주장을 하려면 배포 환경에서 잘못된 파일 주입과 예측 장애가 실제 기준 응답으로 복귀하고 경보·기록까지 남는지 관측해야 한다.
