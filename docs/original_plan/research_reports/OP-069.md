# OP-069 재고 변경 시 안전 조건을 유지하며 대체 조합을 계산한다.

등록 증거 `wellnessbox-rnd/data/original_plan/evidence/op069_op070_product_combination_stock_cart_smoke_v1.json`은 이전에 고른 상품 한 개가 재고 목록에서 사라진 뒤 다른 안전한 조합을 다시 선택한 과정을 보존한다.

## 단순한 품절 교체가 아닌 이유

재고가 없어진 상품과 비슷한 상품을 바로 바꾸면 처음 추천을 만들 때 적용한 안전 조건과 비용 조건이 빠질 수 있다. 복합 상품에는 원래 추천하지 않은 성분이 들어갈 수 있고, 더 비싼 대체품이 예산을 넘을 수도 있다. OP-069은 품절 상품 하나를 이름으로 치환하는 기능이 아니다. 이전 최적화 입력을 고정한 채 현재 카탈로그 전체를 다시 평가하고, 안전 조건이 보존됐을 때만 새 상위 조합을 인정하는 요구다.

`src/wellnessbox_rnd/optimizer/product_combinations.py`의 `ProductCombinationInventoryContextV1`은 이전 카탈로그 버전, 이전 상위 조합 식별자, 당시 입력과 결과 지문, 안전 제외 성분과 규칙, 선택 상품과 약국 상품 식별자를 한데 묶는다. 모델은 이전 조합 식별자를 선택 목록에서 다시 계산하고, 이전 카탈로그 버전이 저장된 재생 정보와 같은지도 대조한다. 호출자가 과거 조합이나 안전 조건을 다른 값으로 바꿔 대체 계산의 출발점을 꾸밀 수 없게 한 것이다.

현재 카탈로그로 순위를 다시 만들 때 추천 성분, 점수, 근거, 예산, 최대 상품 수, 제외 성분과 안전 규칙은 이전 값과 같아야 한다. 검증기는 이전과 현재의 `optimization_input`이 다르면 대체 결과를 거부한다. 바뀔 수 있는 것은 카탈로그 내용과 그 내용에서 계산한 버전뿐이다. 이전 선택에 있던 약국 상품 식별자가 현재 카탈로그에 없을 때만 `missing_pharmacy_product_ids`에 들어간다.

## 대체 결과를 판정하는 방법

재고가 실제로 빠졌고 현재 상위 조합이 이전과 달라졌을 때 상태는 `SUBSTITUTED`가 된다. 이 자료에는 이전·현재 카탈로그 버전, 두 조합 식별자, 사라진 약국 상품 식별자, 안전 조건 보존 여부, 최적화 입력 유지 여부가 들어간다. `ProductCombinationStockCartEvidenceV1`은 이전 선택이 과거 상위 조합과 맞는지, 품절 목록이 현재 카탈로그에서 독립적으로 계산되는지, 현재 조합이 새 순위의 1위인지 차례로 다시 확인한다.

기준 사례에서는 조합 후보가 8건에서 4건으로 줄었고 약국 상품 `30004` 한 건이 사라졌다. 이전 1위 `combo_a9af0169dbf9de70` 대신 `combo_da17182d16b21e1c`가 선택됐다. 추천 입력은 같았고, `ING:ZINC` 제외와 `SAFE-OP069-STOCK-SUBSTITUTION` 규칙도 유지됐다. 증거의 `safety_constraints_preserved=true`와 `optimization_input_unchanged=true`는 단순 표기가 아니라 두 순위 자료를 모델이 비교한 결과다.

## 잘못된 교체를 거부하는 시험

`wellnessbox-rnd/tests/test_product_combinations.py`는 이전 선택 목록과 맞지 않는 조합 식별자를 넣으면 `identity does not match` 오류가 나는지 확인한다. `ProductCombinationStockCartEvidenceV1`의 검증 규칙은 사라진 상품이 없거나, 안전 조건이 바뀌거나, 이전 입력이 달라지거나, 새 조합이 현재 1위가 아니면 자료를 승인하지 않는다. 서비스 보고에서 만든 이전·현재 순위도 R&D 함수로 각각 다시 계산해 상위 목록, 비선택 사유, 재생 지문이 같은지 비교했다.

실패를 발견하고 수정한 시간순 이력은 manifest에 등록된 구현·시험·증거 파일만으로 확인되지 않았다. 이번 조사에서는 위 모델과 시험, `wellnessbox-rnd/scripts/run_product_combination_stock_cart_smoke.py`, 기준 JSON을 읽어 현재 실패 조건을 확인했다. 서비스 파일은 AGENTS.md의 저장소 경계에 따라 직접 열지 않았고, 증거에 기록된 서비스 소스 목록과 커밋을 확인했다.

## 현재 단계와 아직 확인하지 않은 것

서비스 경로 함수에서 재고 변경 자료를 만들고 R&D가 이전·현재 순위를 독립 계산했으므로 현재 단계는 `INTEGRATED`다. 증거는 서비스 전용 재고 문맥을 R&D 요청에 섞지 않았고, 새 안전한 1위를 서비스의 장바구니 후보 계약으로 변환한 사실까지 보여 준다.

하지만 이 검증은 실제 Prisma 쿼리를 실행하지 않았다. 운영 데이터베이스의 품절 행, 여러 재고 변경이 동시에 일어나는 상황, 공개 배포에서의 최신 카탈로그 반영도 확인되지 않았다. 따라서 “서비스 함수 연결에서 안전 조건을 유지한 대체 조합을 계산했다”까지만 믿을 수 있고, 운영 재고가 항상 제때 반영된다고 주장할 수는 없다.
