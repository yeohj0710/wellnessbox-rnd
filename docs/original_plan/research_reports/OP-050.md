# OP-050 추천 결과를 실제 서비스 성분과 상품 후보로 변환한다.

manifest의 기준 증거는 `wellnessbox-rnd/data/original_plan/evidence/op049_op050_replay_product_candidates_smoke_v1.json`이다. R&D 성분을 WellnessBox 성분으로 바꾸고 기존 `/api/tips` 경로에서 판매 후보를 붙이는 서비스 코드까지 연결돼 있어 OP-050은 `INTEGRATED`다. 다만 공개 운영과 실제 판매 데이터베이스 사용은 증명되지 않았다.

## R&D 성분만으로는 사용자가 상품을 고를 수 없다

R&D는 `magnesium_glycinate`처럼 연구용 성분 키를 반환하지만 서비스는 `ING:MAGNESIUM` 같은 식별자와 판매 상품 ID를 사용한다. 이름이 비슷하다는 이유만으로 상품을 붙이면 더 넓거나 좁은 성분 개념을 같은 것으로 오인할 수 있다. 상품명에 성분 단어가 있어도 실제 함량, 재고, 가격, 제형이 없으면 구매 후보로 제시할 수 없다. 따라서 식별자 변환과 판매 후보 확인을 두 단계로 나눴다.

현재 `wellnessbox/contracts/wb-rnd/ingredient-identifier-map-v1.json`은 R&D 키와 서비스 ID의 관계, 허용 변환 방향, 매핑 버전을 저장한다. `calcium_citrate`와 `ING:CALCIUM`처럼 서비스 쪽이 더 넓은 관계도 명시한다. `wellnessbox/contracts/wb-rnd/product-candidate-match-v1.json`은 서비스 ID별 한글·영문 검색어와 후보 수, 조합 수, 탐색 상태 수의 상한을 둔다.

## 기존 서비스 경로에 상품 후보를 붙인 방법

`wellnessbox/app/api/tips/route.ts`의 POST는 기존 `runUserInterimRecommendationRoute`를 호출한다. `wellnessbox/lib/server/wb-rnd-interim-route.ts`는 R&D 추천 응답의 안전 권한을 먼저 검사한다. 추천이 비어 있지 않을 때만 상품 카탈로그를 읽고 `attachWbRndProductCandidates`를 실행한다. 안전 차단 성분이 추천 목록에 다시 들어오면 상품 검색 전에 502로 중단한다.

`wellnessbox/lib/product/product.catalog.ts`의 `getProductCandidateCatalog`는 재고가 있고 가격이 있는 `PharmacyProduct`만 읽도록 쿼리를 정의한다. `wellnessbox/lib/server/wb-rnd-product-candidates.ts`는 상품 상세 정보에서 성분 함량과 제형을 정규화하고, 서비스 성분별 후보를 붙인다. 일치 상품이 없으면 ID를 만들어 내지 않고 `NO_MATCH`로 남긴다. 조합을 만들 때는 같은 상품을 여러 추천에 중복 사용하지 않고, 상품별 성분 함량을 합산한다. 결과는 승인 전 장바구니 후보일 뿐이며 `approval_required=true`, `order_created=false`로 고정한다.

이 구분은 추천과 주문의 책임을 분리한다. R&D가 성분을 추천해도 서비스가 실제 재고·가격·함량을 확인해야 상품 후보가 된다. 후보가 준비돼도 사용자 승인과 기존 주문 생성 경로를 거치기 전에는 주문이나 결제 자료를 만들지 않는다.

## 실패한 실행과 다시 확인한 결과

서비스 QA를 처음 `tsx` 실행 파일로 직접 호출했을 때 `Error: This module cannot be imported from a Client Component module. It should only be used from a Server Component.` 오류가 났다. 제품 로직 실패가 아니라 `server-only` 모듈을 불러오는 Node 조건이 빠진 실행 오류였다. 저장소 `package.json`에 적힌 방식대로 `node --conditions=react-server --import tsx scripts/qa/check-rnd-product-candidates.cts`로 다시 실행했고, 코드 수정 없이 전체 검사가 통과했다.

현재 QA는 매핑 버전 `2026-07-24.1`의 서비스 성분 10개가 모두 상품 후보 계약에 포함되는지 확인했다. 매핑되지 않은 서비스 성분은 0개였다. 잘못된 카탈로그, 재고 0인 판매 옵션, 함량·제형 누락, 범위로 적힌 모호한 함량은 502로 차단됐다. 목표 성분의 함량이 없는 이름 일치 상품은 HTTP 200 응답 안에서 `NO_MATCH`가 됐다. 조합 탐색이 4,096상태 상한에 닿은 사례는 상위 조합을 반환하지 않았다. 시험 코드의 소스 검사에서도 승인 전 주문·결제·장바구니 저장 호출은 발견되지 않았다.

## 통합 증거의 범위와 남은 간격

기준 증거는 OP-050을 `INTEGRATED`로 기록한다. 실제 `/api/tips` 서비스 경로, 성분 계약, 상품 변환기가 한 호출 경계에서 연결됐고, 계약에 맞는 준비 상태 응답을 시험용 의존성 주입 경로로 넣어 상품 후보 변환을 확인했다. 별도 R&D HTTP 프로세스 호출도 관측됐지만 그 사례는 안전 차단 응답이었다. 기준 증거와 현재 서비스 QA에서 준비 상태 추천의 실제 두 프로세스 연속 변환은 `확인되지 않음`이다.

증거 파일을 만들 당시 상품 매핑은 버전 `2026-07-16.1`의 8개였고, 현재 계약과 재실행 결과는 `2026-07-24.1`의 10개다. 현재 QA는 통과했지만 기준 증거의 소스 식별 정보는 최신 계약을 반영하지 않는다. 이 차이는 확인됐으며 증거 파일 갱신은 이번 보고서 수정 범위가 아니다. 실제 Prisma 판매 카탈로그 조회, production 배포, 주문 생성, 사용자 승인은 조사한 파일과 시험에서 확인되지 않았다. 그러므로 `OPERATED`나 실제 판매 완료를 주장하지 않는다.
