# OP-050 추천 결과를 실제 서비스 성분과 상품 후보로 변환한다

## 결론과 통합 범위

OP-050은 연구 추천의 성분 키를 WellnessBox 서비스 성분 ID로 바꾸고, 실제 상품 카탈로그에서 재고·가격·성분 함량을 확인해 구매 전 상품 후보를 반환하도록 요구한다. 현재 `POST /api/tips` 경로는 R&D 추천 응답을 받은 뒤 서비스 매핑 계약과 Prisma 상품 조회 결과를 사용해 후보를 붙인다. 매핑되지 않거나 카탈로그가 불완전하면 상품 ID를 추측하지 않고 빈 후보 또는 502 오류로 닫힌다.

이전 경계에서는 `magnesium_glycinate` 같은 연구 식별자가 서비스의 `ING:MAGNESIUM`이나 상품 ID와 자동으로 같다고 볼 수 없었다. 이름만 비슷한 상품을 연결하면 목표 성분의 실제 함량이 없거나 재고가 없는 상품이 추천될 수 있다. 현재 변환기는 식별자 매핑, 상품명·분류, 목표 성분의 정량 함량, 판매 옵션의 가격과 재고를 각각 확인한다. 주문이나 장바구니 쓰기는 수행하지 않고 승인 전 후보만 만든다.

매니페스트에 등록된 서비스 경로 `wellnessbox/lib/server/wb-rnd-product-candidates.ts`를 포함해 구현 5개, 서비스 QA, 연구 측 재생 테스트·스모크·JSON 증거, 통합 경로 3개를 모두 실제 `C:\dev\wellnessbox`와 `C:\dev\wellnessbox-rnd`에서 확인했다. 모든 파일은 존재한다. 다만 등록 JSON 영수증의 서비스 소스 시점과 현재 서비스 계약 사이에는 아래에 설명한 차이가 있다.

## R&D 응답이 상품 후보가 되는 과정

`wellnessbox/contracts/wb-rnd/ingredient-identifier-map-v1.json`은 연구 성분 키와 서비스 성분 ID의 방향·관계를 고정한다. 현재 계약은 매핑 10개와 별도의 미매핑 항목을 명시한다. `wellnessbox/contracts/wb-rnd/product-candidate-match-v1.json`은 버전 `2026-07-24.1`이며 서비스 성분 10개를 상품 검색 규칙에 연결한다. 카테고리·표시 이름·목표 성분명이 모두 계약에 들어 있어 단순 부분 문자열 검색을 피한다.

`wellnessbox/lib/product/product.catalog.ts`의 `getProductCandidateCatalog`는 Prisma에서 판매 중인 상품과 상세 성분 사실, 재고가 0보다 크고 가격이 있는 약국 상품 옵션만 읽는다. `wellnessbox/lib/server/wb-rnd-product-candidates.ts`의 `loadContract`와 `validateCatalog`는 계약·카탈로그의 중복과 필수 필드를 검사한다. `parseIngredientAmount`는 g·mg·mcg를 정수 나노그램으로, IU를 milli-IU로 정규화하며 범위나 모호한 일일 용량 표기는 거부한다. `candidatesForIngredient`는 이름·카테고리 일치에 더해 목표 성분의 정량 함량이 있어야 후보로 인정한다.

현재 파일에는 OP-067 이후의 상품 조합 기능도 함께 있다. `buildProductCombinations`는 같은 상품 중복을 제거하고 탐색 상태를 4,096개로 제한한다. `rankProductCombinations`는 총비용, 상품 수, 조합 ID 순으로 순위를 고정하고 최대 3개를 반환한다. `buildStockSubstitution`과 `buildCartCandidate`는 재고 변경 때 대체 조합을 만들고 승인 전 장바구니 후보 형식을 제공한다. 이 후속 기능은 OP-050의 성분·상품 변환을 소비하지만, 조합 최적화 자체를 OP-050의 원래 완료 근거로 확대해서는 안 된다.

`wellnessbox/lib/server/wb-rnd-interim-route.ts`의 `runUserInterimRecommendationRoute`는 사용자를 인증하고 연구 서비스에 가명 사용자 ID로 요청한다. 반환된 안전 결정의 권한을 다시 확인한 뒤 `listWbRndProductCatalog`와 `attachWbRndProductCandidates`를 호출한다. R&D가 차단 또는 빈 추천을 반환하면 상품 변환으로 안전 결정을 뒤집지 않는다. `wellnessbox/app/api/tips/route.ts`의 `POST`가 이 서비스 함수로 연결된다.

## QA가 검증한 정상·오류 경로

등록된 `wellnessbox/scripts/qa/check-rnd-product-candidates.cts`는 실제 `POST /api/tips` 핸들러를 테스트 전용 의존성 주입 경로로 호출한다. 현재 명령 `node --conditions=react-server --import tsx scripts/qa/check-rnd-product-candidates.cts`는 성공했고 31개 검사를 보고했다. 현재 계약 버전 `2026-07-24.1`, 매핑 10개, 미매핑 서비스 성분 0개, 상품 조합 4개, 주문 생성 `false`를 확인했다. L-테아닌과 차전자피는 스냅숏에 합성 상품 ID 9001·9002를 추가한 QA 픽스처로 검사하므로 운영 상품 존재 증거는 아니다.

오류 검사는 매핑되지 않은 식별자, 잘못된 카탈로그·판매 옵션·성분 사실, 모호한 함량, 목표 성분 함량 부재를 다룬다. 잘못된 카탈로그와 모호한 함량은 502로 닫히고, 이름은 맞지만 목표 성분 함량이 없는 상품은 후보가 되지 않는다. 같은 입력의 반복 실행과 카탈로그 행 순서 변경에도 순위와 재생 해시가 같은지 확인한다. 안전 제외 성분이 상품 조합에 다시 들어오면 502로 거부하며, 예산·상품 수 제한과 재고 대체 뒤에도 기존 안전 제약을 유지한다. 소스 검사와 실행 결과 모두 장바구니 저장·주문·결제 생성이 없음을 확인한다.

`wellnessbox/contracts/wb-rnd/product-candidate-catalog-snapshot-v1.json`은 2026-07-17에 캡처한 7개 상품의 비운영 스냅숏이다. 현재 DB 재고를 증명하지 않으며 `production_operation_proven=false` 성격의 시험 자료다. 연구 저장소의 `wellnessbox-rnd/tests/test_recommendation_replay_product_candidates.py`는 연구 성분 계약과 서비스 매핑 범위가 맞는지 확인하고, 이번 집중 테스트 74개가 통과했다.

## JSON 영수증과 현재 코드의 시점 차이

등록 증거 `wellnessbox-rnd/data/original_plan/evidence/op049_op050_replay_product_candidates_smoke_v1.json`은 OP-050을 `INTEGRATED`로 기록하고 실제 R&D HTTP 차단 응답과 서비스 테스트 경로의 상품 변환을 함께 보존한다. 차단 사례는 `SAFE-EMERGENCY-001`, `STOP_AND_ESCALATE`, 추천 0개였고, 잘못된 계약과 미매핑 식별자는 502로 닫혔다. 이 내용은 경계 동작과 일치한다.

그러나 영수증의 서비스 소스 커밋은 `4d904f43b028a35524a29206aaf7c6b99f58a97b`이며 매핑 버전 `2026-07-16.1`, 매핑 8개를 기록한다. 현재 서비스 HEAD는 `f545b83f1da4aff12f0b1b1d6785feaf49aeaa5f`이고 매핑 버전은 `2026-07-24.1`, 매핑은 10개다. 해당 커밋 이후 매핑 계약, 중간 경로, QA 스크립트가 바뀌었다. 따라서 기존 JSON의 서비스 소스 SHA-256을 현재 파일의 해시라고 주장할 수 없다. 현재 QA를 별도로 실행해 10개 매핑 경로가 통과함을 확인했지만, 정식 JSON 영수증은 아직 현재 서비스 커밋으로 다시 생성되지 않았다.

## 현재 단계와 검증하지 않은 사항

OP-050의 단계는 매니페스트와 같은 `INTEGRATED`로 유지한다. 이유는 실제 서비스 API 경로가 연구 응답, 식별자 계약, Prisma 카탈로그 조회, 상품 후보 첨부를 연결하고 서비스 저장소의 등록 QA가 현재 코드에서 통과하기 때문이다. 이 단계는 서로 다른 저장소의 구성요소가 연결되었다는 뜻이며, 운영 사용을 뜻하지 않는다.

실제 운영 DB의 최신 재고·가격으로 두 프로세스 간 정상 추천을 끝까지 호출한 증거는 없다. JSON 영수증도 `ready_two_process_product_conversion_proven=false`와 `production_operation_proven=false`를 명시한다. 테스트 전용 주입 경로의 성공, 오래된 카탈로그 스냅숏, 합성 상품 두 개는 생산 판매 증거가 아니다. 현재 서비스 커밋으로 영수증을 재생성하고 실제 인증·네트워크·Prisma 환경에서 비파괴 통합 관측을 남기기 전에는 `OPERATED`로 올릴 수 없다.
## 추천 후보를 점수로 바꿀 때
추천 후보를 잘 고르는 일과 특정 후보를 복용했을 때의 효과를 추정하는 일은 다르다. 이 그룹은 입력 신호가 어떤 점수로 바뀌는지, 안전 차단 전후의 후보가 어떻게 보존되는지, 불확실성을 어디에 표시하는지를 분리해 설명한다.

`OP-050`는 “추천 결과를 실제 서비스 성분과 상품 후보로 변환한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=18`, `docs/context/original_plan.pdf#page=19`
- 구현·설계: `wellnessbox/contracts/wb-rnd/product-candidate-match-v1.json`, `wellnessbox/contracts/wb-rnd/product-candidate-catalog-snapshot-v1.json`, `wellnessbox/lib/product/product.catalog.ts`, `wellnessbox/lib/server/wb-rnd-product-candidates.ts` 외 1개
- 테스트·실행: `wellnessbox/scripts/qa/check-rnd-product-candidates.cts`, `wellnessbox-rnd/tests/test_recommendation_replay_product_candidates.py`, `wellnessbox-rnd/scripts/run_learned_replay_product_candidates_smoke.py`, `wellnessbox-rnd/data/original_plan/evidence/op049_op050_replay_product_candidates_smoke_v1.json`
- 통합 증거: `wellnessbox/app/api/tips/route.ts`, `wellnessbox/contracts/wb-rnd/ingredient-identifier-map-v1.json`, `wellnessbox/contracts/wb-rnd/product-candidate-match-v1.json`, `wellnessbox-rnd/data/original_plan/evidence/op049_op050_replay_product_candidates_smoke_v1.json`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `INTEGRATED`, 현재 주장 단계를 `INTEGRATED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
