# OP-107 — 관리자 화면의 실제 R&D 상태 조회

관리자 라우트는 세션 인증 뒤 R&D의 상태, KPI, 출처 API를 실제 HTTP로 조회한다. canonical QA는 인증 실패가 R&D에 도달하지 않는지 확인하고, 별도 FastAPI 프로세스에서 상태 카운트 14종, 출처 9건, 어댑터 8건을 받았다. 데이터가 없는 KPI API는 현재 계산 불가 상태를 반환하므로 관리자 전체 화면을 502로 만들지 않고 `UNAVAILABLE`로 명시한다. 이 상태를 성공 값으로 꾸미지 않는다.

초기 병렬 조회는 SQLite 초기화 경쟁으로 `database is locked`를 만들었다. 단일 컴퓨터 전제에 맞게 상태, KPI, 출처를 순차 조회하도록 고쳤다. 요구 단계는 `OPERATED`지만 증거는 로컬 두 프로세스 `INTEGRATED`다. 공개 관리자 화면과 운영 트래픽은 증명하지 않았다.

관리자 화면은 서비스 API만 호출하며 내부 토큰은 브라우저로 전달하지 않는다. 실제 운영 완료에는 배포된 R&D, 관리자 세션, 지속 DB, 브라우저 렌더링을 추가로 확인해야 한다.
