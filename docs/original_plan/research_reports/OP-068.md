# OP-068 같은 입력과 카탈로그 버전에서 같은 최적 조합을 재현한다.

재현성의 기준은 등록 증거 `wellnessbox-rnd/data/original_plan/evidence/op067_op068_product_combination_top_k_smoke_v1.json`에 고정돼 있다. 이 파일은 입력 지문, 카탈로그 버전, 순위 결과 지문을 한 묶음으로 기록한다.

## 무엇이 같아야 같은 실험인가

추천 결과를 다시 만들려면 사용자 추천 입력만 같아서는 부족하다. 같은 성분을 추천받아도 상품 가격, 재고, 성분 표기가 달라지면 최적 조합은 달라질 수 있다. OP-068은 추천과 제약 조건이 같은지 나타내는 입력 지문과, 상품 카탈로그 내용이 같은지 나타내는 버전을 모두 비교 기준으로 삼는다. 두 값이 같은 경우에만 결과 재현을 요구한다.

입력 지문에는 성분 식별자, 추천 순위와 점수, 근거 식별자, 최대 비용과 상품 수, 제외 성분, 안전 규칙이 들어간다. 카탈로그 버전에는 상품 식별자, 이름, 성분 선언, 정규화된 함량, 제형, 가격·재고가 포함된다. `src/wellnessbox_rnd/optimizer/product_combinations.py`는 이 자료를 정해진 필드 순서로 JSON 문자열로 만든 뒤 SHA-256 지문을 계산한다. 카탈로그 버전은 `catalog_` 뒤에 64자리 지문을 붙인 형태다.

결과 지문은 입력 지문과 카탈로그 버전, 상위 조합, 비선택 사유를 함께 묶는다. 따라서 입력과 카탈로그가 같아도 순위나 사유가 달라지면 다른 결과로 드러난다. 각 조합의 식별자도 선택 상품과 약국 상품 식별자를 정렬해 만든 16자리 지문에서 나온다. 실행 때마다 임의 번호를 새로 붙이지 않으므로 같은 상품 묶음은 같은 조합 식별자를 갖는다.

## 순서 차이가 결과를 바꾸지 않게 한 선택

순위 함수는 조건을 통과한 조합을 총비용, 상품 수, 조합 식별자 순으로 정렬한다. 비용과 상품 수가 같은 경우에도 마지막 기준이 남아 있으므로 입력 배열의 우연한 순서에 의존하지 않는다. 카탈로그 행 순서의 정리는 서비스 상품 변환 경계에서 수행되고, R&D는 서비스가 보낸 정규화된 `catalog_identity`를 지문 계산에 사용한다. 이 역할 분리는 서비스 상품 자료를 R&D가 다시 크롤링하거나 별도 카탈로그로 복제하지 않게 한다.

다만 R&D의 `_canonical_sha256()` 함수 자체는 전달된 배열을 다시 정렬하지 않는다. 따라서 서비스 정규화 규칙을 거치지 않은 임의 호출자가 카탈로그 행 순서를 바꾸면 같은 버전을 보장한다고 넓혀 말할 수 없다. 이번 통합 증거는 서비스 함수가 행 순서를 바꾼 시험 자료도 같은 정규화 결과로 만들어 R&D 경계에 전달했다는 범위다.

## 재실행과 변조 시험 결과

기준 실행의 입력 지문은 `709f6bd9adb7b584624e3f672e4f6d3cc39de6953bdcc841299a2f0afd3bc768`이다. 카탈로그 버전은 `catalog_1a7aefae72413f07ca27d119ebd04cccdcf2f5e800ef5fd0b210f486da6794a6`, 결과 지문은 `2413b3afd3ab40f4cba41f03f1914895a3103bf0842693f244155b2bd81baf1d`로 남았다. 네 조합에서 뽑은 상위 세 건과 나머지 한 건의 사유가 반복 실행에서 같았다.

`wellnessbox-rnd/tests/test_product_combinations.py`는 같은 함수 호출 두 번의 객체와 결과 지문이 같은지 비교한다. 이어서 결과 지문을 0으로 바꾸거나 추천 점수와 카탈로그 상품명을 바꿔 재검증한다. 모델은 모두 거부한다. 등록된 생성 스크립트는 같은 자료의 반복 실행뿐 아니라 카탈로그 원본 행 순서를 바꾼 서비스 결과도 비교한다. 구현 중 발생한 과거 재현 실패와 수정 커밋의 순서는 등록 자료에서 확인되지 않았다. 이번 보고서는 현재 코드가 다루는 변조·순서 변경 실패만 설명한다.

## 현재 단계와 재현성의 한계

서비스 상품 함수의 출력과 R&D의 독립 계산이 일치하고, 서비스 입력 행 순서 변경도 같은 결과를 만들었으므로 OP-068의 현재 단계는 `INTEGRATED`다. manifest에 등록된 서비스 파일은 저장소 경계 밖이라 직접 읽지 않았으며, 기준 증거가 고정한 서비스 커밋 `4d904f43b028a35524a29206aaf7c6b99f58a97b`와 소스 목록을 근거로 연결 범위를 확인했다.

실제 운영 환경의 재현성은 확인되지 않았다. 증거 파일은 실제 Prisma 조회, 준비 상태의 R&D HTTP 경로, 운영 카탈로그 최신성, 공개 배포를 모두 미확인으로 둔다. 현재 주장은 고정된 입력과 고정된 서비스 카탈로그 내용에서 함수 연결 결과를 다시 만들 수 있다는 뜻이며, 실시간 재고가 변하는 동안에도 결과가 같다는 뜻은 아니다.
