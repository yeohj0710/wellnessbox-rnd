# OP-120 독립 최종 감사가 100% 완료를 증명한 뒤 전체 목표를 완료 처리한다.

## 요구사항과 실제 결과

OP-120은 최종 감사가 OP-001부터 OP-120까지의 요구사항 수, 연구보고서 수, 단계 공백, 외부 검증 입력, 최종 영수증을 직접 확인한 뒤에만 전체 목표를 완료하도록 요구한다. 수정 완료 패키지를 반영한 현재 최종 감사는 `status=READY`, `goal_complete=true`, `blockers=[]`를 반환한다. 감사 결과는 요구사항 120개, 연구보고서 120개, 누락 보고서 0개, 단계 공백 0개, 유효한 검증 영수증과 독립 검토 영수증을 기록한다.

## 해결한 문제와 재사용한 경로

기존 manifest 감사기는 요구사항 120개, 증거 파일, 원문 해시와 Git 추적 여부를 검사하지만 연구보고서 120개, 요구 단계 충족, 외부 검증, 최종 검증 영수증과 독립 검토 영수증을 하나의 완료 판정으로 묶지 않았다. 새 감사기는 기존 `original_plan_audit.py`와 manifest schema를 그대로 호출한다. 별도의 요구사항 목록이나 증거 체계를 만들지 않아 기존 감사 결과와 OP-120 판정이 갈라지는 문제를 막았다.

## 입력과 처리 계약

감사기는 기준 manifest, 두 저장소의 루트, 연구보고서 디렉터리와 정책 파일을 입력으로 받는다. 비외부 요구사항은 `IMPLEMENTED < INTEGRATED < OPERATED` 순서로 요구 단계와 주장 단계를 비교한다. `EXTERNAL` 요구사항은 같은 순서에 섞지 않고 실제 `EXTERNAL` 주장만 인정한다. 연구보고서는 정확한 `OP-NNN.md` 파일명, 최소 분량과 절 구조, 요구·검증·증거·완료 경계의 의미 범주, manifest 증거 경로 인용을 검사한다. 최종 검증 영수증과 독립 검토 영수증은 Git 추적, manifest 및 기준 감사 지문, 소스 커밋, 허용된 Ed25519 서명과 통과 상태가 모두 맞을 때만 인정한다.

## 실패 처리와 안전 경계

요구사항 수나 주장 수가 120이 아니거나, 요구 단계가 부족하거나, 외부 검증이 없거나, 보고서가 빠지거나, canonical evidence 감사가 실패하거나, 두 최종 영수증 중 하나가 없으면 감사기는 완료를 거부한다. 읽을 수 없거나 형식이 잘못된 영수증도 통과로 추정하지 않는다. 현재 정책은 영수증 경로를 `null`로 유지하므로 허위 완료 증거를 만들지 않는다.

## 검증 범위와 canonical evidence

고정 데이터셋은 요구사항 재고, 주장 재고, 비외부 단계 부족, 외부 검증, 보고서 수, 기준 증거, 최종 영수증, 완료 결정의 8개 사례를 검사한다. 현재 감사 증거의 관측값은 요구사항 120개, 주장 120개, 비외부 단계 부족 0개, 외부 검증 공백 0개, 유효 보고서 120개와 누락 0개, 검증 영수증 2건 유효, 최종 상태 `READY`다. OP-039 검토자 프로필은 별도 보고서에서 예비 약사 사전 검토로 구분하며, 이 감사 결과가 검토자에게 약사 자격이나 독립 외부기관 지위를 부여하지는 않는다.

## 서비스 통합·운영·외부 검증 상태

OP-120 감사기와 최종 세션 콘솔은 R&D 저장소에서 실행할 수 있다. 서비스 저장소와 연결된 기존 증거는 기준 감사가 재검사한다. 현재 감사 증거는 비외부 단계 공백과 외부 검증 공백을 0건으로 기록하고 OP-120의 완료 조건을 통과한다. 다만 KPI-2는 3차년도 운영 사용자 100명 수집·측정 대상이고, H-003 학습 게이트는 `NO-GO`로 유지한다. OP-120의 `READY`는 2차년도 연구보고서 제출 패키지와 감사 조건을 충족했다는 뜻이지, 2차년도에 연구 전체를 완주했거나 KPI-2를 앞당겨 확정했다는 뜻이 아니다.

## 현재 한계와 완료 조건

최종 감사가 유지해야 할 조건은 연구보고서 120개, 영수증의 manifest·canonical audit·source commit 바인딩, 두 발급자의 ID·공개키 분리, KPI 정답지 무결성, H-003 `NO-GO`, 여형준의 H-005 자기검토 차단이다. 이 조건을 다시 확인할 때도 사람 기록·판정·서명을 자동 생성하지 않는다. 3차년도 약사 재검토와 KPI-2 운영 사용자 수집은 별도 연구 일정으로 남긴다.

## 관련 구현과 검증 자산

핵심 구현은 `wellnessbox-rnd/src/wellnessbox_rnd/governance/final_completion_audit.py`와 `wellnessbox-rnd/src/wellnessbox_rnd/governance/final_session_console.py`다. 회귀 테스트는 `wellnessbox-rnd/tests/test_final_session_console.py`, 단일 실행기는 `wellnessbox-rnd/scripts/run_final_session_console.py`에 있다. 리허설 증거 `wellnessbox-rnd/data/original_plan/evidence/final_session_console_rehearsal_v1.json`은 H-001~H-007을 임시 자료로 처리한 뒤 `READY`에 도달했고 실제 원장·영수증 경로를 바꾸지 않았음을 기록한다.
## 운영 증거와 종료 판단을 나눈 이유
운영 증거는 구현 파일을 나열하는 데서 끝나지 않는다. 보안, 장애 복구, 계약 일치, 배포 health, 브라우저 경로, 운영 증거, 외부 의존성과 최종 감사가 각각 어떤 주장을 지지하는지 단계별로 나눈다.

`OP-120`는 “독립 최종 감사가 100% 완료를 증명한 뒤 전체 목표를 완료 처리한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=15-26`
- 구현·설계: `wellnessbox-rnd/src/wellnessbox_rnd/governance/final_completion_audit.py`, `wellnessbox-rnd/src/wellnessbox_rnd/governance/final_session_console.py`, `wellnessbox-rnd/scripts/run_final_session_console.py`, `wellnessbox-rnd/data/original_plan/op120_final_audit_policy_v1.json`
- 테스트·실행: `wellnessbox-rnd/tests/test_final_completion_audit.py`, `wellnessbox-rnd/tests/test_final_session_console.py`, `wellnessbox-rnd/scripts/run_final_completion_audit.py`, `wellnessbox-rnd/scripts/run_final_session_console_smoke.py` 외 2개
- 통합 증거: `wellnessbox-rnd/data/original_plan/final_session/operational_evidence/OP-120.json`
- 운영 증거: `wellnessbox-rnd/data/original_plan/final_session/operational_evidence/OP-120.json`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `OPERATED`, 현재 주장 단계를 `OPERATED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
