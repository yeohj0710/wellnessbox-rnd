# OP-038 규칙 버전과 적용 시각을 안전 판정 응답에 포함한다.

## 요구사항과 감사 문제

안전 판정이 차단이나 경고를 반환해도 어떤 규칙을 언제 적용했는지 남지 않으면 나중에 같은 결과를 설명하기 어렵다. 규칙 내용이 바뀐 뒤에는 현재 규칙만 보고 과거 판정을 재구성할 수도 없다. 이 요구사항은 안전 응답에 규칙 식별자뿐 아니라 규칙 버전과 적용 시각을 함께 넣어 판정 당시의 기준을 추적할 수 있게 하는 작업이다. 확인한 모델은 `SafetyRuleMetadata.version`과 `RuleReference.rule_version`을 1 이상의 정수로 제한하고, `SafetySummary.applied_at`에는 시간대가 있는 시각만 허용한다. 따라서 버전이 없거나 지역 시간인지 알 수 없는 시각은 정상 안전 응답으로 통과하지 않는다.

## 규칙 버전과 적용 시각을 전달하는 방식

`wellnessbox-rnd/src/wellnessbox_rnd/safety/service.py`의 안전 판정 함수는 호출자가 적용 시각을 주면 그 값을 사용하고, 주지 않으면 현재 UTC 시각을 만든다. 시간대 정보가 없는 시각은 거부하고, 시간대가 있는 시각은 UTC로 변환한다. 상호작용·금기·용량 규칙이 발동하면 원본 규칙 메타데이터의 버전을 각 `RuleReference`에 복사한다. 응답 소비자는 차단 근거마다 규칙 ID와 버전을 읽고, 전체 판정에 기록된 적용 시각과 결합해 당시 판단을 식별할 수 있다.

현재 런타임 지식 데이터베이스에는 버전이 붙은 안전 규칙 13개가 있다. 구성은 상호작용 2개, 금기 6개, 용량 5개이며 확인 시점의 버전은 모두 1이다. 규칙 파일과 런타임 데이터베이스가 별도 파일이어도 서비스가 메타데이터를 같은 응답 계약으로 내보내므로 호출 경로마다 감사 정보 형식이 달라지지 않는다. 응답 스키마는 `wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation.py`에 있고, 도메인 모델은 `wellnessbox-rnd/src/wellnessbox_rnd/domain/models.py`에 있어 저장 계층과 API 계층이 같은 제약을 사용한다.

## 재현성과 동적 시각을 함께 다룬 선택

적용 시각은 감사에는 필요하지만 세션 재현 결과를 비교할 때마다 달라지는 값이다. `wellnessbox-rnd/src/wellnessbox_rnd/interim/data_lake.py`는 안정적인 응답 비교 값을 만들 때 `applied_at`을 제외한다. 이 선택은 적용 시각을 응답에서 없애는 것이 아니다. 실제 응답에는 시각을 남기되, 동일 입력과 동일 규칙 버전의 판정 내용이 같은지 비교하는 해시에서는 동적 시각만 제거한다. 그 결과 감사 기록은 언제 판정했는지 보존하고, 재현 검사는 시간 차이 때문에 거짓 불일치를 만들지 않는다.

## 실패 경계를 포함한 검증

API 시험은 반환된 `applied_at`을 다시 파싱해 시간대가 존재하는지 확인하고, 모든 발동 규칙의 버전이 1 이상인지 검사한다. 학습 모델 경계 시험은 안전 판정이 결정론적 규칙에 남아 있고 적용 시각 주입이 선택 사항인지 확인한다. 용량 제한 스모크 시험은 고정 시각 `2026-07-16T00:00:00+00:00`을 넣어 여섯 용량 사례를 실행하고, 13개 안전 규칙의 최소 버전이 1임을 기록했다. 기준 증거는 `wellnessbox-rnd/data/original_plan/evidence/op037_op038_dose_limit_rule_metadata_smoke_v1.json`이다.

검증은 불완전한 복용량, 뜻이 모호한 단위, 잘못된 단위를 정상 수치로 억지 변환하지 않는 경계도 함께 지나간다. 이 경우 시스템은 보수적으로 후보를 제외하거나 입력을 거부한다. OP-038의 핵심은 용량 판정 자체보다, 어떤 안전 규칙이 실제로 적용됐는지 버전과 시각을 잃지 않고 반환하는 데 있다.

## 완료 단계와 남은 한계

현재 근거로 확인되는 단계는 **IMPLEMENTED**다. 모델, 스키마, 안전 서비스, 런타임 데이터와 자동 시험이 연결되어 있고 고정 입력 스모크 증거도 있다. 그러나 이 자료는 운영 환경에서 장기간 축적한 감사 로그나 외부 검토 결과를 증명하지 않는다. 규칙이 버전 2 이상으로 변경될 때 과거 버전을 계속 조회할 수 있는 보존 정책과 실제 운영 응답의 지속적인 감사 수집도 별도 확인이 필요하다. 따라서 구현 완료를 운영 완료나 임상적 안전성 입증으로 확대 해석하면 안 된다.
