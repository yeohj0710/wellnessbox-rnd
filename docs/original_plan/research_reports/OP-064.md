# OP-064 제품 간 중복 성분과 합산 용량을 계산한다.

제품 조합의 중복 성분과 합산 함량은 `wellnessbox-rnd/src/wellnessbox_rnd/optimizer/product_combinations.py`에서 검증한다. 서비스는 `wellnessbox/lib/server/wb-rnd-product-candidates.ts`에서 같은 규칙으로 조합을 만든다. 등록 증거 `wellnessbox-rnd/data/original_plan/evidence/op063_op064_product_combination_dose_smoke_v1.json`은 두 구현의 결과를 함께 기록한다. 매니페스트의 현재 단계는 `INTEGRATED`다. 다만 여기서 합산하는 값은 판매 제품에 선언된 함량이지, 사용자의 실제 일일 복용량은 아니다.

## 기존 구현은 제품 수와 성분 함량을 혼동할 수 있었다

OP-063에서 한 조합에 같은 제품을 두 번 넣지 않는 규칙을 추가했어도, 서로 다른 제품이 같은 성분을 포함하면 중복 섭취 가능성이 남는다. 반대로 복합 제품 하나에 같은 성분을 설명하는 원료 행이 여러 개 있어도 제품 하나를 여러 번 복용한 것으로 세면 안 된다. 제품 ID 중복 제거와 성분별 합산을 따로 처리해야 하는 이유다.

첫 구현 커밋 `879dc78 feat: validate product combination doses`는 제품 조합에서 중복 성분과 함량을 검증하는 경계를 만들었다. 이후 `78fad48 fix: validate bounded exact product doses`가 단위와 필드 이름을 바로잡았다. 초기 구현은 mcg와 IU를 충분히 작은 정수 단위로 바꾸지 않았고, 합산값을 `total_daily_amount`라고 불러 실제 일일 복용량처럼 읽힐 여지가 있었다. 수정 후 질량은 나노그램(`ng`), IU는 천분의 1 IU(`milli_IU`)로 정규화하고 필드 이름을 `total_declared_amount`로 바꿨다.

## 서비스는 제품을 먼저 고유하게 만든 뒤 성분을 합산한다

`wb-rnd-product-candidates.ts`의 `materializeCombination`은 선택한 제품을 제품 ID 기준으로 한 번만 남긴다. 이어 각 제품의 선언 성분을 `(ingredient_id, canonical_unit)`별로 합산하고, 각 성분에 기여한 제품 ID도 함께 저장한다. 질량과 IU는 서로 변환할 근거가 없으므로 별도 합계로 유지한다.

중복 판정은 성분 행의 개수가 아니라 서로 다른 제품 ID의 개수를 사용한다. 같은 제품에서 성분 행이 반복돼도 중복 성분으로 올리지 않는다. 반대로 한 성분이 질량 단위와 IU 단위로 나뉘어 있어도 두 개 이상의 제품 ID가 기여했다면 `duplicate_ingredient_ids`에 성분 ID를 한 번만 넣는다. 이 방식은 중복 여부와 단위별 합계를 분리한다.

Python의 `ProductCombinationV1` 검증기는 서비스가 보낸 `product_count`, `total_cost_krw`, `ingredient_totals`, `duplicate_ingredient_ids`, 조합 ID를 신뢰하지 않는다. `evaluate_product_combination_v1`이 선택 제품에서 값을 다시 계산하고 저장값과 비교한다. 조작된 합계나 제품 ID를 포함한 결과는 모델 생성 단계에서 거부된다.

## 회귀 테스트는 합계 조작과 단위 혼합을 막는다

`wellnessbox-rnd/tests/test_product_combinations.py`의 `test_combination_validates_duplicate_and_total_dose`는 10 mg과 15 mg의 같은 성분을 25,000,000 ng로 합산하고 중복 성분으로 판정하는지 확인한다. 같은 테스트는 합계를 26,000,000 ng로 바꾸거나 기여 제품 ID를 하나 지운 결과가 검증에 실패한다고 단언한다. 조합 ID, 제품 수, 총비용을 조작한 경우도 별도 단언으로 거부한다.

`test_mass_and_iu_totals_remain_separate`는 한 성분의 질량과 IU 합계를 서로 다른 항목으로 유지한다. `test_duplicate_identity_spans_separate_mass_and_iu_totals`는 단위가 달라도 서로 다른 제품이 같은 성분에 기여하면 중복 ID가 하나만 생긴다고 확인한다. `wellnessbox-rnd/scripts/run_product_combination_dose_smoke.py`는 서비스가 만든 조합을 Python 계약으로 다시 검증한다.

등록 증거의 중복 사례에는 아연을 포함한 제품 29와 제품 42가 들어 있다. 선언 함량 103 mg과 150 mg은 253,000,000 ng, 즉 253 mg로 합산됐고 `duplicate_ingredient_ids`에는 `ING:ZINC`가 한 번 기록됐다. 다른 사례는 복합 제품 하나에서 여러 성분을 제공하지만 제품 ID가 하나이므로 중복 목록이 비어 있다.

현재 서비스 QA에서는 12.5 mcg를 12,500 ng로 바꾸는 정수 변환도 확인한다. 또한 목표 성분에 이름이나 범주만 맞고 선언 함량이 없는 제품은 조합 후보로 인정하지 않는다. 이는 등록 증거가 생성된 뒤 서비스 커밋 `cee66e7 fix: bound and normalize product combinations`에서 강화된 조건이다.

## `INTEGRATED`는 서비스 경로 연결을 뜻하며 실제 복용량을 증명하지 않는다

집중 검증에서 `wellnessbox-rnd/tests/test_product_combinations.py`를 포함한 지정 Python 테스트 96개와 `wellnessbox/scripts/qa/check-rnd-product-candidates.cts`가 통과했다. 서비스 QA는 고정 카탈로그를 사용했으며 실제 Prisma 조회는 실행하지 않았다. 등록 증거도 `actual_prisma_query_executed=false`, `production_operation_proven=false`로 기록한다.

등록 증거의 결합 지문 `ff1cda3ce8b5684628a776ea05741316b27748ab2212c800490d04a81072a412`은 현재 관련 파일에서 다시 계산한 `c72cec8feba9a237f0ab968620d74a76adcecc3f777e492e96d1bcbb8446466f`과 다르다. 따라서 등록 JSON은 당시 회귀 근거로는 유효하지만 현재 파일과 동일한 실행 산출물은 아니다.

매니페스트의 `INTEGRATED` 판정은 서비스의 제품 조합 생성 결과를 R&D 계약이 재검증하는 경로까지 확인했다는 뜻이다. 제품 라벨의 선언 함량이 1회 제공량인지 1일 제공량인지, 사용자가 실제로 몇 회 복용하는지, 운영 DB의 최신 제품 정보가 같은 계산을 통과하는지는 현재 근거에서 확인되지 않는다. 실제 섭취량 또는 안전 상한 비교로 해석하려면 복용 빈도와 라벨 기준량을 별도 계약으로 받아야 한다.
