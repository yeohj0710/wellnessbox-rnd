# OP-064 제품 간 중복 성분과 합산 용량을 계산한다.

중복과 합계의 기준 구현은 `wellnessbox-rnd/src/wellnessbox_rnd/optimizer/product_combinations.py`에 있다. 서비스가 실제 계산 자료를 만드는 경로 `wellnessbox/lib/server/wb-rnd-product-candidates.ts`와 등록 증거 `wellnessbox-rnd/data/original_plan/evidence/op063_op064_product_combination_dose_smoke_v1.json`도 함께 확인했다. 현재 단계는 `INTEGRATED`다. 다만 계산 대상은 상품에 표시된 성분 함량이며, 개인이 실제 하루에 섭취한 양을 측정한 결과는 아니다.

## 상품 수만 세면 놓치는 안전 문제

복합 상품과 단일 성분 상품을 함께 고르면 같은 성분이 두 상품에서 겹칠 수 있다. 상품이 서로 다르다는 이유로 함량을 따로 보여 주면 사용자는 전체 노출량을 알 수 없다. 반대로 한 복합 상품이 여러 추천 성분을 담당하는 경우 같은 상품을 여러 번 더하면 비용과 함량이 모두 과대 계산된다. 따라서 먼저 상품을 고유 ID로 합치고, 그다음 성분별 표시 함량을 더해야 한다.

이 구현은 성분 식별자와 단위를 한 쌍으로 묶어 합계를 낸다. g, mg, mcg 계열은 정수 나노그램으로, IU는 천분의 IU인 `milli_IU`로 바꾼다. 질량과 IU는 서로 바꿀 근거가 없으므로 같은 표에 억지로 더하지 않는다. 다만 같은 성분이 단위가 다른 두 상품에 나타나도 중복 성분 표시는 하나로 남는다. 합계 숫자는 단위별로 따로 유지된다.

## 파생값을 원자료에서 다시 계산하는 이유

`ProductCombinationV1`은 저장된 `product_count`, `total_cost_krw`, `ingredient_totals`, `duplicate_ingredient_ids`를 그대로 믿지 않는다. 선택 상품의 판매가를 다시 더하고, 각 상품의 성분 함량을 순회해 합계를 만든 뒤, 보고된 값과 일치하는지 비교한다. 한 상품 안에 같은 성분 식별자가 두 번 들어오는 자료도 거부한다. 이 검사는 조합 생성기와 검증기가 같은 오류를 공유하지 않도록 서비스 TypeScript 결과를 Python에서 한 번 더 읽는 데 사용된다.

중복의 기준은 서로 다른 `product_id` 두 개 이상이다. 같은 상품이 여러 추천 성분 후보로 반복돼도 중복 성분으로 세지 않는다. 합계에는 어떤 상품 ID가 기여했는지도 남기므로, 수치가 커졌을 때 출처 상품을 찾을 수 있다. 범위 표기, 하루 복용량 표기, 여러 수치가 섞인 문자열은 하나의 확정 함량으로 간주하지 않고 서비스 단계에서 오류로 돌린다.

## 아연 합계와 변조 시험

기준 smoke의 중복 사례에는 아연이 상품 29와 상품 42에 들어 있었다. 표시 함량은 각각 103 mg와 150 mg였고 합계는 253,000,000 ng, 즉 253 mg로 계산됐다. 결과의 `duplicate_ingredient_ids`에는 `ING:ZINC` 하나가 남았다. 다른 검증 조합은 복합 상품 하나가 여러 성분을 맡았지만 같은 상품 ID를 한 번만 사용했으므로 중복 목록이 비어 있었다.

`wellnessbox-rnd/tests/test_product_combinations.py`는 10 mg와 15 mg 아연을 25,000,000 ng로 더하는 작은 사례도 검사한다. 합계를 26,000,000으로 바꾸거나 기여 상품 ID를 하나 지운 자료, 제품 수·총비용·조합 ID를 임의로 고친 자료는 모두 검증에 실패한다. 질량과 IU 합계를 분리하는 경우와, 서로 다른 단위를 쓰더라도 두 상품에 같은 성분이 있으면 중복으로 잡는 경우도 다룬다. 현재 Python 집중 시험과 서비스 상품 QA는 모두 성공했다.

## 통합 단계가 의미하지 않는 것

정본은 질량 단위 정규화, IU 분리, 서로 다른 상품 사이의 중복 판정, R&D 계약의 합계 재계산을 true로 기록한다. 하지만 실제 Prisma 조회, 운영 상품 정보의 최신성, 주문 생성은 모두 증명하지 않았다. 표시 함량이 1회분인지 1일분인지 상품 상세 자료가 명확히 주지 않으면 이 계산만으로 실제 일일 섭취량을 판단할 수 없다. 조사한 계약, 어댑터, 시험, 증거 파일에는 함량의 복용 단위를 확정할 운영 자료가 없어 `확인되지 않음`으로 남긴다.

기준 증거의 결합 지문과 현재 등록 파일들의 결합 지문도 일치하지 않았다. 최신 시험은 파생값 검증을 통과했지만 기준 smoke와 동일한 소스 실행은 아니다. 따라서 OP-064는 서비스 함수와 R&D 검증 경계를 통과한 `INTEGRATED`로 판단하되, 현재 운영 상품의 실제 복용 단위 합계까지 입증했다고 넓히지 않는다.
