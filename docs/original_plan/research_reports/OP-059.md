# OP-059 효과 악화 시 상태기계가 유지, 감량, 중단, 재최적화를 선택한다.

이 요구는 점수가 나빠졌다는 한 가지 사실을 곧바로 계획 변경으로 번역하지 말고, 복용 이행과 이상사례를 함께 따져 네 행동 중 하나를 고르라는 뜻이다. manifest가 지정한 중심 구현은 `wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_actions.py`다. 등록된 두 프로세스 smoke와 현재 단위·API 시험을 나눠 대조한 결과, 등록 시점의 단계는 `INTEGRATED`가 맞다. 다만 이 판정은 로컬 WellnessBox 서비스와 R&D API 사이의 전달을 입증할 뿐, 실제 사용자의 복용 계획을 운영에서 감량하거나 중단한 기록까지 뜻하지 않는다.

## 기존 후속 평가에는 명시적인 네 갈래 결정이 없었다

`8448cec` 이전의 `pro_plan_service.py`는 복용 전후 점수의 해석과 추천 이력을 반환했지만, 그 해석을 `maintain`, `reduce`, `stop`, `re_optimize` 중 하나로 고정하는 결과는 없었다. 이런 상태에서는 화면이나 후속 작업 코드가 같은 악화를 서로 다르게 해석할 수 있다. 특히 복용을 빠뜨려 점수 해석이 제한된 경우와, 심각한 이상사례가 생긴 경우를 같은 “악화”로 처리하면 각각 불필요한 계획 변경과 안전 대응 지연이 생긴다.

커밋 `8448cec`는 새 판정 모델 `PROPlanActionDecisionV1`과 함수 `decide_pro_plan_action_v1`을 추가하고, 신규 후속 기록과 정정 기록 모두에 `action_decision`을 붙였다. 이 변경은 기존 설문 점수 계산기를 교체하지 않았다. 이미 계산된 `observed_change_status`, `interpretation_status`, 이상사례 수, 심각성 표시를 입력으로 받아 다음 행동만 결정한다. 원인과 결과를 증명한 자료가 아니므로 `causal_effect_claim_allowed=True`인 해석은 아예 받지 않는다.

## `decide_pro_plan_action_v1`은 안전 우선순위를 코드로 고정한다

가장 먼저 보는 값은 `serious_adverse_event_present`다. 이 값이 참이면 점수와 복용률에 앞서 `stop`을 고르고, `NextAction.REDUCE_OR_STOP`과 `stop_or_escalate` 상태를 연결한다. 심각하지 않은 이상사례가 하나라도 있으면 `reduce`가 같은 안전 상태로 간다. 이상사례가 없고 점수가 악화됐을 때는 해석 가능성을 나눈다. 낮은 복용률이나 누락 복용 때문에 변화 해석이 제한되면 `maintain`, 그런 제한이 없으면 `re_optimize`다. 악화가 아닌 결과도 `maintain`으로 남는다.

이 함수가 만든 결과는 자기 검증도 한다. `PROPlanActionDecisionV1.validate_decision`은 저장된 행동, 다음 작업, 예상 상태, 이유 코드를 원래 해석에서 다시 계산한다. 예를 들어 해석 가능한 악화의 행동만 `maintain`으로 고친 자료는 `PRO action decision does not match source interpretation` 오류로 거부된다. `wellnessbox-rnd/src/wellnessbox_rnd/orchestration/pro_plan_service.py`의 `record_or_correct_pro_followup_v1`은 새 기록과 기존 시점 정정 모두에서 이 함수를 다시 호출하므로, 정정 뒤에도 이전 행동이 남지 않는다.

API 경계에서는 `wellnessbox-rnd/apps/inference_api/routes/interim.py`의 `record_pro_followup`이 심각한 이상사례를 먼저 `BoundedAgent.record_adverse_event`에 기록한다. 그 결과 기존 후속 작업이 취소되고 계획 중단 상태가 남는다. 심각하지 않은 일반 후속 결과는 `WorkflowJobQueue.enqueue_input_reevaluation`로 재평가 작업을 만든다. 서비스 클라이언트 `wellnessbox/lib/tips/pro-study-rnd-client.ts`는 `action_decision`이 빠진 응답을 오류로 처리하며, `wellnessbox/components/tips/ProStudySimulation.tsx`는 네 행동을 각각 유지·감량·중단·재최적화로 보여 준다. 즉 Python의 분기값이 응답 직렬화와 서비스 화면까지 전달된다.

## 기록된 smoke와 현재 시험은 서로 다른 시점을 보여 준다

등록 증거 `wellnessbox-rnd/data/original_plan/evidence/op059_op060_pro_action_real_outcome_smoke_v1.json`에는 실제 관찰 결과로 표시한 등록 4건과 후속 입력 4건이 있다. 14회 중 10회 복용한 악화는 `worsening_confounded_maintain`, 경미한 이상사례는 `adverse_event_reduce`, 심각한 이상사례는 `serious_adverse_event_stop`, 다른 제한이 없는 악화는 `interpretable_worsening_re_optimize`로 갈렸다. 네 사례 모두 `REAL_WORLD_OUTCOME` 표지를 보존했고, 저장 결과에는 원인 효과 주장을 허용하지 않는 값이 남았다. smoke는 localhost에서 R&D 서버를 띄우고 서비스의 `run-tips-pro-correction-client.cts`를 거쳐 요청했으므로 등록 시점의 서비스 결합 근거다.

현재 코드에서는 `python -m pytest tests/test_pro_actions.py tests/test_pro_plan_service.py tests/test_optimization_constraints.py tests/test_product_combinations.py tests/test_interim_api.py -q`를 실행했고 96개 시험이 통과했다. `test_pro_action_policy_selects_exact_closed_loop_action`은 심각 이상사례, 일반 이상사례, 낮은 복용률, 누락 복용, 해석 가능한 악화, 개선의 여섯 입력을 각각 기대 행동·다음 작업·상태·이유 코드와 대조한다. `test_pro_action_decision_rejects_derived_field_mutation`은 파생 행동 변조를 거부한다. `test_serious_pro_followup_stops_plan_and_cancels_prior_next_job`은 심각 이상사례 뒤 계획 중단과 기존 작업 `CANCELLED`를 확인한다. 서비스 시험 `check-tips-pro-study-rnd-client.cts`도 통과해 클라이언트가 다음 행동 결정을 요구하고 화면에 네 한국어 행동명이 있는지 확인했다.

커밋 이력에는 최초 구현 전 실패 로그가 남아 있지 않다. 따라서 “어떤 실패 시험이 `8448cec`를 촉발했다”는 설명은 확인되지 않았다. 대신 이후 시험이 실제로 막는 실패는 명확하다. 행동 필드만 바꾼 자료, 원인 효과를 허용한 해석, 심각 이상사례를 기록하면서 기존 재평가 작업을 유지하는 상태는 현재 계약을 통과하지 못한다.

## `INTEGRATED` 판정은 저장된 실행 시점에 한정된다

정본은 `op059_proven_stage=INTEGRATED`, `localhost_two_process_integration_proven=true`를 기록한다. 같은 파일에서 `production_data_used`, `production_operation_proven`, `production_deployment_proven`은 모두 false다. 또한 등록 JSON의 결합 지문 `cf54b2e62cc8a2ca15195d0c6cfc4ba2d2a34ca551f7ed4a49a462d2db64f6d3`은 현재 등록 소스에서 다시 계산한 `70159f73f8625b511b55dda31ae979a31aec0fc661def844a793fe80e7d035a8`과 다르다. 최신 집중 시험은 통과했지만 같은 두 프로세스 smoke를 다시 만들지는 않았으므로, 현재 소스 전체의 통합 재현은 확인되지 않았다.

아직 남은 범위도 분명하다. `reduce`와 `stop`은 상위 다음 행동에서 모두 `reduce_or_stop`으로 모이므로, 운영 작업자가 두 결과를 서로 다르게 집행하는 절차는 이 OP가 입증하지 않는다. 실제 사용자가 안내를 받고 복용량을 줄였는지, 중단했는지, 이후 안전 상태가 개선됐는지도 확인되지 않았다. 그러므로 이 보고서의 결론은 “네 행동 결정과 서비스 전달이 통합됐다”까지이며 `OPERATED`나 `EXTERNAL`로 올리지 않는다.
## 효과를 측정할 때 분리한 것
효과를 말하려면 예측값과 실제 복용 전후 관측값을 섞지 않아야 한다. 이 그룹은 PRO 원점수, 표준화, 개인별 변화, 집단 평균, 신뢰구간, 순응도와 이상사례를 각각 기록해 숫자가 무엇을 의미하는지 확인한다.

`OP-059`는 “효과 악화 시 상태기계가 유지, 감량, 중단, 재최적화를 선택한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=18`, `docs/context/original_plan.pdf#page=19`
- 구현·설계: `wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_actions.py`, `wellnessbox-rnd/src/wellnessbox_rnd/orchestration/pro_plan_service.py`, `wellnessbox/components/tips/ProStudySimulation.tsx`
- 테스트·실행: `wellnessbox-rnd/tests/test_pro_actions.py`, `wellnessbox-rnd/tests/test_pro_plan_service.py`, `wellnessbox-rnd/scripts/run_pro_worsening_action_real_outcome_smoke.py`, `wellnessbox-rnd/data/original_plan/evidence/op059_op060_pro_action_real_outcome_smoke_v1.json`
- 통합 증거: `wellnessbox/lib/tips/pro-study-rnd-client.ts`, `wellnessbox/components/tips/ProStudySimulation.tsx`, `wellnessbox-rnd/data/original_plan/evidence/op059_op060_pro_action_real_outcome_smoke_v1.json`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `INTEGRATED`, 현재 주장 단계를 `INTEGRATED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
