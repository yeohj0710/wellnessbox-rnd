# OP-014 복용 건강기능식품의 제품명, 성분, 1일 용량을 구조화한다.

## 제품 용량과 성분 용량을 섞으면 합산이 틀어진다

원본은 복용 약물과 함께 건강기능식품 입력을 개인 특성 데이터로 모은다. 제품명만 있으면 어떤 성분을 얼마나 먹는지 알 수 없고, 복합제품의 `5000 IU`를 모든 성분에 복사하면 상한 비교가 거짓이 된다. OP-014의 결과는 제품명, 성분별 이름과 1일 용량을 분리하고, 중복 성분과 불완전한 용량을 안전하게 판정할 수 있는 구조를 만드는 것이다.

## 제품과 성분은 같은 객체 안에서도 역할이 다르다

`SupplementInput`은 제품 name, legacy dose, 구조화 product daily_dose, ingredients를 가진다. 각 `SupplementIngredientInput`은 성분 name과 선택 daily_dose를 가진다. `DoseAmount`는 OP-013과 같은 양수·단위 계약을 재사용한다. legacy dose와 structured daily_dose를 동시에 제공하면 `dose and daily_dose cannot both be provided`로 거부한다. 별도 보충제 파서를 만들지 않고 기존 `RecommendationRequest.current_supplements`와 intake를 확장했다.

`src/wellnessbox_rnd/domain/intake.py`는 제품명과 성분명을 canonical catalog key로 정규화하고 제품 set과 ingredient set을 따로 만든다. `domain/catalog.py`, `domain/loaders.py`, `knowledge/runtime_db.py`의 기존 ingredient identity와 runtime knowledge를 재사용한다. 모델에는 안정된 `current_ingredient::vitamin_d3` feature가 전달된다. 안전 서비스는 여러 제품의 같은 성분을 합산하지만 한 제품의 반복 성분 줄을 cross-product duplicate로 부르지 않는다.

## 불완전한 용량은 숫자를 발명하지 않는다

구조화된 vitamin D3 2400 IU와 2000 IU는 4400 IU로 합산되고 제품 수 2, 관측 수 2, complete true가 된다. 용량 없는 두 probiotic 제품은 duplicate임을 표시하되 total과 unit을 `None`으로 둔다. 한 제품만 용량이 있으면 알려진 부분합은 보존하지만 complete false다. g와 mg처럼 변환 가능한 질량은 기준 단위로 바꾼 뒤 비교한다. IU와 mg처럼 변환할 수 없는 값, range, `twice daily`, `bid`, 복합 문자열은 `dose_evidence_incomplete`로 fail closed하고 한 숫자를 임의 성분에 배정하지 않는다.

`data/samples/api_recommend_structured_safety_block_request_v1.json`은 Daily Bone Softgel의 Vitamin D3 125mcg를 구조화 예제로 제공한다. `data/catalog/ingredients.json`, `data/rules/safety_rules.json`, `data/knowledge/runtime_knowledge_db_v1.json`은 identity, 상한 rule과 evidence-linked interaction을 기존 저장 구조에서 제공한다. 별도 catalog나 안전 엔진을 만들지 않았다.

## 테스트가 합산과 모호성의 양쪽을 실행한다

`tests/test_medication_supplement_input_contracts.py`는 구조화·legacy 입력, 여러 제품 합산, 단위 변환, 중복 성분, 부분 용량, 무용량, 복합제품, range와 schedule, fuzzy title, 상한 초과를 실행한다. Warfarin과 omega-3 interaction이 정확한 reference·claim ID를 반환하는지도 확인한다. 구조화 name과 ingredient가 efficacy·policy feature에 같은 key로 도달한다. `tests/test_inference_api.py`는 실제 API 요청 경계를 보완한다.

최초 구조화 커밋은 `405484dd5245828363be58ae97c9da445708af97`이다. `5a893776381e94a64d0b8a94fec25ee776bbccf3`은 중복·합산과 interaction을 연결했고, `8b5f6dde1f2f1639a1001ee3a5ec27ff4ff42e0b`은 불완전 dose를 fail closed하도록 강화했다. 현재 manifest 감사와 CI는 이 계보의 추적 파일과 계약 테스트를 반복한다.

## 완료 단계와 남은 한계

OP-014는 required와 claimed stage가 `IMPLEMENTED`이며 COMPLETE다. 제품·성분·1일 용량 계약, 단위 변환, 모호한 입력 거부와 안전 합산 테스트가 구현을 증명한다. 실제 구매 제품 라벨의 진실성, production 복용 기록, 의료 전문가 확인은 증명하지 않는다. 따라서 통합·운영·외부검증을 주장하지 않는다.

이번 보고서 작성은 코드·서비스·데이터·학습·모델·simulation을 바꾸지 않는다. frozen 256건, 일곱 지표, weakest slice와 replay delta는 0으로 유지된다. 남은 조건은 실제 product label과 사용 기록이 필요한 운영 단계 및 외부 안전 평가를 별도 증거로 충족하는 것이다.
