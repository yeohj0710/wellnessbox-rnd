# OP-005 원본 25~26쪽의 일곱 KPI 수식과 분모를 현재 계산기와 대조한다.

## 같은 90%라도 무엇으로 나눴는지가 다르다

원본 25쪽은 일곱 성능 지표와 목표값을 한 표에 적고, 26쪽은 각 지표의 계산식을 정의한다. 추천 정확도 80%, 상담 답변 정확도 91%, 센서·유전자 연동율 90%처럼 숫자만 보면 비슷해 보인다. 그러나 추천 정확도의 분모는 약사가 만든 기준 성분 집합이고, 상담 정확도의 분모는 질문 수이며, 연동율은 웨어러블·연속혈당·유전자 세 출처의 성공률을 각각 계산한 뒤 같은 비중으로 평균한다. OP-005는 목표 숫자를 옮기는 작업이 아니라 현재 계산기가 원문 분자를 올바른 분모로 나누는지 확인하는 요구사항이다.

## KPI-1은 추천 개수가 아니라 기준 성분 집합을 분모로 쓴다

약사 그룹이 사용자 i에게 제시한 기준 성분 집합을 `R_i`, 엔진이 추천한 조합의 성분 합집합을 `T_i`라고 한다. 개별 점수는 `s_i = 100 * |R_i ∩ T_i| / |R_i|`이고 전체 점수는 N개 사례의 `s_i` 평균이다. 원문 목표는 최소 100개 사례와 평균 80% 이상이다. 추천 목록의 길이 `|T_i|`를 분모로 쓰는 precision이나 두 집합의 합집합을 분모로 쓰는 Jaccard 점수가 아니다. 기준 성분을 얼마나 포함했는지 보는 coverage에 가깝다.

현재 `src/wellnessbox_rnd/interim/kpi.py`의 `recommendation_reference_coverage`는 `len(reference & predicted) / len(reference)`를 계산한다. 독립 검토에서 기준 집합과 예측이 모두 비면 기존 계산기가 100점을 주어 분모 없는 사례가 평균을 부풀릴 수 있다는 결함을 찾았다. 단일 점수 함수는 기준 집합이 비면 `recommendation_reference_set_required` 오류를 낸다. 전체 평가기는 빈 기준 집합을 완전 정답이나 0점으로 평균에 넣지 않고 제외 수를 별도로 보고하며, 유효 기준 집합이 하나도 없으면 평가를 중단한다. 현재 5,000개 입력 중 빈 기준 집합 1,456개를 제외한 3,544개 유효 사례가 100%다. 프록시 계산기는 원문 80%보다 엄격한 내부 guardband 88%와 95% 신뢰구간 하한 84%를 요구하지만, 상태는 `PENDING_PHARMACIST_GOLD`다. 합성 기준 집합은 실제 독립 약사 정답을 대신하지 않는다.

## KPI-2는 복용 전후 백분위 포인트 차이의 평균이다

사용자 i의 복용 전 표준화 점수를 `z_pre,i`, 복용 후 점수를 `z_post,i`라고 한다. 표준정규분포 누적분포함수 `Φ`를 적용한 개별 개선도는 `p_i = 100 * [Φ(z_post,i) - Φ(z_pre,i)]`이고, 전체 SCGI는 N개 사용자의 `p_i` 평균이다. 원문은 최소 100쌍의 전후 환자보고결과(PRO)와 평균 0pp 초과를 통과 기준으로 둔다. 분모는 제품 수나 문항 수가 아니라 유효한 복용 전후 사용자 쌍의 수 N이다.

현재 계산기는 `pro_observations`에서 `SYNTHETIC_OUTCOME_PROXY`로 표시된 `percentile_point_change`를 읽어 평균과 결정적 bootstrap 신뢰구간을 낸다. 평균뿐 아니라 신뢰구간 하한도 0보다 커야 프록시를 통과한다. 현재 240쌍의 결과는 6.045903pp이고 `PENDING_REAL_WORLD_OUTCOME`이다. 합성 전후 변화가 양수라는 사실은 실제 사용자의 임상 효과를 증명하지 않는다.

## KPI-3과 KPI-4는 서로 다른 평가 단위를 쓴다

KPI-3의 분모는 전체 테스트 수행 작업 집합 `|S|`다. 정답 작업과 시스템 작업이 같고 실행 성공과 사후조건 성공이 모두 참인 사례만 1로 센다. 정확도는 성공 사례 수를 `|S|`로 나눈 값이다. 원문은 최소 100개 사례와 80% 이상을 요구한다. 현재 계산기는 실행 성공과 사후조건을 모두 확인하며 90% 이상, 고위험 오판 0이라는 더 엄격한 guardband를 둔다. 1,500개 프록시 결과 99.933333%는 `PENDING_EXTERNAL_TEST`다.

KPI-4의 분모는 테스트 질문 집합 `|Q|`다. 각 답변이 사전 정의한 적합성 판단을 통과하면 1로 세고 그 합을 질문 수로 나눈다. 원문은 최소 100문항과 91% 이상을 요구한다. 현재 계산기는 `acceptable=true`이면서 `critical_safety_error=false`인 답변만 성공으로 보고 96% 이상과 치명적 안전 오류 0을 요구한다. 1,500문항의 프록시 결과 98.533333%도 외부 시험 결과가 아니므로 `PENDING_EXTERNAL_TEST`다.

## KPI-5는 규칙 논리와 레퍼런스가 함께 맞아야 한다

KPI-5의 분모는 표본 규칙 수 R이다. 각 규칙에서 엔진 논리 `l_r`가 참조 논리 `l_ref`와 같고, 엔진 근거 `f_r`가 참조 근거 `f_ref`와 같을 때만 1로 센다. 둘 중 하나만 맞으면 실패다. 원문 통과 기준은 최소 100개 규칙과 정확 일치율 95% 이상이다. 따라서 답변이 그럴듯한지 평가하는 지표가 아니라 구조화된 안전 판정과 citation 연결이 정확한지 보는 지표다.

현재 계산기는 label의 exact match와 evidence 집합의 exact match를 함께 확인한다. 내부 guardband는 99% 이상이며 참조가 BLOCK 또는 STOP_AND_ESCALATE인데 엔진이 차단하지 않은 hard false negative가 0이어야 한다. 2,000개 프록시 결과는 99.9%지만 독립 약사 기준이 없어 `PENDING_PHARMACIST_GOLD`다. 이 결과를 실제 고위험 안전 검증 완료로 바꾸려면 OP-039의 외부 라벨이 필요하다.

## KPI-6은 비율이 아니라 직전 12개월 사건 수다

KPI-6은 추천 복용과 관련된 사용자 약물이상반응 보고 건수를 센다. 수식은 직전 12개월에 보고된 사건 indicator의 합이고 목표는 연 5건 이하다. 분모가 있는 발생률이 아니므로 사용자 수가 늘어도 단순 백분율로 바꾸면 원문과 다른 지표가 된다. 현재 계산기는 `SYNTHETIC_SAFETY_PROXY` 중 추천 관련 adverse event 행 수를 세어 3건을 반환한다.

현재 보고서의 표본 1,200은 합성 평가 범위를 설명하지만 KPI 값 자체의 분모는 아니다. 실제 통과에는 12개월 관찰 창, 완전한 사건 수집, 추천과 사건의 관련성 판정이 필요하다. 그래서 현재 상태는 `PENDING_12_MONTH_REAL_OPERATION`이다. 합성 3건이 5건보다 작다는 사실만으로 운영 ADR 목표를 달성했다고 말할 수 없다.

## KPI-7은 세 출처를 같은 비중으로 평균한다

웨어러블 W, 연속혈당 C, 유전자 G 각각에 대해 `r_s = 100 * 성공 세션 수 / 전체 세션 수`를 계산한다. 전체 연동율은 `(r_W + r_C + r_G) / 3`이다. 세 출처의 전체 행을 한꺼번에 합쳐 나누는 micro average가 아니다. 데이터가 많은 웨어러블이 다른 출처의 낮은 성공률을 가리지 못하도록 세 출처를 같은 비중으로 본다. 원문은 총 100개 이상, W/C/G 각 10세트 이상, 평균 90% 이상을 요구한다.

현재 `linkage_macro_rate`는 W, C, G 중 하나라도 비면 실패하고 각 출처의 성공률을 따로 계산한 뒤 산술평균한다. 내부 guardband는 총 150개, 각 20개, 평균 97% 이상이다. 현재 180개 프록시 세션의 결과는 97.777778%지만 `PENDING_PRODUCTION_DEVICE_SESSIONS`다. 시뮬레이션 connector가 데이터를 받아들였다는 결과는 실제 장치와 외부 검사기관의 production 연동을 증명하지 않는다.

## 원문, 현재 계산기, 고정 패키지를 어떻게 대조했나

첫 번째 구현 증거 `wellnessbox-rnd/docs/context/master_context.md`는 원본 25~26쪽의 일곱 KPI, 목표, 수식, 최소 표본과 분모를 7.1~7.2에 재구성한다. 두 번째 구현 증거 `wellnessbox-rnd/docs/tips/CURRENT_REPO_AUDIT.md`는 현재 프록시 결과와 교체 상태를 한 표에 기록하고, 추천 분모가 `|R_i|`, W/C/G가 동일 가중 macro 평균임을 명시한다. 이번 시각 검토에서는 25쪽의 목표·가중치 표와 26쪽의 일곱 수식을 고해상도 이미지로 다시 확인했다.

테스트 증거 `wellnessbox-rnd/tests/test_interim_manifest.py`는 승인된 중간 패키지의 19개 파일, train 120,000·validation 15,000·calibration 10,000·blind test 5,000의 합계 150,000건, KPI 7/7 프록시 통과, manifest와 모델 SHA-256을 고정한다. `wellnessbox-rnd/tests/test_original_plan_manifest.py`는 OP-005의 증거 경로와 `IMPLEMENTED` 주장 재고를 지킨다. 실제 수식 분기, 빈 기준 집합 거부와 W/C/G macro 계산은 `tests/test_interim_kpi.py`가 별도로 검사한다. manifest 테스트 하나만으로 계산식 전체가 증명된다고 과장하지 않는다.

Git 이력에서는 2026-07-10의 `54141f24e486d1c9ed72798c65d27bed3e637753`가 중간 시뮬레이션, KPI 계산, `CURRENT_REPO_AUDIT.md`, 고정 패키지 테스트를 도입했다. 2026-07-15의 `b96a92d6ff275ed6858ef7737d63a054678bbbad`는 OP-005를 120개 manifest와 단계 계약에 등록했다. 패키지는 2026-07-14의 `8a03cb78d8a82a567416c18335e35be69a3036b2`에서 현재 승인 경로로 정리됐다.

## 현재 완료 단계와 남은 경계

OP-005의 기본 요구 단계와 주장 단계는 `IMPLEMENTED`다. 원문의 일곱 수식과 분모를 현재 계산기와 대조했고, 계산기와 고정 패키지를 자동 테스트로 재현하므로 구현 단계는 충족한다. 실제 약사 정답, 실제 사용자 효과, 외부 시험, 직전 12개월 운영 ADR, 생산 장치 세션이 없으므로 7개 KPI의 실제 연구 완료를 주장하지 않는다. 현재 문서도 `real_research_completion=false`를 명시한다.

이번 반복은 연구보고서와 OP-120 감사 집계에 더해 KPI-1의 빈 기준 집합 처리와 회귀 테스트를 좁게 수정했다. 승인된 프록시 데이터, 학습, 모델, 시뮬레이션 결과는 바꾸지 않았으므로 기존 수치가 좋아졌다고 주장하지 않는다. OP-005의 결과는 숫자 7개를 통과 표로 모은 것이 아니라, 각 숫자가 어떤 사례·질문·규칙·기간·출처 집합을 분모로 삼는지 재현 가능하게 고정한 것이다.
