# OP-054 순응도, 누락 복용, 이상사례를 효과 해석에 반영한다.

## 점수 변화만으로 효과를 단정하지 않는 것이 요구사항의 핵심이다

OP-054는 시작 점수와 추적 점수의 차이를 계산하되, 복용 순응도와 누락 횟수, 이상사례 문맥을 함께 보고 해석 상태와 제한 사유를 결정한다. 정식 정책은 `wellnessbox-rnd/data/contracts/pro_followup_interpretation_v1.json`에 있다. 최소 순응률은 0.8이고, 판정 우선순위는 중대한 이상사례, 그 밖의 이상사례, 80% 미만 순응, 1회 이상 누락, 제한 없는 해석 순이다. 앞선 조건이 있으면 단순히 점수가 좋아졌다는 이유로 더 낮은 우선순위의 정상 해석을 선택하지 않는다.

모든 결과는 관찰 변화이며 인과 추정이 아니다. 계약의 `causal_interpretation_allowed`는 `false`이고 결과 모델도 같은 값을 강제한다. 즉, “복용 뒤 점수가 좋아졌다”는 시간적 관찰은 기록할 수 있지만 “추천 성분이 개선을 일으켰다”는 결론은 이 기능의 완료 범위를 벗어난다. 도입 전에는 점수 변화, 순응도, 이상사례를 같은 버전 계약으로 결합해 파생 결과를 재검증하는 모듈이 없었다.

## 해석 함수는 관찰 변화와 제한 사유를 원자료에서 다시 계산한다

`wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_followup.py`의 `PROInstrumentObservedChangeV1`은 시작 평가와 추적 평가의 원점수, 건강 방향 Z 점수, 백분위 차이를 보관한다. 두 점수는 같은 평가 도구, 점수 계약 버전, 시작 분포 해시를 가져야 한다. `PROAdherenceWindowV1`은 예정·실제·누락 복용 수의 합계를 맞추고 순응률을 계산하며, `PROAdverseEventContextV1`은 이상사례의 유무와 중증도를 표현한다.

`PROFollowUpEffectInterpretationV1`은 관찰 변화, 순응도, 이상사례, 해석 상태, 제한 사유, 인과 해석 금지 표시를 한 결과로 묶는다. 이 모델은 저장된 파생 필드를 그대로 신뢰하지 않고 다시 계산한 값과 비교한다. `interpret_pro_followup_effect_v1`도 입력 이벤트의 계획, 데이터 등급, 평가 도구, 시작 분포, 평가 식별자, 관측 순서를 대조한 뒤 결과를 만든다. 다른 계획의 시작 점수, 같은 `assessment_id`를 쓴 두 점수, 추적 시각이 시작 시각보다 이른 입력, 임의로 바꾼 결과 필드는 모두 거부된다.

정규화 함수와 공개 해석 함수가 Pydantic 인스턴스까지 재검증하므로 생성자 검사를 우회한 객체도 통과하지 않는다. 이 설계는 API 앞단에서 올바른 JSON을 받았는지와 별개로, 효과 해석 경계 자체가 계약 위반을 차단하도록 한다.

## 초기 구현 뒤 교차 계획과 시간 역행 우회가 명시적으로 막혔다

커밋 `334bd70`은 해석 계약과 `PROInstrumentObservedChangeV1`, `PROFollowUpEffectInterpretationV1`, 해석 함수, 단위 테스트와 스모크를 추가했다. 커밋 `83997c1`은 다른 계획의 점수를 섞는 입력, 중복 평가 식별자, 뒤로 가는 관측 시각, 엄격한 PRO 이벤트를 일반 이벤트로 위장하는 경로를 추가로 차단했다. 해석 단계에서는 계산 결과를 임의로 바꾼 모델도 거부하도록 회귀 검사가 보강됐다. 커밋 `706fb4a`는 이 보강 뒤 실행 결과를 정식 증거로 등록했다.

확인 가능한 결함은 해석 공식의 부호 오류가 아니라 입력 계보와 영속 경계의 우회 가능성이었다. 저장소 이력에는 이 결함이 실제 사용자 판단을 바꿨다는 사고 기록이 없으므로, 보고서는 코드 경계의 실패와 수정만 설명한다. 또한 등록 증거 생성 이후 관련 소스가 더 바뀌었으므로, 당시 성공 결과와 현재 코드의 동일성을 별도로 판단해야 한다.

## 단위 테스트는 같은 점수 변화가 문맥에 따라 다르게 해석되는지 확인한다

`wellnessbox-rnd/tests/test_pro_followup_effects.py`의 `test_effect_interpretation_reflects_adherence_missed_doses_and_adverse_events`는 동일한 개선 방향을 가진 입력에서도 순응도, 누락, 이상사례에 따라 해석 상태와 제한 사유가 달라지는지 확인한다. `test_interpretation_rejects_cross_plan_distribution_and_output_mutation`은 다른 계획이나 시작 분포를 섞거나 파생 결과를 변조했을 때 실패하는지 확인한다. `test_interpretation_rejects_duplicate_assessment_or_reversed_observation_time`은 같은 평가를 시작·추적 양쪽에 재사용하거나 관측 시간을 역전시키는 입력을 막는다.

같은 파일의 시점 순서 검사와 원장 저장 검사는 해석 함수가 받는 이벤트 자체의 신뢰성을 보완한다. 현재 `test_pro_followup_effects.py`에서 수집된 23개 테스트는 모두 통과했고, 점수·추적·집단효과·계획 서비스 핵심 네 파일을 함께 실행한 79개 테스트도 모두 통과했다. 반면 매니페스트에 연결된 계보·수정 원장 테스트까지 포함한 전체 실행은 106개 중 104개가 통과하고 정식 증거의 데이터베이스 스키마 버전 불일치 검사 2개가 실패했다. 이 두 실패는 해석 계산 결과가 틀렸다는 증거는 아니지만, 증거 묶음 전체가 현재 상태라고 말할 수 없게 한다.

## 스모크는 다섯 문맥을 재현했고 모든 결과의 인과 해석을 금지했다

`wellnessbox-rnd/scripts/run_pro_followup_adherence_interpretation_smoke.py`의 등록 결과는 시작 대비 평균 건강 방향 Z 점수 변화가 모두 `+1`인 다섯 사례를 실행한다. 14회 중 14회 복용한 사례는 제한 없는 해석, 14회 중 12회 복용한 사례는 순응률 0.857143이지만 누락 사유가 있는 제한 해석, 14회 중 10회 복용한 사례는 순응률 0.714286로 기준 미달 해석을 기록한다. 경미한 이상사례와 중대한 이상사례 사례는 각각 이상사례 문맥과 우선 대응 필요성을 점수 개선보다 먼저 반영한다.

정식 결과 파일 `wellnessbox-rnd/data/original_plan/evidence/op053_op054_pro_followup_interpretation_smoke_v1.json`은 다섯 사례 모두에서 인과 해석을 허용하지 않는다. 계약 변조, 교차 계획·분포, 평가 중복, 관측 시간 역행, 결과 변조 등 실패 차단 항목도 기록한다. 따라서 스모크가 증명하는 것은 문맥별 결정 규칙의 재현성과 입력 계보 검증이지, 특정 성분의 임상 효과가 아니다.

## 현재 단계는 IMPLEMENTED이며 등록 증거는 시점 기록으로 읽어야 한다

매니페스트에서 OP-054의 요구 단계와 현재 단계는 `IMPLEMENTED`다. 해석 계약, 코드, 단위 테스트, 합성 스모크가 존재하고 현재 핵심 테스트가 통과하므로 코드 수준 완료 근거는 있다. OP-053과 OP-058에 등록된 로컬 실제 세션 영수증은 OP-054를 적용 범위로 명시하지 않으므로, 그 영수증으로 OP-054를 `OPERATED`로 올릴 수 없다.

등록 스모크의 소스 해시 `ba663ac…`는 현재 같은 소스 집합의 재계산 값 `e455b85…`와 다르다. 증거의 소스 커밋은 `94b0374`이고 관련 경로에는 `3f67d0b`까지 후속 변경이 있다. 그러므로 JSON은 생성 시점의 합성 실행 증거이고, 현재 코드의 정식 소스 다이제스트는 아니다.

실제 사용자의 복용 기록 정확도, 이상사례 분류의 임상 검토, 80% 기준의 대상 집단 적합성, 장기 추적 누락 편향, 서비스 화면에서의 해석 문구, 운영 세션과 프로덕션 환경은 검증되지 않았다. OP-054의 완료 경계는 정해진 입력이 들어왔을 때 관찰 변화와 제한 사유를 결정적으로 계산하고 인과 표현을 막는 구현까지다.
## 효과를 측정할 때 분리한 것
효과를 말하려면 예측값과 실제 복용 전후 관측값을 섞지 않아야 한다. 이 그룹은 PRO 원점수, 표준화, 개인별 변화, 집단 평균, 신뢰구간, 순응도와 이상사례를 각각 기록해 숫자가 무엇을 의미하는지 확인한다.

`OP-054`는 “순응도, 누락 복용, 이상사례를 효과 해석에 반영한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=18`, `docs/context/original_plan.pdf#page=19`
- 구현·설계: `wellnessbox-rnd/data/contracts/pro_followup_interpretation_v1.json`, `wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_followup.py`
- 테스트·실행: `wellnessbox-rnd/tests/test_pro_followup_effects.py`, `wellnessbox-rnd/scripts/run_pro_followup_adherence_interpretation_smoke.py`, `wellnessbox-rnd/data/original_plan/evidence/op053_op054_pro_followup_interpretation_smoke_v1.json`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `IMPLEMENTED`, 현재 주장 단계를 `IMPLEMENTED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
