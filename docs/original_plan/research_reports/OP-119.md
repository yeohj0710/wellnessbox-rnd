# OP-119 외부 항목별 책임자, 입력, 교체 계약, 차단 사유를 기록한다.

## 결론

OP-119는 요구 단계 `IMPLEMENTED`를 충족한다. manifest에서 `required_stage=EXTERNAL`인 요구사항을 자동 탐색하고, 각 항목에 책임 역할, 외부 공급 역할, 필수 입력, repository 교체 계약, 현재 차단 사유와 승격 조건을 연결하는 엄격한 원장을 구현했다. 현재 외부 요구사항은 OP-039 한 건이며 원장도 OP-039 한 건만 포함한다.

## 책임과 입력 계약

내부 책임 역할은 `wellnessbox_external_evidence_governance`다. 이 역할은 외부 검증 입력 자체를 만들지 않고 승인 기록과 repository trust root 등록을 소유한다. 외부 공급 역할은 구현 팀과 독립된 임상 안전성 검토 조직과 별도 증명 검증 조직이다. 필요한 입력은 외부 고위험 JSONL 데이터셋, 외부 증명서, 별도 검증 영수증, 라벨링 전에 동결된 coverage protocol 네 종류다.

각 입력은 기존 OP-039 계약의 정확한 schema version과 acceptance contract를 가진다. 현재 네 입력 모두 `MISSING`이다. 원장은 임의 조직명, 가짜 승인 hash, 합성 데이터 또는 자기 증명서를 외부 증거로 만들지 않는다.

## 교체 계약과 차단 사유

OP-039 manifest의 교체 계약 두 개와 원장의 경로 집합은 정확히 일치한다. coverage trust root에는 승인된 protocol과 승인 기록이 없고, attestation trust root에는 승인된 증명서·검증 영수증과 승인 기록이 없다. 감사기는 네 JSON pointer가 실제로 빈 목록인지 읽어 현재 `BLOCKED` 상태를 검증한다.

## canonical evidence

동결 사례 데이터셋은 `data/original_plan/op119_external_dependency_registry_cases_v1.json` 8건이다. 사례는 외부 요구사항 집합, 책임 역할, 외부 공급 역할, 필수 입력 4종, 교체 계약 2종, 차단 사유 4종, readiness, 승격 조건을 검증한다. runner는 예상값과 관측값을 완전 일치 비교하고 입력 파일의 Git blob과 source commit을 기록한다.

## 완료 범위와 제한

OP-119는 외부 의존성을 숨기지 않고 관리하는 구현 요구다. OP-039 외부 검증 완료를 뜻하지 않는다. OP-039가 완료되려면 실제 독립 조직이 네 입력을 제공하고 승인 hash와 승인 기록이 trust root에 등록된 뒤 독립 평가가 hard false negative 0을 입증해야 한다.
