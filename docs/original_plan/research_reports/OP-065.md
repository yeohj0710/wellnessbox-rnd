# OP-065 예산과 최대 복용 수를 넘는 조합을 제외한다.

R&D 요청 제한은 `wellnessbox-rnd/apps/inference_api/routes/interim.py`에 있고, 조합별 재검산은 `wellnessbox-rnd/src/wellnessbox_rnd/optimizer/product_combinations.py`에 있다. 서비스 필터 `wellnessbox/lib/server/wb-rnd-product-candidates.ts`와 정본 `wellnessbox-rnd/data/original_plan/evidence/op065_op066_product_combination_filter_smoke_v1.json`까지 따라가 확인했다. 등록된 입증 단계는 `INTEGRATED`다. 예산과 제품 수 제한이 서비스 조합 결과에 적용됐다는 뜻이며 실제 구매 제한을 운영에서 집행했다는 뜻은 아니다.

## 제한을 추천 뒤에 적용해야 하는 이유

성분 추천 단계에서는 어떤 판매 상품들이 한 조합을 이루는지 아직 알 수 없다. 같은 성분 목록도 복합 상품을 고르면 제품 수와 가격이 줄고, 단일 상품을 여러 개 고르면 늘어난다. 그래서 예산과 최대 제품 수는 추천 성분 자체가 아니라 판매 옵션을 선택해 만든 완성 조합에 적용해야 한다. 제한을 넘은 조합은 순위를 낮추는 방식이 아니라 후보 목록에서 제외한다.

R&D 요청은 `product_constraints`에 `max_total_cost_krw`와 `max_products`를 받는다. 비용은 0 이상의 정수, 제품 수는 1~20의 정수여야 한다. R&D 응답은 이 두 값과 안전 제외 성분·규칙을 `product_optimization_constraints_v1` 형식으로 묶는다. 서비스는 필드가 정확히 다섯 개인지, 목록이 정렬되고 중복이 없는지, 안전 제외 성분에 근거 규칙이 있는지 다시 확인한다.

## 조합 생성과 제외 이유의 연결

서비스는 추천별 상품 선택을 모두 조합으로 만든 뒤 각 조합의 판매가 합계와 고유 상품 수를 계산한다. 비용이 한도를 넘으면 `OVER_BUDGET`, 제품 수가 한도를 넘으면 `OVER_MAX_PRODUCTS`를 남긴다. 두 제한을 동시에 넘으면 두 이유가 함께 기록된다. 통과 조합만 비용, 제품 수, 조합 ID 순으로 정렬한다. 검색 상태가 상한에 닿은 경우에는 일부 결과를 최선이라고 오해하지 않도록 상위 조합 목록을 비운다.

Python의 `evaluate_product_combination_filters_v1`은 서비스가 보고한 제외 결과를 독립적으로 다시 계산한다. 정책과 조합 목록에서 통과 ID, 예산 제외 ID, 제품 수 제외 ID를 만들고 저장된 결과와 비교한다. 결과 ID를 임의로 삭제하거나 추가하면 모델 검증이 실패한다. 이중 계산을 둔 이유는 서비스의 필터 숫자가 잘못돼도 기준 증거 생성 단계에서 발견하기 위해서다.

## 기준 실행과 현재 시험에서 관측한 값

등록 smoke는 고정 조합 네 개에 65,000원과 최대 제품 다섯 개 제한을 적용했다. 한 조합만 남았고 나머지 세 개는 예산과 제품 수 제한을 모두 넘었다. smoke가 따로 호출한 실제 R&D 응답 경계에서는 54,321원과 최대 세 개가 서비스까지 그대로 전달됐다. 다만 정본은 이 R&D 응답이 실제 READY 상품 필터 경로까지 이어진 사실을 `actual_ready_filter_path_proven=false`로 남겼다. 필터 숫자는 별도 서비스 고정 자료에서 검증한 것이다.

현재 `check-rnd-product-candidates.cts`는 시험 상수를 100,000원과 최대 일곱 개로 바꾼 상태다. 최신 실행에서도 네 조합 중 하나만 남았고, 세 조합이 두 제한으로 제외됐으며 관련 이유 코드가 존재했다. `tests/test_interim_api.py`는 42,000원·최대 두 개 요청이 응답에 그대로 나오고, 음수 비용·소수 비용·0개·21개·추가 필드가 HTTP 422로 거부되는지 확인한다. Python 필터 시험은 세 조합 중 두 개가 25,000원 예산을 넘어 제외되는 결과를 재계산했다. 집중 시험 96개와 서비스 QA가 모두 통과했다.

## 증거의 시점 차이와 운영 한계

정본이 사용한 65,000원·다섯 개와 현재 QA의 100,000원·일곱 개는 서로 다른 시험 시점의 값이다. 구현이 입력된 제한을 따르므로 둘 다 같은 경계 규칙을 시험하지만, 하나의 실행 결과처럼 합쳐서는 안 된다. 실제 사용자 예산이나 복용 가능 제품 수가 어디에서 결정되고 동의를 받는지는 API, 서비스 필터, 시험, 증거 파일에서 찾지 못해 `확인되지 않음`으로 기록한다.

정본은 서비스 함수 통합과 R&D 안전 계약 전달을 true로 두지만, 실제 Prisma 조회, 운영 상품 최신성, production 배포, 주문과 결제는 모두 false다. 등록 증거의 소스 결합 지문도 현재 파일에서 계산한 값과 다르다. 따라서 OP-065는 기록된 서비스 통합 기준으로 `INTEGRATED`이며, 최신 운영 DB와 실제 READY 응답을 함께 통과한 필터 실행은 아직 확인되지 않았다.
