# OP-056 효과 추정에 표본 수, 신뢰구간, 불확실성 사유를 포함한다.

## 평균 하나 대신 표본 규모와 해석 제한을 함께 반환해야 한다

OP-056은 집단 효과를 평균값 하나로 보고하지 않고 표본 수, 95% 신뢰구간, 불확실성 사유를 같은 결과에 포함하도록 요구한다. 정식 정책은 `wellnessbox-rnd/data/contracts/pro_group_effect_summary_v1.json`에 있다. 계산 가능한 최소 집단은 2명이고, 충분한 표본을 판단하는 KPI 기준은 100명이다. 계약은 개인별 관찰 변화의 산술평균과 결정적 백분위 부트스트랩 평균 구간을 사용하며 반복 수 3,000회, 난수 시드 20,260,710, 신뢰수준 0.95를 고정한다.

불확실성 사유는 항상 관찰 자료라 인과 결론을 낼 수 없다는 점, 실제 현장 자료가 아닌 경우, 표본 수가 100명 미만인 경우, 제한된 해석 상태의 개인이 포함된 경우, 신뢰구간이 0을 가로지르는 경우를 구분한다. 여러 조건이 동시에 맞으면 계약에 정한 우선순서로 배열한다. 평균이 양수여도 구간이 0을 포함하거나 표본이 작으면 그 제한을 숨기지 않는다.

도입 전에는 이 정책을 버전으로 고정한 계약과 공통 통계 함수가 없었다. 같은 데이터라도 호출자가 다른 반복 수, 시드, 백분위 보간법을 선택하면 결과가 달라질 수 있었고, 점 추정치만 전달하면 표본 크기와 불확실성을 잃을 수 있었다. OP-056은 특정 통계 방법이 모든 연구에 최선이라고 선언하는 대신, 현재 제품 연구 경계에서 사용하는 계산법과 한계를 재현 가능하게 고정한다.

## 통계 함수와 결과 모델은 계산 정책의 임의 변경을 거부한다

`wellnessbox-rnd/src/wellnessbox_rnd/metrics/statistics.py`의 `linear_percentile`은 정렬된 표본에서 선형 보간 백분위를 계산한다. `deterministic_bootstrap_mean_ci`는 고정된 시드로 개인 변화를 복원 추출하고 각 표본의 평균을 만든 뒤 하한과 상한을 계산한다. 빈 입력, 유한하지 않은 값, 잘못된 신뢰수준, 불리언 또는 1 미만 반복 수, 불리언 또는 정수가 아닌 시드는 실패한다. 같은 입력과 정책이면 실행 순서나 머신의 호출 시점과 무관하게 같은 구간을 재생하도록 난수 상태를 함수 안에서 만든다.

`wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_group_effects.py`의 `_derive_summary_fields`는 원점수 변화, 건강 방향 Z 점수 변화, 백분위 변화 각각에 평균과 신뢰구간을 계산한다. `PROGroupEffectSummaryV1`은 `sample_size`, 세 점 추정치, 세 구간, 해석 상태별 개수, 불확실성 사유를 개인 결과에서 다시 파생해 대조한다. `build_pro_group_effect_summary_v1`은 서로 다른 시점·데이터 등급·도구·계약·시작 분포를 섞지 않은 집단에서만 이 모델을 만든다.

결과에 포함된 “95% 신뢰구간”은 이 고정 부트스트랩 절차가 산출한 구간이라는 뜻이다. 합성 표본의 대표성, 관측 독립성, 결측 과정, 임상적 유의성을 자동으로 보증하는 표현은 아니다.

## 증거 출처 누락은 계산 수정과 분리해 보강됐다

커밋 `5b9dedc`은 통계 함수, 집단 결과 모델, 계약, 테스트와 스모크를 처음 추가했다. 커밋 `56d0542`는 스모크 결과의 소스 식별자 목록에 직접 사용하는 계약 파일과 중간 계약 모듈이 빠져 있던 문제를 수정했다. 같은 커밋의 `test_smoke_source_identity_includes_direct_contract_dependencies`는 이후 증거 생성에서 직접 의존성이 누락되지 않는지 검사한다. 커밋 `0a1f102`는 보강된 스모크 결과를 정식 증거로 등록했다.

이 이력에서 확인되는 후속 결함은 평균이나 부트스트랩 수치의 오계산이 아니라 증거가 참조한 소스 범위의 누락이다. 따라서 보고서는 계산값 변경과 출처 계보 보강을 구분한다. 저장소에는 이 통계 기능을 실제 사용자 집단에 적용했다가 구간이 잘못됐다는 실패 기록은 없다.

## 테스트는 결정적 재생, 입력 실패, 불확실성 분기를 검증한다

`wellnessbox-rnd/tests/test_pro_group_effects.py`의 `test_deterministic_bootstrap_mean_ci_replays_exactly`는 같은 값, 반복 수, 시드가 같은 구간을 재현하는지 확인한다. `test_deterministic_bootstrap_mean_ci_rejects_invalid_inputs`는 빈 값과 비정상 숫자, 잘못된 신뢰수준·반복 수·시드를 거부한다. `test_group_summary_reports_sample_ci_and_uncertainty_reasons`는 표본 수, 세 변화 지표의 평균과 구간, 불확실성 사유가 함께 만들어지는지 확인한다.

`test_group_summary_reports_limited_and_zero_crossing_uncertainty`는 제한된 개인 해석 상태와 0을 가로지르는 구간을 별도 사유로 반환하는지 확인한다. `test_group_summary_rejects_derived_output_mutation`은 계산된 표본 수, 구간, 사유를 호출자가 바꾼 모델을 막는다. `test_group_effect_contract_rejects_policy_drift`는 반복 수, 시드, KPI 같은 정책 변조를 거부한다. 현재 이 파일에서 수집된 18개 테스트가 모두 통과했고, 관련 핵심 네 파일의 79개 테스트도 모두 통과했다.

## 합성 100명 증거는 수치와 불확실성 코드의 재현성을 보여 준다

정식 실행 결과 `wellnessbox-rnd/data/original_plan/evidence/op055_op056_pro_personal_group_uncertainty_smoke_v1.json`은 합성 개인 100명의 변화를 3,000회 고정 시드로 집계한다. 건강 방향 Z 점수 변화 평균은 0.67이고 95% 구간은 0.616666~0.723333이다. 건강 백분위 변화 평균은 25.779542이고 구간은 23.82636~27.745993다. 100명 모두 제한 없는 개인 해석 상태이므로 작은 표본이나 제한된 개인 사유는 붙지 않지만, 인과 해석 금지와 실제 현장 자료가 아니라는 사유는 남는다.

스모크는 파생 결과 변조와 집단 식별자 혼합을 실패시키고, 단위 테스트는 구간이 0을 지나는 소집단과 제한 상태가 섞인 집단을 추가로 확인한다. 증거의 소스 해시 `2964b1d…`는 현재 같은 소스 집합의 재계산 값과 일치하며, 기록된 커밋 `06031bee`도 조사한 관련 경로의 최신 커밋이다. 등록 JSON을 현재 구현과 직접 연결할 수 있는 상태다.

## 현재 단계는 IMPLEMENTED이며 통계적 타당성의 외부 검토는 남아 있다

매니페스트의 OP-056 요구 단계와 현재 단계는 `IMPLEMENTED`다. 계약에 고정된 계산, 실패 차단, 단위 테스트, 현재 소스와 일치하는 합성 스모크가 있으므로 구현 완료 근거는 충족한다. 서비스 응답, 사용자 화면, 운영 세션, 프로덕션 데이터에 이 결과가 실제로 표시됐다는 등록 증거는 없다.

실제 데이터의 표본 대표성, 개인 관찰 간 독립성, 결측·중도 탈락 처리, 여러 도구나 여러 시점을 반복 비교할 때의 다중성, 신뢰구간 방법의 통계 검토, 임상적으로 의미 있는 변화 기준은 검증되지 않았다. KPI 100은 계약상 경고 기준이지 충분한 검정력이나 외적 타당성을 보장하는 숫자가 아니다. OP-056의 완료 경계는 입력 집단에 대해 고정 정책으로 표본 수·구간·불확실성 사유를 재현하는 코드까지다.
## 효과를 측정할 때 분리한 것
효과를 말하려면 예측값과 실제 복용 전후 관측값을 섞지 않아야 한다. 이 그룹은 PRO 원점수, 표준화, 개인별 변화, 집단 평균, 신뢰구간, 순응도와 이상사례를 각각 기록해 숫자가 무엇을 의미하는지 확인한다.

`OP-056`는 “효과 추정에 표본 수, 신뢰구간, 불확실성 사유를 포함한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=18`, `docs/context/original_plan.pdf#page=19`
- 구현·설계: `wellnessbox-rnd/data/contracts/pro_group_effect_summary_v1.json`, `wellnessbox-rnd/src/wellnessbox_rnd/metrics/pro_group_effects.py`, `wellnessbox-rnd/src/wellnessbox_rnd/metrics/statistics.py`
- 테스트·실행: `wellnessbox-rnd/tests/test_pro_group_effects.py`, `wellnessbox-rnd/scripts/run_pro_personal_group_uncertainty_smoke.py`, `wellnessbox-rnd/data/original_plan/evidence/op055_op056_pro_personal_group_uncertainty_smoke_v1.json`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `IMPLEMENTED`, 현재 주장 단계를 `IMPLEMENTED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
