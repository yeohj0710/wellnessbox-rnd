# OP-047 결정 불확실성과 추가 입력 조건을 정량화한다

## 결론과 요구사항의 의미

OP-047은 추천 결과에 막연한 “확신 낮음” 표시를 붙이는 대신, 어떤 정보가 없고 후보 간 점수 차이가 얼마나 작은지 수치와 코드로 반환하도록 요구한다. 현재 `DecisionUncertainty`는 누락 입력, 응답 상태, 후보 점수 간격을 각각 계산하고 합계를 0과 1 사이로 제한한다. 동시에 `additional_input_conditions`에 더 받으면 판단이 달라질 수 있는 입력을 기록하고, `candidate_ranking_snapshot`에 선택 전 전체 후보 순위를 남긴다.

이 요구사항이 없으면 출력 개수를 1개로 제한했을 때 두 번째 후보가 응답에서 사라져 1위와 2위가 사실상 동점인지 알 수 없다. 또한 약물·질환·임신 정보가 비어 있는 경우와 후보 점수가 비슷한 경우가 모두 같은 “검토 필요” 상태로 뭉개진다. 현재 구현은 두 원인을 분리해 사용자가 무엇을 추가로 입력해야 하는지와 현재 순위가 얼마나 불안정한지를 함께 설명한다.

매니페스트에 등록된 경로 `wellnessbox-rnd/src/wellnessbox_rnd/orchestration/recommendation_service.py`에서 계산을 확인했고, 스키마·계약·최적화 코드와 등록된 테스트·스모크·증거 파일도 모두 존재하며 내용이 일치했다.

## 계산식과 데이터 불변식

`recommend`가 추천과 후보 점수를 만든 뒤 `_build_decision_uncertainty`가 세 종류의 점수를 합산한다. 임신 정보가 없으면 0.05, 질환 정보가 없으면 0.10, 약물 정보가 없으면 0.20을 더한다. 응답 상태가 `NEEDS_REVIEW`이면 0.20을 더한다. 안전 통과 후보가 없으면 후보 항목으로 0.15를 더하고, 후보가 둘 이상이면 1위와 2위의 점수 차이를 사용한다. 차이가 1 미만이면 0.20, 3 미만이면 0.10, 5 미만이면 0.05다. 합계는 최대 1.0으로 제한된다.

최종 등급은 합계가 0.25 이하이면 `low`, 0.50 이하이면 `moderate`, 그보다 크면 `high`다. 경계값 자체도 스키마 검증 대상이다. `additional_input_conditions`에는 누락된 임신·질환·약물 입력이 각각 코드와 함께 들어가고, 후보 간격 항목에는 비교한 후보와 점수 차이가 근거로 남는다. 숫자만 있어 원인을 알 수 없는 구조가 아니다.

`wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation.py`의 `DecisionUncertainty.validate_uncertainty_calculation`은 구성요소 합계, 제한된 총점, 등급, 추가 입력 코드의 일치를 검사한다. `CandidateRankingSnapshot.validate_ranking_snapshot`은 선택 전 후보 수, 연속 순위, 정렬 순서와 1·2위 간격을 검사한다. `RecommendationResponse.validate_decision_diagnostics`는 이 스냅샷을 `candidate_preselection_scores` 및 실제 선택과 다시 맞춘다. 따라서 응답 제한 뒤 보이는 후보만으로 불확실성을 다시 계산하거나, 선택되지 않은 후보의 점수 근거를 버리는 구현은 검증을 통과하지 못한다.

외부 계약 경로인 `wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation_contracts.py`의 `_validate_decision_uncertainty_contract`도 응답 상태, 선택 개수, 후보 스냅샷을 교차 확인한다. 내부 계산과 외부 계약이 각각 같은 필드를 독립 검증하는 구조다.

## 테스트와 재현된 사례

`wellnessbox-rnd/tests/test_decision_uncertainty_learned_fallback.py`의 `test_decision_uncertainty_reconciles_components_and_band`는 구성요소·합계·등급을 함께 확인한다. `test_candidate_margin_uses_preselection_pool_when_output_limit_is_one`은 출력이 하나여도 전체 사전 후보에서 점수 간격을 계산하는지 시험한다. `test_ranking_snapshot_is_reconciled_with_independent_score_trace`와 `test_unselected_candidate_score_trace_preserves_full_breakdown`은 미선택 후보의 순위와 이유 분해가 남는지 확인한다. 외부 카탈로그 후보도 같은 검사를 통과하는지는 `test_unselected_candidate_score_trace_uses_external_catalog_registry`가 담당한다.

실패 경계도 별도 시험한다. `test_preselection_goal_mutation_returns_validation_error_not_key_error`는 조작된 목표가 내부 예외가 아니라 명시적 검증 오류로 닫히는지 확인한다. `test_missing_information_is_quantified_as_additional_input_conditions`는 누락 입력이 코드와 점수로 나타나는지 검증한다. `test_uncertainty_and_learned_diagnostic_schemas_fail_closed`는 합계, 등급, 후보 간격을 바꾼 모델을 거부한다. 계약 테스트의 `test_recommendation_set_contract_revalidates_status_against_uncertainty`, `test_recommendation_set_contract_revalidates_selection_count`, `test_diagnostics_contract_reconciles_snapshot_with_preselection_scores`도 외부 직렬화 뒤의 변조를 검출한다.

`wellnessbox-rnd/data/original_plan/evidence/op047_op048_decision_uncertainty_learned_fallback_smoke_v1.json`에는 완전 입력 사례의 불확실성 0.20과 1·2위 간격 0.5, 누락 입력 사례의 불확실성 0.45가 기록되어 있다. 후자는 임신 0.05, 질환 0.10, 약물 0.20, 후보 간격 2.4에 대한 0.10의 합이다. 출력 개수가 하나인 사례에서도 안전 통과 후보 7개와 점수 간격 0.7이 남는다. 이번 확인에서 관련 집중 테스트를 포함한 74개가 통과했다.

## 증거 단계와 검증하지 않은 사항

현재 증거 단계는 `IMPLEMENTED`다. 계산식과 오류 거부 규칙이 코드에 있고, API 계약과 JSON 증거가 같은 값을 보존한다. 증거의 연구 코드 커밋은 `94b0374a3599973ba5201a3cc751912f07bb146a`이며 현재 등록 경로와 차이가 없다. 이는 구현 재현성을 뒷받침하지만 운영 사용을 입증하지는 않는다.

0.05·0.10·0.20 같은 가중치는 임상 코호트에서 보정된 확률이 아니라 현재 제품 규칙이다. 따라서 0.45를 “추천이 45% 틀릴 확률”로 해석하면 안 된다. 누락 정보 질문이 실제 사용자에게 노출되었는지, 답변을 추가했을 때 의사결정 품질이 좋아졌는지, 등급 경계가 임상 위험과 일치하는지는 확인되지 않았다. 증거 파일은 `production_operation_proven=false`이므로 상위 단계 주장은 하지 않는다.
