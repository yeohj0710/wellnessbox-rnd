# OP-047 결정 불확실성과 추가 입력 조건을 정량화한다.

등록 증거 `wellnessbox-rnd/data/original_plan/evidence/op047_op048_decision_uncertainty_learned_fallback_smoke_v1.json`은 불확실성 점수의 구성 항목과 추가 질문을 함께 보존한다. 현재 코드는 이 값을 진단 확률이 아닌 “미해결 입력과 후보 순위 안정성” 점수로 제한하며, OP-047 단계는 `IMPLEMENTED`다.

## 불확실성을 숫자로 남기는 목적

추천이 나왔다는 사실만으로 입력이 충분하다고 볼 수 없다. 현재 약물이나 주요 증상이 비어 있거나 상위 두 후보의 점수가 거의 같다면, 같은 추천이라도 추가 정보를 먼저 받는 편이 안전하다. 반대로 막연히 “확실하지 않음”이라고만 쓰면 어떤 정보를 더 받아야 판단이 달라지는지 알 수 없다. 이 요구는 불확실성의 원인, 가중치, 사용자에게 물을 질문을 한 계산 안에 묶는다.

점수 이름도 해석 범위를 고정한다. 응답의 `score_scope`는 `unresolved_recommendation_inputs_and_ranking_stability_not_clinical_probability`다. 즉 0.45는 부작용 확률 45%나 추천 실패 확률 45%가 아니다. 누락된 입력과 후보 간 점수 차이를 정해진 규칙으로 합산한 값이다.

## 점수와 추가 질문을 계산하는 규칙

`wellnessbox-rnd/src/wellnessbox_rnd/orchestration/recommendation_service.py`는 누락 정보의 중요도를 낮음 0.05, 보통 0.10, 높음 0.20으로 바꾼다. 응답 상태가 `NEEDS_REVIEW`이면 0.20을 더하고, 차단 상태가 아닌데 선택 후보가 없으면 0.15를 더한다. 상위 두 후보의 선택 점수 차이가 1 미만이면 0.20, 3 미만이면 0.10, 5 미만이면 0.05를 더한다. 모든 항목의 합은 `raw_uncertainty_score`에 남고, 최종 점수는 1.0에서 상한을 둔다. 0.25 이하는 낮음, 0.50 이하는 보통, 그보다 크면 높음이다.

추가 입력 조건에는 코드와 중요도만 저장하지 않는다. 사용자가 답해야 할 질문과 그 정보가 필요한 이유도 함께 반환한다. `wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation.py`는 각 추가 입력 조건이 같은 코드의 불확실성 구성 항목과 정확히 대응하는지 확인한다. 상위 후보, 차순위 후보, 두 점수와 차이도 `CandidateRankingSnapshot`에 남긴다.

후보 점수 차이는 최종 출력 개수와 분리했다. 사용자가 상품 하나만 요청해도 추천 전에 계산한 전체 통과 후보 순위에서 상위 두 개를 비교한다. 출력 한 개만 보고 차순위 후보가 없다고 처리하면 불확실성을 실제보다 낮게 계산하기 때문이다.

## 경계값과 조작 실패를 확인한 결과

`wellnessbox-rnd/tests/test_decision_uncertainty_learned_fallback.py`는 출력 제한을 한 개로 낮춰도 후보 7개의 사전 순위와 0.7점 차이가 유지되는지 확인한다. 누락된 심혈관 정보 0.20, 주요 증상 0.10, 현재 복용 보충제 0.05도 각각 추가 질문과 연결된다. 후보 수를 임의로 줄이거나 총점을 바꾸거나 근거 없는 구성 항목을 추가하면 응답 재검증이 실패한다.

기준 증거에는 입력이 충분한 수면 사례가 기록돼 있다. 마그네슘 글리시네이트 68.0과 L-테아닌 67.5의 차이 0.5가 0.20점 불확실성으로 변환돼 낮음 구간이 됐다. 심혈관 정보와 증상, 현재 복용 보충제가 빠진 사례는 누락 점수 0.35와 후보 차이 점수 0.10을 더해 0.45, 보통 구간으로 계산됐다. 현재 관련 시험 묶음도 같은 규칙으로 통과했다.

## 현재 단계와 아직 모르는 것

OP-047은 계산식과 계약이 구현된 `IMPLEMENTED` 단계다. 점수 구간은 정책상 정한 값이며 실제 사용자 결과에 맞춰 보정한 확률 모델이 아니다. 추가 질문이 실제로 답변률을 높이는지, 어느 점수에서 추천을 보류해야 하는지, 이 값이 이상사례나 추천 변경과 어떤 상관이 있는지는 확인되지 않았다. 코드, 단위 시험과 smoke 증거를 조사했지만 운영 세션의 답변률과 결과 상관은 `확인되지 않음`이다. 기준 증거는 `production_operation_proven=false`다. 운영 단계로 올리려면 실제 세션에서 질문 제시, 답변 수집, 재계산, 추천 변경까지 같은 실행 이력으로 관측해야 한다.
