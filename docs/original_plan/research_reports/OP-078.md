# OP-078 약사 검토 작업 생성과 완료 사후조건을 저장한다.

## 무엇을 해결했는가

안전 검토나 모호한 후속 판단을 사람이 확인할 작업으로 남기는 요구를 구현했다. 검토 요청만 만들고 완료 결과를 바꿀 수 있게 두는 문제를 막기 위해, 작업 생성부터 결정 완료까지 같은 저장소에서 추적하고 완료 기록은 변경하지 못하게 했다.

## 어떻게 구현했는가

`PharmacistReviewService`는 이유 코드와 대상 실행을 묶어 검토 작업을 만든다. 완료 시 사후조건과 해시를 저장하고, 같은 결정을 다시 보내면 기존 결과를 되돌려준다. Phase 2 정책의 `request_safety_review`와 `hold_for_review`는 이 검토 경계로 이어질 상태를 명시한다.

## 무엇으로 확인했는가

등록된 검증 증거 `wellnessbox-rnd/data/original_plan/evidence/op077_op078_fail_closed_job_review_smoke_v1.json`은 실패한 작업마다 기존 검토 작업 1건이 연결되고 완료 기록이 불변임을 확인한다. 검토 품질이나 속도를 판정하는 테스트는 추가하지 않았다.

## 어디까지 믿을 수 있는가

검토 작업 저장과 중복 방지는 `IMPLEMENTED`다. Phase 3은 별도의 AI 초안 원장에 필수 provenance를 저장하고, 승인 전 자료를 학습·평가·추천·지식 경로에서 차단했다. `wellnessbox-rnd/data/original_plan/evidence/ai_draft_pharmacist_approval_v1.json`은 승인 1건, 수정 승인 1건, 반려 1건, 대기 1건으로 결정 경계와 차단 결과를 재현한다. 실제 약사가 검토한 운영 기록은 없으며 실제 검토는 H-003에서 진행한다.
