# OP-078 약사 검토 작업 생성과 완료 사후조건을 저장한다.

OP-078은 자동 처리가 멈춘 원인과 약사 검토의 완료 전제를 하나의 추적 가능한 기록으로 남기는 요구다. `wellnessbox-rnd/src/wellnessbox_rnd/interim/reviews.py`에는 검토 생성·완료 규칙이 있고 데이터베이스는 완료 행의 변경과 삭제를 막는다. 등록 스모크의 약국 식별자와 결정은 시험용 값이며, 운영 영수증에는 `review_tasks` 생성·완료가 0건이므로 실제 약사 검토를 주장할 수 없다. 직접 입증 단계는 `IMPLEMENTED`다.

## 검토 생성은 자동 실패의 provenance를 보존한다

검토가 필요하다는 상태만 남기면 어떤 업무와 어떤 안전 조건이 원인이었는지 재구성하기 어렵다. `PharmacistReviewService.create_in_transaction()`은 사용자, 정렬하고 중복을 제거한 이유 코드, 선택적인 `source_job_id`로 결정적 `review_id`를 만든다. 같은 실패를 다시 처리하면 같은 식별자를 반환하며, 기존 행의 의미가 다르면 검토를 조용히 재사용하지 않고 충돌로 멈춘다. provenance는 결과가 어디서 왔는지를 추적하는 정보이며 여기서는 원본 업무·실행·자료 분류·안전 이유를 뜻한다.

`review_tasks` 행에는 `agent_run_id`, `profile_id`, `source_kind`, `is_mock`, `urgency`, `reason_codes`, `source_job_id`, 생성 시각이 저장된다. `source_job_id`는 `workflow_jobs` 외래키여서 시간 초과나 오래된 근거로 취소된 정확한 업무까지 따라갈 수 있다. `wellnessbox-rnd/src/wellnessbox_rnd/interim/agent.py`의 중대한 이상사례 경로는 같은 서비스를 호출하되 `URGENT`와 사례 이유를 넣고, 일반 업무 안전 폐쇄는 `HIGH`로 구분한다.

## 완료 전에 다시 계산하는 사후조건

`PharmacistReviewDecisionV1`은 `pharmacy_id >= 1`, 비어 있지 않은 80자 이하 결정, 선택적인 1000자 이하 메모를 요구한다. 결정 문자열은 대문자로 정규화한다. `complete_review()`는 검토가 `OPEN`인지, 완료 시각이 생성 시각 이상인지, 이미 배정된 약국과 요청 약국이 같은지 확인한다. 다른 약국이면 `review_pharmacy_mismatch`, 과거 완료 시각이면 `review_completed_at_before_created_at`으로 저장을 거부한다.

원본 업무가 연결된 검토는 그 업무가 실제 `CANCELLED`인지 다시 읽는다. 중대한 이상사례 검토라면 해결되지 않은 `ESCALATED` 보류와 실행 원장의 계획 중단 이벤트가 모두 있어야 한다. 조건을 통과하면 결정 내용, 약국 식별자, 완료 시각, 계산된 사후조건 JSON과 그 SHA-256을 같은 행에 저장한다. 해시는 JSON 키를 일정한 순서로 직렬화한 결과에 대해 계산하므로 이후 동일 내용을 독립적으로 대조할 수 있다.

`wellnessbox-rnd/src/wellnessbox_rnd/interim/store.py`에는 완료된 `review_tasks`의 `UPDATE`와 `DELETE`를 각각 `completed_review_immutable`로 막는 트리거가 있다. 서비스도 두 번째 완료 요청에 `review_already_completed`를 반환한다. 응용 계층의 검사를 우회해 SQL을 직접 실행해도 완료 결과가 덮어써지거나 삭제되지 않는 이중 방어다.

## API가 검토 큐와 결정 서비스를 공유한다

`wellnessbox-rnd/apps/inference_api/routes/interim.py`의 검토 목록 경로는 배정되지 않은 행이나 요청 약국에 배정된 행만 반환한다. 결정 경로는 별도 SQL 갱신을 만들지 않고 `PharmacistReviewService.complete_review()`를 호출한다. 따라서 API를 거친 결정에도 원본 업무 취소, 이상사례 보류, 계획 중단, 시간 순서, 약국 일치 규칙이 동일하게 적용된다.

검토 큐와 AI 추천 초안 검토는 다른 저장 계약이다. 이후 추가된 `ai_drafts` 표와 초안 검토 API는 모델 생성 결과의 승인·거절을 기록한다. OP-078의 `review_tasks`는 안전 실패나 중대한 이상사례에 대한 약사 작업이다. 두 표에 “review”라는 말이 들어간다고 해서 `ai_drafts_reviewed` 수를 이 요구의 검토 완료로 바꿔 읽을 수 없다.

## 구현 연대기가 불변성을 강화한 지점

커밋 `c35abf`의 중대한 이상사례 처리에는 긴급 검토 생성이 처음 연결됐다. 커밋 `bd2429`는 이를 일반적인 `PharmacistReviewService`와 `review_tasks` provenance·완료 사후조건 스키마로 확장했다. 시간 초과, 동의 상실, 오래된 근거가 자동 재실행 대신 같은 트랜잭션에서 검토를 열도록 바뀐 것도 이 시점이다.

커밋 `932358`은 세 가지 미완성 경계를 닫았다. 완료 시각이 생성 시각보다 이른 요청을 거부했고, 완료 행을 직접 수정하거나 삭제하지 못하게 데이터베이스 트리거를 추가했으며, 대문자가 포함된 사례 ID의 재전송에서도 기존 검토 연결이 유지되도록 이유 계산을 안정화했다. 서비스의 두 번째 결정 거부만으로는 직접 SQL 변경을 막지 못하므로 트리거는 더 이른 공통 저장 계층에서 불변식을 고친 변경이다.

커밋 `3f67d0`은 별도의 AI 초안 검토 표와 API를 추가했고, 커밋 `651984` 이후 로컬 실제 세션에서 AI 초안 검토 증가가 기록됐다. 이 후속 기능은 OP-078 약사 안전 검토를 대체하지 않는다. 저장소에서 완료 검토가 실제로 수정된 사고 기록이나 약사의 판단 오류 기록은 확인되지 않았으며, 수정 이력은 diff와 회귀 시험이 다루는 기술적 결함 범위로 제한한다.

## 테스트가 확인하는 생성·완료·불변 조건

`wellnessbox-rnd/tests/test_interim_reviews.py`의 `test_review_schema_persists_provenance_and_postcondition_columns`는 스키마에 원본 업무, 약국, 결정, 사후조건 JSON·SHA와 완료 시각 열이 있는지 확인한다. `test_job_failure_review_is_deterministic_and_completion_is_immutable`은 동일 실패의 검토 ID가 같고, 취소 업무를 전제로 완료한 뒤 SQL `UPDATE`와 `DELETE`가 모두 `completed_review_immutable`로 실패하는지 단언한다.

`test_review_completion_rejects_source_job_that_is_not_cancelled`는 원본 업무가 아직 실행 가능한 상태면 결정을 기록하지 않는지 검사한다. `test_review_completion_rejects_time_before_creation`은 시각 순서가 잘못된 요청 뒤 검토가 계속 `OPEN`인지 본다. 이 두 시험은 결정 문자열이 들어왔다는 사실보다 완료 사후조건이 실제 저장 상태와 맞는지를 우선한다.

`wellnessbox-rnd/tests/test_interim_agent.py`는 안전 실패와 중대한 이상사례에서 검토가 각각 결정적으로 생성되고 재요청해도 연결이 유지되는지를 다룬다. `wellnessbox-rnd/tests/test_interim_api.py`의 `test_serious_ae_flow_creates_review_and_review_decision_is_immutable`은 API를 통해 중대 사례 검토를 완료하고 `serious_hold_active=true`, `plan_stop_recorded=true`, 검증 가능한 사후조건 SHA가 저장되는지 확인한다. 두 번째 결정 요청은 409가 되어야 한다.

## 스모크 결정은 약사의 임상 판단이 아니다

`wellnessbox-rnd/scripts/run_fail_closed_job_pharmacist_review_smoke.py`는 임시 SQLite에서 시간 초과로 취소된 업무의 검토를 만든다. 출력 `wellnessbox-rnd/data/original_plan/evidence/op077_op078_fail_closed_job_review_smoke_v1.json`에는 `pharmacy_id=7`, 결정 `acknowledged`, 상태 `COMPLETED`, 원본 업무 `CANCELLED`, `decision_recorded=true`가 저장돼 있다. 스크립트가 사후조건 JSON을 다시 직렬화해 SHA 일치를 확인하고, 두 번째 결정에서 `review_already_completed`를 받는다.

여기서 `pharmacy_id=7`은 스크립트가 넣은 합성 식별자이고 `acknowledged`는 저장 계약을 시험하는 문자열이다. 실제 면허 약사가 사례를 검토했거나 결정이 의약학적으로 적절했다는 증거가 아니다. JSON도 `op078_proven_stage=IMPLEMENTED`, `production_pharmacist_review_proven=false`를 명시한다.

생성 시점은 `source_commit=24d82df`이며 기록된 소스 묶음 해시 `3038be…`은 현재 대응 파일에서 계산한 `781e88…`과 다르다. 후속 불변 트리거와 별도 AI 초안 기능이 반영된 현행 파일을 이 과거 스모크가 실행했다고 볼 수 없으므로, 현재 평가는 소스·테스트·git diff를 함께 사용했다.

## 운영 자료와 현재 단계의 결론

manifest의 운영 경로 `wellnessbox-rnd/data/original_plan/final_session/operational_evidence/OP-078.json`은 `executed_paths`에 `pharmacist_review`를 포함하지만 데이터베이스 증가량은 `review_tasks=0`, `review_tasks_completed=0`이다. 같은 영수증의 `ai_drafts +1`, `ai_drafts_reviewed +1`은 별도 표의 추천 초안 검토 결과다. 이 수치를 OP-078 완료 증거로 전환하면 저장 대상을 혼동하게 된다.

현재 판단은 `IMPLEMENTED`다. 검토의 결정적 생성, 원본 업무 연결, 완료 전 사후조건, 해시, 완료 행 불변성은 로컬 코드와 시험에서 확인됐다. 실제 약사가 검토 큐를 열고 권한을 증명한 기록, 배정·재배정 절차, 임상 판단의 근거, 운영 처리 시간과 미처리 건수는 확인되지 않았다. `OPERATED`로 인정하려면 가명 검토 ID, 권한을 확인한 약국·약사 주체, 원본 업무 상태, 완료 전제, 결정 시각, 사후조건 SHA를 동일 운영 사건에 연결해야 한다.
