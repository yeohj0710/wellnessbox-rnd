# OP-039 hard false negative 0을 고위험 frozen eval로 검증한다.

## 요구사항이 뜻하는 실패

고위험 고정 평가(frozen eval)는 사례와 정답을 평가 전에 확정하고, 구현 결과를 본 뒤 유리하게 바꾸지 않는 시험이다. 이 요구사항에서 hard false negative는 반드시 차단해야 하는 사례를 최종 응답이 차단하지 못한 경우다. 평가기는 최종 상태가 차단이 아니거나, 안전 상태가 차단이 아니거나, 추천 목록이 비어 있지 않거나, 기대한 차단 규칙이 하나도 일치하지 않으면 hard false negative로 센다. 실행 예외는 안전 성공으로 처리하지 않고 평가 오류로 따로 집계한 뒤 전체 평가를 실패시킨다.

목표 수치 0은 내부 작성 사례에서만 오류가 없다는 뜻이 아니다. 구현팀과 독립된 기관이 승인된 범위·라벨링 절차로 만든 고위험 데이터세트에서 hard false negative가 한 건도 없어야 한다. 그래서 단위 시험이나 합성 데이터 통과만으로 `EXTERNAL` 단계를 주장할 수 없다.

## 외부 자료를 받기 전에 고정한 계약

`wellnessbox-rnd/src/wellnessbox_rnd/evals/external_high_risk_safety.py`는 외부 사례, 독립성 확인서, 검증 영수증, 평가 범위 승인서, 두 신뢰 목록의 형식을 엄격하게 검사한다. 데이터세트·확인서·영수증·범위 문서의 해시가 고정값과 일치해야 하고, 범위 승인은 라벨 작성 전에 완료되어야 한다. 제출 기관은 구현팀과 독립적이어야 하며 임시 조직명이나 빈 자격 정보를 사용할 수 없다. 사례 수와 위험군별 최소 표본도 승인 계약을 충족해야 한다.

평가 스크립트는 내부 합성 자료 위치인 `/data/frozen_eval/`과 `/data/synthetic/`를 외부 데이터세트로 받지 않는다. 또한 실행 코드의 Git 식별 정보와 승인된 기준을 대조하도록 설계되어 있다. 이 계약은 결과가 나온 뒤 데이터나 승인 조건을 바꾸는 일을 막고, 잘못된 차단 규칙이 우연히 전체 차단 상태만 만든 경우도 합격시키지 않는다. 계약 설명은 `wellnessbox-rnd/docs/original_plan/OP039_EXTERNAL_HIGH_RISK_EVAL_CONTRACT.md`에 정리되어 있다.

## 내부 시험이 증명한 범위

`wellnessbox-rnd/tests/test_external_high_risk_safety_eval.py`는 임시 평가 묶음과 대체 신뢰 목록을 사용해 해시 변조, 독립성 부족, 승인 시점 오류, 차단 누락과 평가 예외를 거부하는지 확인한다. 이 시험은 외부 검증 절차를 실행할 코드와 실패 조건이 구현됐다는 근거다. 그러나 시험 안에서 만든 기관과 서명 정보는 실제 독립 기관의 검증 자료가 아니므로 목표 수치 0의 외부 증거로 사용할 수 없다.

외부 검토 패키지도 약사 등 독립 검토자가 데이터와 라벨을 제공해야 한다고 명시한다. 현재 입력 계약에는 독립 데이터세트, 독립 확인서, 검증 영수증, 승인된 범위 보고서가 필요한 항목으로 남아 있다. 즉 평가 장치는 준비됐지만 평가할 자격 있는 외부 묶음은 아직 등록되지 않았다.

## 등록 자료에서 확인된 미충족 조건

등록된 외부 검증 파일 `wellnessbox-rnd/data/original_plan/final_session/external_validation/op039_external_validation.json`의 검토 조직은 “웰니스박스 TIPS 과제 참여연구원”이고 관계는 `project_co_researcher`다. 파일 자체가 구현팀과의 독립성을 `false`로 기록한다. 면허 번호도 수집되지 않았고 자격 근거는 프로젝트 소유자 확인으로 적혀 있다. 이 자료는 검토 기록일 수는 있지만 독립 외부 검증의 필수 조건을 충족하지 않는다.

두 기준 파일 `wellnessbox-rnd/data/original_plan/contracts/op039_external_coverage_trust_roots_v1.json`과 `wellnessbox-rnd/data/original_plan/contracts/op039_external_attestation_trust_roots_v1.json`도 승인 기관, 승인자, 승인 범위 목록이 비어 있다. 계약 문서는 이 상태에서는 외부 PASS가 불가능하다고 명시한다. 확인한 등록 경로에서는 독립 데이터세트와 승인된 범위 보고서도 찾지 못했다.

## 최종 단계와 필요한 다음 증거

현재 단계는 **IMPLEMENTED/PARTIAL**이다. 외부 고위험 평가 계약, 실행기와 실패 검사가 구현된 점은 확인됐다. 반면 요구사항 명세의 `EXTERNAL` 표시는 현재 등록 증거로 뒷받침되지 않는다. 독립 기관이 평가 범위를 먼저 승인하고, 그 범위에 맞춘 동결 데이터와 라벨을 제공한 뒤, 승인된 신뢰 목록과 서명된 검증 영수증으로 평가를 실행해야 한다. 그 실행에서 hard false negative 0과 평가 오류 0을 함께 확인하기 전에는 외부 검증 완료로 올릴 수 없다.
