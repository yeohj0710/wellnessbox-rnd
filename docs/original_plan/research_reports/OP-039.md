# OP-039 hard false negative 0을 고위험 frozen eval로 검증한다.

## 요구사항이 뜻하는 검증 수준

OP-039의 목표는 고위험 사례에서 차단해야 할 결과를 통과시키거나, 차단했더라도 필수 차단 사유를 빠뜨린 hard false negative가 0인지 독립 자료로 확인하는 것이다. 여기서 frozen eval은 평가 사례와 정답, 적용 범위를 시스템 결과를 본 뒤 바꾸지 못하도록 미리 고정한 평가를 뜻한다. 내부 작성자가 만든 사례를 내부 참여자가 확인한 결과만으로는 EXTERNAL 단계가 되지 않는다.

정확한 manifest 위치는 data/original_plan/requirements_manifest_v1.json이다. manifest는 OP-039의 required_stage와 claimed_stage를 모두 EXTERNAL로 적었다. 그러나 현재 등록 파일을 직접 확인하면 외부 입력과 승인 정보가 비어 있어, 이 주장을 그대로 유지할 수 없다.

## 평가기가 구현한 차단 조건

src/wellnessbox_rnd/evals/external_high_risk_safety.py는 평가 사례, 시스템 결과, 외부 평가자 확인서, 고정된 평가 범위 계약을 서로 연결한다. 예상 상태가 BLOCKED 또는 예상 행동이 STOP_AND_ESCALATE인데 시스템이 통과시키면 hard false negative로 센다. 시스템이 차단했더라도 expected_rule_ids에 적힌 필수 규칙이 matched_rule_ids에서 빠지면 같은 오류로 계산한다. 사례 해시와 평가 범위 해시가 다르거나, 결과 파일이 저장소 내부 자료를 외부 데이터처럼 가리키면 평가를 거부한다.

scripts/run_external_high_risk_safety_eval.py는 이 검증기를 명령행에서 실행하는 진입점이다. docs/original_plan/OP039_EXTERNAL_HIGH_RISK_EVAL_CONTRACT.md는 외부 평가자가 준비해야 할 사례 파일, 평가 범위, 확인서, 승인 기록, 해시와 고정 시각을 정의한다. 구현의 핵심은 “0”을 출력하는 것이 아니라, 승인되지 않은 자료로 0을 만들지 못하게 하는 데 있다.

## 실패하도록 만든 경계와 회귀 테스트

tests/test_external_high_risk_safety_eval.py의 test_verified_external_eval_reports_zero_hard_false_negatives는 완전한 승인 자료가 있을 때 0을 계산하는 정상 사례다. test_wrong_blocking_reason_is_a_hard_false_negative와 test_non_blocked_decision_is_a_hard_false_negative는 잘못된 차단 사유와 미차단 결과를 각각 hard false negative로 잡는다.

외부성 위조 방지 테스트도 구체적이다. test_eval_rejects_unapproved_attestation, test_eval_rejects_coverage_protocol_not_pinned_by_repository, test_eval_rejects_coverage_protocol_frozen_after_attestation, test_eval_rejects_frozen_coverage_shortfall은 승인과 고정 순서를 검사한다. test_eval_rejects_hash_mismatch, test_eval_rejects_non_external_attestation, test_eval_rejects_repository_internal_dataset_path는 바뀐 자료, 내부 평가자, 저장소 내부 사례를 외부 근거로 인정하지 않는다.

이 테스트들은 이전처럼 내부 테스트가 통과했다는 사실을 독립 검증으로 잘못 확대하는 문제를 막는다. 다만 테스트가 검증기의 동작을 증명할 뿐, 실제 외부 기관이 작성한 자료를 대신하지는 않는다.

## manifest에 등록된 파일을 대조한 결과

등록 구현 파일 세 개는 src/wellnessbox_rnd/evals/external_high_risk_safety.py, scripts/run_external_high_risk_safety_eval.py, docs/original_plan/OP039_EXTERNAL_HIGH_RISK_EVAL_CONTRACT.md다. 원문 등록 경로 wellnessbox-rnd/src/wellnessbox_rnd/evals/external_high_risk_safety.py도 동일한 파일을 가리킨다. 등록 테스트·검토 파일은 tests/test_external_high_risk_safety_eval.py와 data/original_plan/final_session/external_validation/op039_external_validation.json이다. 다섯 파일은 모두 존재하며 각각 평가기, 실행 명령, 제출 계약, 회귀 검사, 검토 결과라는 설명과 맞는다.

외부 입력을 대체하기 전까지 차단 상태를 명시하는 계약은 data/original_plan/contracts/op039_external_coverage_trust_roots_v1.json과 data/original_plan/contracts/op039_external_attestation_trust_roots_v1.json이다. 두 파일도 존재하지만 approved_coverage_protocols, approved_attestations, approval_record_references가 모두 빈 배열이다. 즉 파일의 존재는 EXTERNAL 증거가 아니라 아직 승인된 외부 신뢰 기준이 없다는 증거다.

## 현재 외부 검토 파일이 충족하지 못한 조건

data/original_plan/final_session/external_validation/op039_external_validation.json은 임신, 수유, 중증 신장 위험, 간 위험, 혈색소침착증, 와파린 상호작용, 비타민 C 상한, 응급 최종 차단 등 10개 판정을 valid로 기록한다. 그러나 reviewer.relationship_to_project는 project_co_researcher이고 independent_of_implementation_team은 false다. organization은 웰니스박스 TIPS 과제 참여연구원이며 pharmacist_license_id는 not_collected, credential_verification_method는 project_owner_attestation이다.

이 파일의 schema_version은 op039_external_review_result_v1이지만, 저장된 속성 자체가 독립 외부 검토가 아님을 명시한다. 또한 승인된 외부 평가 범위, 독립 사례 파일, 외부 확인서와 승인 기록이 trust-root 계약에 등록되지 않았다. 따라서 10개 내부 검토 판정이 타당하더라도 “고위험 전체 범위에서 hard false negative 0”이라는 외부 결론을 낼 수 없다.

## 현재 단계와 교체해야 할 근거

현재 근거 단계는 IMPLEMENTED다. 외부 평가 자료를 검증하는 코드, 명령, 계약, 부정 사례 회귀 테스트는 구현되어 있다. 반면 manifest가 주장하는 EXTERNAL 단계는 충족하지 못했다. INTEGRATED나 OPERATED 단계도 이 요구사항의 핵심인 독립성 부족을 보완하지 않는다.

EXTERNAL로 올리려면 구현팀과 독립된 평가자의 자격 확인, 저장소 밖에서 받은 고정 사례와 정답, 사전 승인된 coverage protocol, 승인된 attestation, 각 승인 기록의 참조값을 두 trust-root 파일에 등록해야 한다. 그 뒤 현재 평가기를 실행해 사례 해시·범위·시각·필수 차단 사유가 모두 맞고 hard false negative가 0임을 새 결과로 남겨야 한다. 이번 검토에서는 외부 자료가 없었으므로 평가기를 재실행하지 않았으며, 현재 확인할 수 없는 외부 성능을 추정하지 않았다.
