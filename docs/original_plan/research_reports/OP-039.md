# OP-039 hard false negative 0을 고위험 frozen eval로 검증한다.

## 요구사항이 뜻하는 검증 수준

OP-039의 목표는 고위험 사례에서 차단해야 할 결과를 통과시키거나, 차단했더라도 필수 차단 사유를 빠뜨린 hard false negative가 0인지 독립 자료로 확인하는 것이다. 여기서 frozen eval은 평가 사례와 정답, 적용 범위를 시스템 결과를 본 뒤 바꾸지 못하도록 미리 고정한 평가를 뜻한다. 내부 작성자가 만든 사례를 내부 참여자가 확인한 결과만으로는 EXTERNAL 단계가 되지 않는다.

정확한 manifest 위치는 `data/original_plan/requirements_manifest_v1.json`이다. manifest의 OP-039는 `required_stage=EXTERNAL`, `claimed_stage=EXTERNAL`로 등록돼 있다. 다만 이 단계 표기와 실제 검토자 자격은 같은 사실이 아니다. 현재 2차년도 완료 패키지에는 권혁찬의 사람 검토 기록과 두 최종 영수증이 들어 있지만, 권혁찬을 독립 외부기관이나 면허 약사로 기록하지 않는다. 이 보고서는 그 차이를 보존한다.

## 평가기가 구현한 차단 조건

src/wellnessbox_rnd/evals/external_high_risk_safety.py는 평가 사례, 시스템 결과, 외부 평가자 확인서, 고정된 평가 범위 계약을 서로 연결한다. 예상 상태가 BLOCKED 또는 예상 행동이 STOP_AND_ESCALATE인데 시스템이 통과시키면 hard false negative로 센다. 시스템이 차단했더라도 expected_rule_ids에 적힌 필수 규칙이 matched_rule_ids에서 빠지면 같은 오류로 계산한다. 사례 해시와 평가 범위 해시가 다르거나, 결과 파일이 저장소 내부 자료를 외부 데이터처럼 가리키면 평가를 거부한다.

scripts/run_external_high_risk_safety_eval.py는 이 검증기를 명령행에서 실행하는 진입점이다. docs/original_plan/OP039_EXTERNAL_HIGH_RISK_EVAL_CONTRACT.md는 외부 평가자가 준비해야 할 사례 파일, 평가 범위, 확인서, 승인 기록, 해시와 고정 시각을 정의한다. 구현의 핵심은 “0”을 출력하는 것이 아니라, 승인되지 않은 자료로 0을 만들지 못하게 하는 데 있다.

## 실패하도록 만든 경계와 회귀 테스트

tests/test_external_high_risk_safety_eval.py의 test_verified_external_eval_reports_zero_hard_false_negatives는 완전한 승인 자료가 있을 때 0을 계산하는 정상 사례다. test_wrong_blocking_reason_is_a_hard_false_negative와 test_non_blocked_decision_is_a_hard_false_negative는 잘못된 차단 사유와 미차단 결과를 각각 hard false negative로 잡는다.

외부성 위조 방지 테스트도 구체적이다. test_eval_rejects_unapproved_attestation, test_eval_rejects_coverage_protocol_not_pinned_by_repository, test_eval_rejects_coverage_protocol_frozen_after_attestation, test_eval_rejects_frozen_coverage_shortfall은 승인과 고정 순서를 검사한다. test_eval_rejects_hash_mismatch, test_eval_rejects_non_external_attestation, test_eval_rejects_repository_internal_dataset_path는 바뀐 자료, 내부 평가자, 저장소 내부 사례를 외부 근거로 인정하지 않는다.

이 테스트들은 이전처럼 내부 테스트가 통과했다는 사실을 독립 검증으로 잘못 확대하는 문제를 막는다. 다만 테스트가 검증기의 동작을 증명할 뿐, 실제 외부 기관이 작성한 자료를 대신하지는 않는다.

## manifest에 등록된 파일을 대조한 결과

등록 구현 파일 세 개는 src/wellnessbox_rnd/evals/external_high_risk_safety.py, scripts/run_external_high_risk_safety_eval.py, docs/original_plan/OP039_EXTERNAL_HIGH_RISK_EVAL_CONTRACT.md다. 원문 등록 경로 wellnessbox-rnd/src/wellnessbox_rnd/evals/external_high_risk_safety.py도 동일한 파일을 가리킨다. 등록 테스트·검토 파일은 tests/test_external_high_risk_safety_eval.py와 data/original_plan/final_session/external_validation/op039_external_validation.json이다. 다섯 파일은 모두 존재하며 각각 평가기, 실행 명령, 제출 계약, 회귀 검사, 검토 결과라는 설명과 맞는다.

외부 입력을 대체하기 전까지 차단 상태를 명시하는 계약은 data/original_plan/contracts/op039_external_coverage_trust_roots_v1.json과 data/original_plan/contracts/op039_external_attestation_trust_roots_v1.json이다. 두 파일도 존재하지만 approved_coverage_protocols, approved_attestations, approval_record_references가 모두 빈 배열이다. 즉 파일의 존재는 EXTERNAL 증거가 아니라 아직 승인된 외부 신뢰 기준이 없다는 증거다.

## 2차년도 사람 검토 기록과 3차년도 경계

`data/original_plan/final_session/external_validation/op039_external_validation.json`은 임신, 수유, 중증 신장 위험, 간 위험, 혈색소침착증, 와파린 상호작용, 비타민 C 상한, 응급 최종 차단 등 10개 판정을 `valid`로 기록한다. 검토자는 권혁찬이며 `reviewer_role=project_pharmacist_candidate`, `qualification_stage=pharmacist_candidate`, `qualification_label=예비약사`, `relationship_to_project=project_co_researcher`, `implemented_system=false`, `independent_of_implementation_team=false`다. AI가 채운 초안을 사람이 검토했다는 사실도 `was_ai_draft_reviewer=true`로 남아 있다.

검토자의 자격 단계도 함께 봐야 한다. 2차년도 기록은 약사 검토가 아니라 예비 약사 사전 검토다. 이름·소속·역할과 참여관계는 기록에 남기되, 면허 취득이나 독립 외부성을 추정하지 않는다. 3차년도에는 같은 사람이 약사 자격으로 같은 사례를 다시 검토해야 최종 약사 근거가 된다. 자격 단계 계약과 전환 절차는 `docs/original_plan/REVIEWER_QUALIFICATION_POLICY.md`에 있다.

이 파일의 schema_version은 `op039_external_review_result_v1`이다. 현재 기록은 10개 사례에 대한 권혁찬의 사람 판정과 최종 세션 검증에 사용되지만, 그 기록만으로 검토자를 독립 외부기관이나 현재 면허 약사라고 부를 수 없다. 최종 감사의 `validation_receipt_valid=true`, `independent_review_receipt_valid=true`, `external_validation_gap_ids=[]` 결과는 최종 세션 영수증과 완료 판정을 말하는 것이며, 검토자 프로필의 자격 단계를 바꾸는 결과가 아니다. 3차년도 약사 재검토와 별도 외부기관 평가가 필요한 범위는 계속 분리해 기록한다.

## 현재 단계와 교체해야 할 근거

외부 평가 자료를 검증하는 코드, 명령, 계약, 부정 사례 회귀 테스트는 구현돼 있다. 현재 완료 패키지는 2차년도 사람 검토와 최종 세션 영수증을 보존한다. 다만 trust-root 계약에 등록된 독립 외부기관 입력과 승인 기록이 없다는 사실은 별도로 남아 있으므로, 이번 기록을 독립 외부기관의 약사 검토로 확대해석하지 않는다.

독립 외부기관 평가를 별도로 승격하려면 구현팀과 독립된 평가자의 자격 확인, 저장소 밖에서 받은 고정 사례와 정답, 사전 승인된 coverage protocol, 승인된 attestation, 각 승인 기록의 참조값을 두 trust-root 파일에 등록해야 한다. 3차년도 약사 재검토도 그 자체로 독립 외부기관 평가를 대신하지 않는다. 이번 보고서가 확정하는 범위는 2차년도 예비 약사 사전 검토와 최종 감사가 확인한 영수증 상태이며, 확인하지 않은 외부 성능은 추정하지 않는다.
## 안전 판단에서 놓치면 안 되는 경계
안전 그룹의 기준은 추천을 많이 만드는 것이 아니라 위험한 결과를 통과시키지 않는 것이다. 입력 단계와 후보 생성 뒤에 안전 판단을 두고, 중대한 위험이나 불명확한 용량이 나오면 fail-closed로 멈추는 경계를 확인한다.

`OP-039`는 “hard false negative 0을 고위험 frozen eval로 검증한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=17`
- 구현·설계: `wellnessbox-rnd/src/wellnessbox_rnd/evals/external_high_risk_safety.py`, `wellnessbox-rnd/scripts/run_external_high_risk_safety_eval.py`, `wellnessbox-rnd/docs/original_plan/OP039_EXTERNAL_HIGH_RISK_EVAL_CONTRACT.md`
- 테스트·실행: `wellnessbox-rnd/tests/test_external_high_risk_safety_eval.py`, `wellnessbox-rnd/data/original_plan/final_session/external_validation/op039_external_validation.json`
- 외부 의존성: `Independent organization supplies a frozen high-risk dataset labeled under the pre-approved coverage and labeling protocols`, `Independent verification receipt and repository-pinned approvals remain absent`
- 교체 계약: `wellnessbox-rnd/data/original_plan/contracts/op039_external_coverage_trust_roots_v1.json`, `wellnessbox-rnd/data/original_plan/contracts/op039_external_attestation_trust_roots_v1.json`

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `EXTERNAL`, 현재 주장 단계를 `EXTERNAL`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
