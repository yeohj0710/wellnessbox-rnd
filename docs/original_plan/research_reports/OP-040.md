# OP-040 프로덕션 추천 경로에서 안전 엔진의 최종 차단 권한을 통합 검증한다.

## 안전 엔진이 마지막 결정을 가져야 하는 이유

추천 모델이 유용한 후보를 만들더라도 응급 증상, 금기, 상호작용을 발견한 안전 엔진이 최종 응답을 차단할 수 있어야 한다. 모델 호출 전 검사만으로는 충분하지 않다. 모델이 새 성분을 반환하거나 서비스 계층이 식별자를 변환하는 과정에서 위험이 다시 생길 수 있기 때문이다. 이 요구사항은 R&D API의 판정이 서비스 응답까지 유지되고, 중간 계층이 차단 결과를 추천으로 되돌리지 못하도록 하는 통합 경계를 확인한다.

R&D 안전 계층은 `PASS`, `WARN`, `BLOCK`, `STOP` 순서로 더 강한 조치를 선택한다. 예를 들어 흉통 같은 응급 증상은 `SAFE-EMERGENCY-001`과 `STOP_AND_ESCALATE`를 만든다. 차단이나 중단이 하나라도 있으면 추천 목록은 비어 있어야 한다. 이 불변 조건은 단순 상태 문자열이 아니라 최종 응답의 조치, 규칙 ID, 추천 개수까지 함께 묶는다.

## R&D와 서비스 경계에서 차단을 보존한 방식

`wellnessbox-rnd/apps/inference_api/routes/interim.py`는 저장된 프로필, 현재 요청, 두 입력을 합친 값에 대해 모델 호출 전에 안전 판정을 실행한다. 강제 차단이 없을 때만 모델을 부르고, 모델이 낸 성분을 포함해 다시 안전 판정을 한다. 두 번째 판정이 위험을 찾으면 모델 결과를 폐기하고 차단 응답과 안전 제약을 반환한다. 이 구조는 모델이 안전 엔진보다 뒤에서 최종 결정을 덮어쓰는 일을 막는다.

서비스의 `wellnessbox/app/api/tips/route.ts`는 R&D 응답을 받은 뒤 `wellnessbox/lib/server/wb-rnd-interim-safety-authority.ts`로 최종 권한 계약을 검사한다. 안전 상태와 조치가 모순되거나 차단 응답에 추천이 남아 있으면 정상 응답으로 전달하지 않는다. 성분 식별자를 서비스 값으로 바꾸지 못한 경우와 R&D 응답 계약 자체가 잘못된 경우에도 HTTP 502와 차단 상태, 빈 추천 목록으로 실패한다. 따라서 서비스 계층 오류가 안전 우회로 바뀌지 않는다.

## 통합 검증에서 확인한 경로

기준 스모크 증거 `wellnessbox-rnd/data/original_plan/evidence/op040_final_safety_authority_integration_smoke_v1.json`은 로컬 Uvicorn 서버를 실제로 띄우고 Node 서비스 경로 처리기를 통해 요청을 보낸 기록이다. 응급 사례는 HTTP 응답에서 `BLOCKED`, `STOP_AND_ESCALATE`, `SAFE-EMERGENCY-001`, 추천 0건으로 끝났다. 정상 후보는 식별자 변환 경로를 통과했고, 변환되지 않는 성분과 잘못된 응답 계약은 각각 502 차단 응답으로 끝났다.

이 검증은 R&D 함수 하나만 호출한 단위 시험이 아니다. HTTP 경계와 서비스 라우트, 안전 권한 검사까지 통과하므로 두 저장소를 잇는 통합 증거다. 다만 증거 파일은 실행 환경을 localhost로 기록하며 `production_operation_proven`을 `false`로 둔다. 또 당시 성분 변환표 버전은 `2026-07-16.1`이므로 현재 변환표 버전에 대한 스모크를 새로 발행해야 현재 배포 후보 전체와 정확히 일치한다.

## 운영 증거의 범위와 완료 단계

운영 영수증 `wellnessbox-rnd/data/original_plan/final_session/operational_evidence/OP-040.json`은 `wellnessbox-local-research-pc`에서 실행한 실제 데이터 분류의 추천 세션을 기록한다. 추천 실행과 항목 증가분이 남아 있고 OP-040이 적용 범위에 포함되며, 영수증에는 Ed25519 서명이 붙어 있다. 이 자료는 서명된 로컬 운영 세션에서 안전 경로가 실행됐다는 근거다.

따라서 현재 완료 단계는 **OPERATED(로컬 연구 PC 범위)**로 판단한다. 이 표기는 공개 프로덕션 서비스에서 장기간 운영됐다는 뜻이 아니다. 실제 서비스 배포 식별자, 프로덕션 트래픽에서 발생한 차단 로그, 최신 성분 변환표로 재생성한 통합 스모크는 확인되지 않았다. 요구사항 제목의 “프로덕션 추천 경로”를 완전히 충족했다고 주장하려면 배포 환경에서 같은 불변 조건을 관찰한 증거가 추가되어야 한다.
