# OP-116 프로덕션 배포 후 R&D health와 WellnessBox alias를 확인한다.

## 결론

OP-116은 `INTEGRATED`까지 입증했으며 필수 단계 `OPERATED`에는 도달하지 않았다. R&D의 실제 로컬 프로세스 `/health`가 배포 계약 상태 `READY_FOR_PROVIDER_DEPLOYMENT`를 반환했고, WellnessBox의 `/api/internal/rnd/health` alias가 upstream `/health`를 호출해 제한된 상태 문서로 변환하는 동작을 검증했다. 프로덕션 배포와 프로덕션 트래픽은 승인도 증거도 없으므로 완료로 표시하지 않는다.

## alias 계약

WellnessBox route는 GET `/api/internal/rnd/health`를 제공한다. route handler는 `getWbRndHealthAlias`만 호출하고 JSON 응답 상태를 전달한다. 서버 함수는 기존 `resolveWbRndEnvironmentContract`에서 base URL, 활성화 여부, timeout을 읽는다. 따라서 추천 API와 health alias가 서로 다른 환경 해석 규칙을 만들지 않는다.

정상 upstream 응답은 `status=ok`, 고정 alias `wellnessbox-rnd`, upstream 상태와 환경, 배포 계약 준비 여부만 반환한다. 내부 토큰은 health GET에 보내지 않으며 응답에도 포함하지 않는다. 연동 비활성 상태와 upstream 장애는 모두 HTTP 503으로 fail closed한다. 두 상태는 각각 `disabled`와 `unavailable`로 구분해 운영자가 설정 누락과 실제 장애를 구별할 수 있다.

## 실제로 검증한 범위

R&D smoke는 임시 포트에서 FastAPI 프로세스를 시작하고 `/health`를 실제 HTTP로 호출했다. health 응답의 endpoint inventory에는 필수 API family 5개가 모두 포함됐다. 프로세스를 다시 시작한 뒤에도 배포 계약과 영속 데이터가 유지됐다. WellnessBox QA는 임시 HTTP upstream을 열어 `/health` 요청 경로, 정상 200 응답 변환, 배포 준비 플래그, 비활성 503을 검사했다. TypeScript 타입 검사와 Next.js 프로덕션 빌드는 route가 제품 빌드에 포함되는지 확인했다.

## 증명하지 않은 범위

로컬 임시 upstream은 실제 production provider가 아니다. Vercel 환경 변수 등록, production DNS·TLS, 실제 R&D 배포 ID, 운영 데이터베이스, 외부 네트워크 경계, 프로덕션 health 호출 시각을 관측하지 않았다. 따라서 `production_deployment_proven=false`, `production_traffic_proven=false`를 canonical evidence에 명시했다. 프로덕션 배포는 사용자 승인이 필요한 운영 변경이므로 이번 loop에서 수행하지 않았다.

## 완료 조건

OP-116을 `OPERATED`와 COMPLETE로 바꾸려면 승인된 배포 뒤 다음 자료가 필요하다. R&D 배포 ID와 코드 커밋의 일치, production `/health`의 비밀정보 없는 응답, 배포된 WellnessBox alias의 200 응답, 두 응답의 관측 시각, provider 또는 CI가 보존한 실행 기록을 연결해야 한다. 한 번의 브라우저 화면이나 로컬 curl 결과만으로는 운영 단계를 주장하지 않는다.
