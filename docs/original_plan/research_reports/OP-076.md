# OP-076 중대한 이상사례 발생 시 계획과 추가 추천을 즉시 중단한다.

manifest에 등록된 안전 중단 결과는 `wellnessbox-rnd/data/original_plan/evidence/op075_op076_followup_input_serious_ae_smoke_v1.json`에 있고, 실행 코드는 `wellnessbox-rnd/src/wellnessbox_rnd/interim/agent.py`에 있다.

## 중대한 이상사례는 다른 모든 후속 판단보다 먼저 처리해야 한다

복용 중 심각한 이상사례가 들어오면 개선 점수나 예정된 재평가와 관계없이 계획을 멈춰야 한다. 한 작업만 취소하고 추천 실행이나 알림이 살아 있으면 사용자는 중단 뒤에도 새 조합이나 복용 안내를 받을 수 있다. OP-076은 이상사례 행을 기록하는 데 그치지 않고, 연결된 계획·추천·후속 업무·새 추천 진입을 한꺼번에 막는 안전 경계를 요구한다.

## 활성 계획을 확인한 뒤 한 트랜잭션에서 중단 상태를 남긴다

`BoundedAgent.record_adverse_event()`는 중대 사례를 저장하기 전에 `execution_id`, `profile_id`, `plan_id`가 현재 활성 계획을 가리키는지 확인한다. 관계가 맞지 않으면 `serious_adverse_event_active_plan_required`로 거부한다. 유효한 사례는 `adverse_events`에 `ESCALATED`로 저장하고, 같은 트랜잭션에서 실행 원장에 `serious_adverse_event_plan_stop_v1` 이벤트를 추가한다. 중단 이벤트의 시간점은 `discontinuation`이며 사례 ID가 멱등 키에 포함된다.

그다음 같은 사용자의 진행 중 에이전트 실행과 추천 실행을 `STOPPED`로 바꾼다. 해당 계획의 열린 후속 기록은 `CLOSED`, 준비됐거나 선점된 업무는 `CANCELLED`가 되고 오류 사유에는 `SERIOUS_ADVERSE_EVENT_STOP`이 남는다. 마지막으로 긴급 약사 검토 작업을 한 건 만든다. 이 일련의 변경은 데이터베이스 잠금과 즉시 트랜잭션 안에서 처리되므로 계획 중단과 검토 요청 사이에 중간 상태가 노출되지 않는다.

## 중단과 새 추천이 엇갈리는 경쟁 조건을 막았다

새 에이전트 실행을 만드는 `create_run()`과 추천 전체 절차는 시작 전에 해결되지 않은 중대 이상사례가 있는지 조회한다. 발견되면 `serious_adverse_event_recommendation_hold`로 중단한다. `tests/test_interim_agent.py`는 실행 생성이 안전 보류 확인 직후 멈춘 상황에서 다른 스레드가 중대 사례를 기록하도록 만들어 경쟁 조건을 재현한다. 두 작업이 끝난 뒤 활성 에이전트 실행은 0건이고 중단 결과만 남아야 한다.

PRO API는 중대한 사례가 포함된 후속 설문을 받으면 설문 행보다 안전 중단을 먼저 시도한다. `tests/test_pro_plan_service.py`는 같은 사례 ID가 과거의 다른 내용과 충돌하는 경우 HTTP 422를 반환하고, 멈추지 않은 후속평가 이벤트가 0건인지 확인한다. 안전 중단이 실패했는데 일반 설문만 저장되는 부분 완료를 허용하지 않는 시험이다. 수정 전 실제 장애 로그나 최초 실패 시각은 등록 자료에서 확인되지 않음이며, 현재 회귀 시험이 보존한 위험 시나리오까지만 서술한다.

## 고정 실행에서 여덟 개 사후조건을 확인했다

기준 실행은 PRO 입력과 기기 입력이 만든 재평가 업무 두 건을 준비한 뒤 중대 사례 `ae_op075_op076_serious`를 기록했다. 결과에서 두 업무는 모두 `CANCELLED`, 두 후속 기록은 모두 `CLOSED`, 진행 중 추천은 `STOPPED`였다. 실행 원장에는 중단 이벤트가 한 건 추가됐고, 긴급 검토도 한 건 생성됐다. 이후 새 실행은 `serious_adverse_event_recommendation_hold`로 거부됐다. 같은 사례를 다시 보낼 때 기존 검토 ID가 유지되는지는 `tests/test_interim_agent.py`가 별도로 확인한다.

FastAPI 수준의 시험도 `/agent/adverse-events` 호출 뒤 일반 추천과 에이전트 추천 절차가 각각 409와 422로 차단되는지 다룬다. 약사 검토 완료 전제에는 중대 사례 보류가 활성이고 실행 원장에 중단 이벤트가 있다는 두 조건이 포함된다. 따라서 화면상 “중단” 문구만 바뀌고 실제 추천 경로가 열려 있는 결함을 이 시험 범위에서는 잡을 수 있다.

## 입증 단계는 로컬 구현에 머문다

등록된 기준 결과 자체는 `op076_proven_stage`를 `IMPLEMENTED`로 적고 `production_serious_ae_stop_proven=false`를 명시한다. manifest의 운영 근거 `wellnessbox-rnd/data/original_plan/final_session/operational_evidence/OP-076.json`은 실제 로컬 세션을 기록하지만, 그 세션의 `adverse_events` 증가량은 0이다. 그러므로 이 영수증은 중대한 이상사례 중단을 실제로 수행했다는 직접 증거가 아니다.

현재 판단은 `IMPLEMENTED`다. 로컬 임시 데이터베이스에서 원자적 중단과 재추천 차단은 재현됐지만 실제 사용자의 이상사례, 운영 업무 처리 프로그램이 맡고 있던 업무, 실제 약사의 긴급 대응 시간은 확인되지 않음이다. 운영 단계로 올리려면 가명 처리된 사례 ID, 중단 이벤트, 취소된 업무, 추천 보류, 약사 검토 시작을 같은 운영 세션에서 연결한 기록이 필요하다.
