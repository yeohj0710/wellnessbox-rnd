# OP-066 안전 차단 성분이 최적화 결과에 다시 들어오지 못하게 한다.

## 요구사항과 기존의 빈틈

안전 엔진이 막은 성분은 상품 조합 단계에서도 다시 제외되어야 한다. 추천 목록에서 성분 이름 하나를 지우는 것만으로는 부족하다. 복합 상품의 부성분으로 같은 성분이 포함되면 안전 판정 뒤에 위험 성분이 다시 들어올 수 있기 때문이다. OP-066은 상품에 선언된 전체 성분과 안전 제외 목록을 대조하고, 제외 사유가 되는 안전 규칙까지 함께 보존하라고 요구한다.

기능을 추가하기 전에는 R&D 추천 응답에 상품 예산·개수·안전 제외 조건을 전달하는 계약이 없었고, 서비스 상품 조합기도 안전 제외 성분을 별도 조건으로 받지 않았다. 커밋 `5dbe3cf`가 `ProductConstraintsRequest`, `ProductOptimizationConstraints`, `ProductCombinationFilterPolicyV1`을 추가하면서 이 빈틈을 처음 닫았다. 다만 이 첫 구현은 안전 판정이 최종적으로 차단되었을 때 요청에 있던 `payload.ingredients`만 `excluded_ingredient_keys`에 넣었다. 추천 모델이 만든 성분을 사후 안전검사에서 차단한 경우에는 그 모델 성분이 제외 목록에서 빠질 수 있었다.

커밋 `bffdd5e`의 diff는 이 실패 가능성을 구체적으로 고쳤다. `apps/inference_api/routes/interim.py`가 제외 성분을 만들 때 요청 성분뿐 아니라 `prediction.ingredients`도 합치도록 바뀌었다. 같은 커밋은 수동 고정 자료만 보던 통합 시험을 실제 R&D 안전 응답과 서비스 함수 연결을 함께 확인하는 시험으로 바꿨다. 따라서 보고서가 다루는 실패는 추정한 사고가 아니라, 초기 구현과 보강 커밋 사이에서 확인되는 계약 누락이다.

## R&D 경계에서 안전 조건을 만드는 과정

`wellnessbox-rnd/apps/inference_api/routes/interim.py`의 `_recommendation()`은 저장 프로필, 현재 요청, 두 자료를 보수적으로 합친 자료를 각각 `evaluate_safety()`에 보낸다. 초기 판정이 `BLOCK` 또는 `STOP_AND_ESCALATE`이면 추천 모델을 부르지 않는다. 초기 검사를 통과해 모델이 성분을 만들었더라도, 모델 출력 성분을 넣어 안전검사를 한 번 더 수행한다. 어느 시점에서든 중대한 실패가 생기면 응답 상태는 `BLOCKED`, 추천 목록은 빈 배열이 된다.

같은 함수는 상품 최적화 조건도 함께 만든다. `max_total_cost_krw`와 `max_products`는 요청의 엄격한 정수형 제한을 따른다. 차단 시 `excluded_ingredient_keys`에는 요청 성분과 모델 후보의 합집합이 들어가고, `safety_rule_ids`에는 실제 발동한 `finding.rule_id`가 정렬되어 들어간다. `ProductCombinationFilterPolicyV1.validate_policy()`는 제외 성분이 있는데 안전 규칙 식별자가 없으면 `safety exclusions require safety rule identities`로 자료 자체를 거부한다. 이 제약은 무엇을 뺐는지와 왜 뺐는지를 분리하지 못하게 한다.

서비스 경계도 직접 확인했다. `wellnessbox/app/api/tips/route.ts`의 POST는 `runUserInterimRecommendationRoute()`로 이어진다. `wellnessbox/lib/server/wb-rnd-interim-route.ts`는 R&D 응답에 서비스의 최종 안전 권한을 적용한 뒤 `assertWbRndProductOptimizationConstraints()`를 호출한다. 추천이 남아 있을 때만 카탈로그를 읽고 `attachWbRndProductCandidates()`를 실행한다. 즉 상품 탐색 전에 안전 조건의 형식과 값을 확인한다.

`wellnessbox/lib/server/wb-rnd-product-candidates.ts`는 R&D 성분 키를 서비스 식별자로 변환한다. 변환하지 못한 제외 성분은 `WB_RND_PRODUCT_MATCH_unmapped_safety_exclusion`으로 중단된다. 더 직접적인 방어도 있다. R&D 추천 배열에 이미 제외 성분이 다시 들어와 있으면 `WB_RND_PRODUCT_MATCH_excluded_recommendation_reentered`를 내고 상품 조합을 만들지 않는다. 변환된 제외 목록은 `buildProductCombinations()`에서 각 조합의 `ingredient_totals`와 대조된다. 추천 대상 성분뿐 아니라 선택 상품이 선언한 모든 성분 합계가 검사 대상이므로 복합 상품의 아연도 빠져나갈 수 없다.

R&D 쪽 독립 판정은 `wellnessbox-rnd/src/wellnessbox_rnd/optimizer/product_combinations.py`의 `_derive_filter_identities()`와 `evaluate_product_combination_filters_v1()`이 맡는다. 비용 초과, 상품 수 초과, 안전 제외를 서로 다른 집합으로 계산하고 세 집합의 합집합에 들지 않은 조합만 `eligible_combination_ids`에 둔다. `ProductCombinationFilterEvaluationV1.validate_filter_evaluation()`은 전달받은 결과 배열을 믿지 않고 원래 조합과 정책으로 네 집합을 다시 계산한다.

## 시험이 재현하는 차단 조건

`wellnessbox-rnd/tests/test_interim_api.py`의 `test_current_safety_input_cannot_remove_stored_high_risk_facts`는 저장 프로필의 임신 상태와 warfarin 복용을 현재 요청이 거짓 또는 빈 배열로 덮으려는 사례를 사용한다. API는 `SAFE-PREG-001`, `SAFE-DDI-001`을 유지하고 `omega3`를 제외 목록에 넣는다. `test_interim_api_blocks_emergency_before_registered_model`은 흉통이 있으면 등록 모델이 호출되기 전에 `SAFE-EMERGENCY-001`로 멈추는지도 본다.

`wellnessbox-rnd/tests/test_product_combinations.py`의 `test_combination_filter_rejects_safety_excluded_ingredient_reentry`는 마그네슘과 아연이 함께 든 복합 조합에 `ING:ZINC`와 `SAFE-OP066-TEST`를 적용한다. 통과 조합은 0건이고 안전 제외 조합은 정확히 그 한 건이어야 한다. `test_combination_filter_rejects_forged_output_and_invalid_policy`는 계산된 통과 목록을 빈 배열로 바꾼 자료와 규칙 식별자 없는 제외 정책을 모두 거부한다.

서비스 시험 `wellnessbox/scripts/qa/check-rnd-product-candidates.cts`도 `/api/tips` 경로 함수를 실제로 호출한다. 아연이 들어 있는 조합 한 건을 전부 제외하고, R&D가 차단한 `magnesium_glycinate`를 추천 배열에 다시 넣은 모순 응답은 HTTP 502로 바꾼다. `run_product_combination_constraint_safety_smoke.py`는 이 서비스 결과를 R&D 자료형으로 다시 계산한 뒤 기준 JSON을 만든다. 등록 증거 `wellnessbox-rnd/data/original_plan/evidence/op065_op066_product_combination_filter_smoke_v1.json`에는 제약 시험 4건 중 1건만 통과하고 3건이 예산과 상품 수 조건으로 제외된 결과, 안전 재진입 시험 1건이 `combo_a59680cc956bf22b`로 제외된 결과가 남아 있다. 실제 R&D-서비스 안전 조건은 `magnesium_glycinate`, `SAFE-EMERGENCY-001`, 54,321원, 최대 3개였다.

## 증거 단계와 확인하지 못한 범위

현재 단계는 `INTEGRATED`다. R&D가 만든 제외 성분·규칙 계약을 서비스 경로 함수가 소비했고, 서비스가 만든 상품 조합 결과를 R&D 판정 모델이 독립적으로 다시 계산했다. 매니페스트의 `claimed_stage=INTEGRATED`와 기준 증거의 `op066_proven_stage=INTEGRATED`가 일치한다.

운영까지 증명되지는 않았다. 기준 증거는 `actual_ready_filter_path_proven=false`, `actual_prisma_query_executed=false`, `production_catalog_operation_proven=false`, `production_data_freshness_proven=false`, `production_deployment_proven=false`를 명시한다. 이번 대조에서 서비스 소스와 시험 파일까지 직접 열었지만, 실제 운영 데이터베이스 조회나 공개 배포 요청은 실행하지 않았다. 따라서 믿을 수 있는 결론은 함수 연결 경계에서 차단 성분의 재진입이 거부된다는 것까지다. 운영 카탈로그가 갱신된 직후에도 같은 차단이 유지되고 주문 경로까지 위험 성분이 전달되지 않는지는 확인되지 않았다.
## 상품 조합을 고를 때 함께 본 조건
상품 조합은 효능 점수 하나로 결정하지 않는다. 안전하게 남은 후보, 성분 중복, 일일 용량, 가격, 재고, 제형과 복용 수를 함께 보고, 선택되지 않은 조합의 이유도 다시 설명할 수 있어야 한다.

`OP-066`는 “안전 차단 성분이 최적화 결과에 다시 들어오지 못하게 한다.”를 다루는 항목이다. 이 항목을 읽을 때는 파일이 존재한다는 사실과 요구된 동작이 증명됐다는 사실을 구분한다. 아래 근거는 이 보고서의 기존 설명을 다시 확인할 때 먼저 열어야 할 자료다.

### 근거를 읽는 순서
- 원문 출처: `docs/context/original_plan.pdf#page=20`
- 구현·설계: `wellnessbox-rnd/apps/inference_api/routes/interim.py`, `wellnessbox-rnd/src/wellnessbox_rnd/optimizer/product_combinations.py`, `wellnessbox/contracts/wb-rnd/product-candidate-match-v1.json`, `wellnessbox/lib/server/wb-rnd-product-candidates.ts`
- 테스트·실행: `wellnessbox-rnd/tests/test_interim_api.py`, `wellnessbox-rnd/tests/test_product_combinations.py`, `wellnessbox-rnd/scripts/run_product_combination_constraint_safety_smoke.py`, `wellnessbox-rnd/data/original_plan/evidence/op065_op066_product_combination_filter_smoke_v1.json` 외 1개
- 통합 증거: `wellnessbox-rnd/apps/inference_api/routes/interim.py`, `wellnessbox-rnd/data/original_plan/evidence/op065_op066_product_combination_filter_smoke_v1.json`, `wellnessbox/app/api/tips/route.ts`, `wellnessbox/lib/server/wb-rnd-interim-route.ts` 외 1개

구현 파일은 설계와 코드의 위치를 알려 주고, 테스트 파일은 어떤 분기를 실행했는지 알려 준다. 통합·운영·외부 증거가 따로 적혀 있지 않다면 구현 파일만으로 그 단계를 주장하지 않는다. 이 구분이 있어야 연구보고서가 “코드가 있다”와 “실제 연구개발 과정에서 검증됐다”를 섞지 않는다.

### 현재 단계와 해석의 경계
manifest는 요구 단계를 `INTEGRATED`, 현재 주장 단계를 `INTEGRATED`로 기록한다.
두 단계 표기는 일치하지만, 이 값이 다른 OP의 운영·외부 검증까지 자동으로 승격시키지는 않는다. 이 보고서는 연결된 증거가 직접 말하는 범위까지만 결론을 쓴다.

이번 보강은 새로운 실험 결과, 사람의 판정·승인·서명, 운영 트래픽을 추가하지 않는다. 기존 연구보고서의 사실과 증거를 더 쉽게 읽도록 연구 질문, 확인 순서, 단계 경계를 풀어 쓴다.
