# OP-033 임신·수유 상태별 제한 규칙을 분리한다.

기준 증거 `wellnessbox-rnd/data/original_plan/evidence/op033_op034_special_population_condition_safety_smoke_v1.json`은 임신, 수유, 두 상태가 함께 있는 경우를 별도 사례로 기록한다. 추천 경로에서는 임신이 `SAFETY-PREG-001`, 수유가 `SAFETY-LACT-001`을 적용하며 두 상태를 하나의 값으로 합치지 않는다.

## 하나의 ‘특수 상태’로 묶지 않은 이유

임신과 수유는 현재 제한 성분이 같더라도 적용 시점과 향후 규칙 변경 가능성이 다르다. 하나의 불리언 값으로 합치면 수유만 해당하는 사용자에게 임신 규칙을 붙이거나, 어느 상태 때문에 성분이 제외됐는지 기록에서 구분하지 못한다. 따라서 사용자 자료에 `pregnant`와 `lactating`을 독립 불리언으로 두고 규칙 식별자도 나눴다.

`wellnessbox-rnd/src/wellnessbox_rnd/schemas/recommendation.py`에서 임신과 수유는 각각 기본값이 거짓(`false`)이다. 수유가 거짓이면 저장 내용에서 생략해 기존 요청의 정규화 지문을 바꾸지 않는다. `wellnessbox-rnd/src/wellnessbox_rnd/safety/service.py`는 두 값을 각각 활성 상태 집합으로 바꾼 뒤 `special_population_rules`와 대조한다. 현재 규칙은 두 경우 모두 아슈와간다와 베르베린을 제외하지만 경고 문구와 규칙 ID가 서로 다르다.

## 두 실행 경로에서 보존한 구분

추천 엔진은 임신만 있으면 `SAFETY-PREG-001`, 수유만 있으면 `SAFETY-LACT-001`을 남긴다. 둘 다 참(`true`)이면 각 규칙이 한 번씩 적용된다. 실제 실행에 쓰는 지식 파일 `wellnessbox-rnd/data/knowledge/runtime_knowledge_db_v1.json`에도 조건 키를 `pregnancy`와 `lactation`으로 나눠 저장하고, `applies_when_pregnant`와 `applies_when_lactating`이 서로 뒤바뀌지 않았는지 확인한다.

중간 결과를 다시 계산하는 경로는 별도의 `SAFE-PREG-001`과 `SAFE-LACT-001`을 쓴다. 여기서는 각각 `BLOCK`을 반환하지만 추천 엔진의 규칙 심각도는 `warning`이므로 안전 요약은 `needs_review`다. 두 경로의 조치 수준이 같다고 주장하지 않고, 상태와 규칙 ID를 분리했다는 요구만 공통 결과로 본다.

## 변경 뒤 재발하지 않도록 시험한 항목

`wellnessbox-rnd/tests/test_special_population_condition_safety.py`는 임신 전용 객체가 `(True, False)`, 수유 전용 객체가 `(False, True)`인지 먼저 본다. 이어서 각 입력이 올바른 규칙 하나만 적용하고 제한 성분을 제외하는지, 두 상태가 함께 있을 때 두 규칙이 중복 없이 한 번씩 남는지 시험한다. `wellnessbox-rnd/tests/test_consent_and_input_hash_contracts.py`는 수유를 거짓(`false`)으로 명시한 요청과 예전처럼 필드를 생략한 요청의 정규화 내용과 내용 지문(SHA-256)이 같은지도 비교한다.

정본 실행 결과는 임신·수유 세 사례 모두 추천 경로에서 `needs_review`와 두 제한 성분을 기록했고, 재현 경로에서는 대응하는 별도 규칙을 남겼다. 실제 수정 순서는 `확인되지 않음`으로 둔다. 이전 버전의 실패 출력이 증거 파일과 시험에 포함되지 않았기 때문이다. 조사에서는 입력 형식, 규칙 자료, 실행용 지식 생성 코드, 집중 시험과 정본 결과까지 대조했다.

## 증명 단계와 주의할 범위

OP-033은 독립 입력과 규칙 적용을 자동 시험으로 재현했으므로 `IMPLEMENTED`다. 정본 결과에는 아슈와간다와 베르베린에 대한 외부 자료 주소가 정책 근거로 적혀 있지만, 해당 원문을 저장소의 근거 ID와 문장 단위 인용으로 연결한 자료는 이 OP의 등록 경로에서 확인되지 않았다. 실제 임신부나 수유부 사용, 약사 판정, 운영 서비스 연결도 관측하지 않았다. 따라서 임상적으로 충분한 규칙 집합이나 `INTEGRATED` 이상의 완료로 해석하면 안 된다.
