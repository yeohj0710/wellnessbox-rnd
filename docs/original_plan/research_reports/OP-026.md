# OP-026 모델 ID, 데이터셋 ID, 코드 커밋, 설정 해시를 실행에 기록한다.

## 같은 입력이라도 실행 버전이 다르면 같은 실험이 아니다

원본 계획 16쪽은 엔진·모델 호출과 결과 로그를 데이터 레이크에 저장하고 개인화 최적화 결과를 다시 활용하는 구조를 제시한다. 결과 payload만 저장하면 어떤 엔진 버전과 데이터로 그 결과를 만들었는지 알 수 없다. 코드나 지식 artifact가 바뀐 뒤 과거 결과를 재생해도 차이를 입력 변화로 오해할 수 있다.

OP-026은 추천 실행마다 model ID, engine version, code commit, runtime dataset ID와 파일 hash, 설정 payload와 설정 hash를 하나의 execution identity로 저장한다. identity는 추천 응답의 execution ID를 기본키로 사용한다. 실행 결과와 버전 정보가 별도 run ID로 갈라지지 않는다.

## identity schema가 실행에 필요한 버전 항목을 고정한다

`src/wellnessbox_rnd/interim/execution_identity.py`의 `ExecutionIdentityRecord`는 execution ID, model ID, engine version, code commit과 출처, dataset identity 목록, config, config SHA-256과 생성 시각을 요구한다. extra field를 금지해 임의 metadata가 조용히 섞이지 않는다.

`src/wellnessbox_rnd/interim/store.py`의 `execution_identities`는 execution ID를 기본키이자 `executions` 외래키로 사용한다. 한 실행에는 identity 한 개만 저장된다. dataset 목록과 config는 canonical JSON으로, config hash는 별도 column으로 남는다. identity가 없는 실행을 정상으로 간주하지 않도록 추천 기록 transaction에서 함께 삽입한다.

trace 조회는 저장 row를 다시 `ExecutionIdentityRecord`로 검증한다. dataset JSON이나 config가 계약을 벗어나면 그대로 반환하지 않는다. 실행 trace 소비자는 결과 event와 같은 응답에서 identity를 확인할 수 있다.

## model ID와 engine version은 실제 응답 metadata에서 온다

`build_execution_identity`는 추천 응답의 `metadata.mode`와 `metadata.engine_version`을 사용한다. 현재 deterministic baseline의 model ID는 `deterministic_baseline_v1`이다. model ID를 코드에 별도 문자열로 다시 적어 응답과 identity가 어긋나게 하지 않는다.

여기서 model ID는 학습 weight 파일의 cryptographic hash가 아니다. 현재 실행 모드를 식별하는 계약 값이다. learned model artifact를 실제 runtime에 추가한다면 model ID뿐 아니라 weight artifact와 training dataset identity를 명시적으로 확장해야 한다. 현재 네 dataset hash가 model weight 증거를 대신하지 않는다.

engine version도 응답 metadata와 동일하다. config에는 model ID와 engine version이 다시 들어가므로 config hash가 두 값을 포괄한다. 실행 row의 top-level field는 조회와 필터링을 쉽게 하고, config hash는 전체 runtime 조합 비교에 사용한다.

## code commit은 environment, Git, unresolved 순서로 결정한다

`resolve_code_commit`은 먼저 `WB_RND_CODE_COMMIT` 환경 변수를 본다. 배포나 evidence runner가 명시한 값이 있으면 `code_commit_source=environment`로 저장한다. 값이 없으면 repository `.git/HEAD`, ref 또는 packed refs에서 commit을 읽고 source를 `git`으로 표시한다.

둘 다 해석할 수 없으면 빈 값을 만들지 않고 `unresolved`를 저장한다. environment override는 배포 시스템이 제공할 수 있도록 최대 128자 문자열을 받으며 Git SHA 형식만 강제하지 않는다. 따라서 source field가 중요하다. `environment` 값이 실제 배포 commit과 일치한다는 운영 보증은 별도 배포 계약이 제공해야 한다.

`tests/test_log_separation_execution_identity.py`는 environment override가 Git보다 우선하는지, override를 제거하면 현재 Git commit을 읽는지 검사한다. canonical smoke는 고정 문자열을 환경 변수로 제공해 machine의 현재 HEAD와 무관하게 결정적인 evidence를 만든다.

## runtime dataset은 ID, 경로, 파일 SHA-256을 함께 가진다

`RUNTIME_DATASET_ARTIFACTS`는 현재 실행에 사용하는 네 artifact를 선언한다. `runtime_knowledge_db_v1`, `reference_knowledge_base_v1`, `safety_rules_v1`, `ingredient_catalog_v1`이다. 각 항목은 repository-relative path와 연결된다.

`runtime_dataset_identities`는 실행 시 파일 존재를 확인하고 bytes의 SHA-256을 계산한다. 파일이 없으면 identity를 일부만 저장하지 않고 `runtime_dataset_artifact_missing`으로 실패한다. 같은 dataset ID인데 내용이 바뀌면 hash가 달라지고 config hash도 함께 달라진다.

목록은 코드 상수의 순서를 유지하지만 config의 dataset map과 canonical JSON hash는 key 정렬을 사용한다. smoke와 currentness test는 ID 집합을 정렬해 비교한다. 이번 loop에서 smoke의 네 ID 하드코딩도 제거하고 `RUNTIME_DATASET_ARTIFACTS`에서 기대 목록을 계산하도록 바꿨다.

## config hash는 runtime 조합을 한 값으로 비교한다

config에는 model ID, engine version, lower-case app environment와 dataset ID별 SHA-256 map이 들어간다. JSON key를 정렬하고 불필요한 공백을 제거한 뒤 SHA-256을 계산한다. 같은 runtime 조합이면 request ID나 execution ID가 달라도 같은 config hash가 나온다.

반대로 사용자 입력은 config에 넣지 않는다. 입력 동일성은 execution의 request hash와 replay snapshot이 담당한다. execution ID와 created time도 config hash에서 제외된다. 버전 조합 비교와 요청 비교를 한 hash에 섞지 않는다.

두 실행의 config hash가 같다는 사실은 출력이 같다는 뜻이 아니다. 같은 코드·dataset·환경·engine 조합을 사용했다는 뜻이다. 출력 재현은 입력 snapshot과 replay 결과 hash까지 함께 비교해야 하며 그 범위는 OP-029의 session replay에서 다룬다.

## recommendation transaction이 identity 누락을 막는다

`src/wellnessbox_rnd/interim/data_lake.py`의 `ExecutionLedger.record_recommendation`은 execution row를 넣은 뒤 같은 transaction에서 `build_execution_identity`를 호출하고 `execution_identities`에 삽입한다. 이후 core event와 선택적 replay snapshot을 기록한다.

identity 생성 중 dataset 파일이 없거나 저장 제약이 실패하면 transaction 전체가 commit되지 않는다. 결과 event만 있고 identity가 없는 절반짜리 추천 기록을 정상 완료로 남기지 않는다. `execution_identities.execution_id` 외래키도 존재하지 않는 실행에 identity를 붙이지 못하게 한다.

API trace는 model ID, engine version, code commit source와 값, dataset 배열, config와 config hash를 반환한다. 내부 token이 필요한 trace endpoint를 통과해야 조회할 수 있다. 이 구현은 public 응답에 repository commit이나 내부 dataset 경로를 무조건 노출하지 않는다.

## 테스트는 두 실행의 고정값과 변동값을 구분한다

`tests/test_log_separation_execution_identity.py`는 실제 `/v1/recommend` 요청 뒤 trace를 읽는다. identity의 execution ID가 응답 ID와 같고, model ID와 engine version, environment code override, 네 dataset ID와 각 64자리 hash, config hash를 검사한다.

입력 request ID만 다른 두 실행은 서로 다른 execution ID를 갖지만 dataset identity와 config hash는 같아야 한다. test는 config의 dataset map이 top-level dataset 배열과 정확히 같은지도 확인한다. code commit resolution의 environment→Git fallback도 별도 단위 사례로 검증한다.

`tests/test_interim_store.py`는 execution identity table의 외래키와 migration을 보완한다. 이후 replay 테스트는 저장 identity와 active identity가 다르면 output replay보다 먼저 version mismatch를 반환한다. OP-026 identity가 단순 장식 metadata가 아니라 재현성 판단에 쓰이는 연결점이다.

## canonical smoke는 두 실행의 identity를 비교한다

`scripts/run_log_separation_identity_smoke.py`는 schema 14 임시 SQLite에서 같은 runtime 구성으로 추천을 두 번 실행한다. `WB_RND_CODE_COMMIT`에 고정 override를 주고 두 trace의 identity를 읽는다. identity row는 실행마다 하나씩 총 2개다.

`data/original_plan/evidence/op025_op026_log_separation_identity_smoke_v1.json`은 case count 2, execution identity 2개, code commit source `environment`, 네 dataset ID를 기록한다. model ID가 deterministic baseline인지, override가 보존되는지, 모든 dataset hash가 64자리인지, 두 실행의 config hash가 같은지를 각각 true로 남긴다.

기존 evidence는 schema 8 시점에 멈춰 있었다. 이번 loop에서 schema 14로 재생하고 evidence schema와 dataset ID가 현재 `SCHEMA_VERSION`, `RUNTIME_DATASET_ARTIFACTS`와 일치하는 회귀 테스트를 추가했다. 두 번 재생한 JSON SHA-256도 동일하다.

## IMPLEMENTED 완료와 운영 provenance의 차이

manifest의 required·claimed stage는 `IMPLEMENTED`다. identity builder, transaction 저장, 네 runtime artifact hash, code source 구분, trace 조회, 회귀 테스트와 canonical smoke가 있으므로 OP-026은 `COMPLETE`다. production 배포 시스템이 실제 image digest와 commit을 정확히 주입했다는 운영 증거는 아니다.

이번 loop는 smoke 현재성 방어와 보고서만 변경한다. 서비스 보호 파일, production, runtime dataset 내용, frozen·학습 데이터, 모델과 simulation은 바꾸지 않는다. 공식 frozen 256건 일곱 지표, replay와 weakest slice delta는 0이다. `OPERATED` 승격에는 배포 image·commit·dataset artifact를 연결한 실제 실행 receipt와 unresolved 비율 0 관측이 필요하다.
