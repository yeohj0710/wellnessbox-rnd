# OP-042 건강 목표별 후보 성분 prior와 근거를 등록한다.

## 요구사항과 기존 점수의 한계

OP-042는 사용자가 선택한 건강 목표와 후보 성분의 기본 연결 점수를 버전이 있는 자료로 분리하고, 각 점수에 출처와 주장 식별자 및 제한 문구를 붙이는 요구사항이다. prior는 추천 순서를 위한 사전 점수이지 치료 성공 확률이나 개인별 효능 수치가 아니다.

변경 전 후보 점수는 카탈로그의 supported_goals가 사용자 목표와 맞는 개수에 고정 가중치를 곱하는 방식에 의존했다. 어떤 목표·성분 조합이 왜 같은 점수를 받는지, 임상 근거인지 내부 선택 정책인지, 근거가 약하면 탐색 목적으로만 써야 하는지를 실행 결과에서 구분하기 어려웠다.

정확한 manifest 경로는 data/original_plan/requirements_manifest_v1.json이다. OP-042는 그룹 E의 기본 단계와 claimed_stage 모두 IMPLEMENTED다. 등록 근거를 확인한 결과 이 단계는 유지할 수 있지만, 공동 스모크 전체를 현재 코드로 재실행한 증거는 아니다.

## 등록 자료와 점수 의미

data/knowledge/goal_ingredient_priors_v1.json의 schema_version은 goal_ingredient_priors_v1, prior_version은 2026-07-16.2다. 24개 레코드가 blood_glucose, bone_joint, energy_support, general_wellness, gut_health, heart_health, immunity_support, sleep_support, stress_support의 아홉 목표를 모두 덮는다.

score_scale은 일반 목표 사전 점수를 35, general_wellness 점수를 18로 둔다. 각 레코드는 ingredient_key, goal_key, prior_score, evidence_strength, evidence_direction, reference_ids, claim_ids, limitations를 가진다. 예를 들어 coq10과 heart_health는 근거가 inconclusive이고 exploratory_only이며, magnesium_glycinate와 sleep_support는 mixed 및 exploratory_only다. coq10과 energy_support처럼 등록 임상 주장이 없는 조합은 policy_only와 selection_policy_only로 명시된다.

18점 또는 35점은 연구 결과에서 계산한 효과 크기가 아니다. data/knowledge/reference_knowledge_base_v1.json의 REF-MC-GOAL-PRIOR-001과 CLM-MC-GOAL-PRIOR-POLICY-001이 점수 정책의 소유권을 밝히고, 외부 근거 주장은 별도의 reference_id와 claim_id로 연결된다. 제한 문구는 성분 범주 근거와 특정 제형 근거를 구분하고, 결핍이 없는 집단의 무효 또는 불확실한 결과도 보존한다.

## 로더와 후보 점수 함수

src/wellnessbox_rnd/knowledge/goal_priors.py는 GoalIngredientPriorRegistry와 레코드 스키마를 정의하고 load_goal_prior_registry, validate_goal_prior_registry, get_goal_prior_index를 제공한다. 검증기는 버전, 적용 시각, 점수 범위, 중복 조합, 아홉 목표의 범위, 카탈로그 성분·목표 관계를 확인한다. 선언한 reference_id가 실제 지식 자료에 있는지, claim_id가 그 출처에 속하는지, 주장 범위가 목표와 성분을 포함하는지도 검사한다.

src/wellnessbox_rnd/efficacy/service.py의 score_candidate는 get_goal_prior_index에서 (item.key, goal) 조합을 찾아 prior_score를 합산한다. 더 이상 카탈로그 목표 일치만으로 임의의 35점을 만들지 않는다. src/wellnessbox_rnd/knowledge/runtime_db.py의 build_runtime_knowledge_db는 같은 레코드를 런타임 DB에 넣고 validate_runtime_knowledge_db가 저장본과 새 빌드 결과를 검사한다.

data/knowledge/runtime_knowledge_db_v1.json은 현재 prior 레코드를 포함한 실행용 자료다. data/knowledge/reference_knowledge_base_v1.json은 각 레코드가 참조하는 출처와 정규화된 주장을 보유한다. 원본 등록 파일, 출처 지식, 실행용 DB가 서로 다른 역할을 가지며 검증 함수가 세 자료의 관계를 확인한다.

## 근거 위조와 과장 방지 테스트

tests/test_goal_ingredient_priors.py의 test_current_goal_prior_registry_is_evidence_linked_and_covers_every_goal은 24개 레코드와 아홉 목표 범위를 검사한다. test_goal_prior_validation_rejects_score_outside_versioned_policy는 18·35 정책 밖 점수를 거부한다. test_goal_prior_validation_rejects_claim_from_another_reference와 test_goal_prior_validation_rejects_reference_without_owned_claim은 출처를 빌려 붙이거나 주장이 소유하지 않은 참조를 추가하는 경우를 찾는다.

test_goal_prior_validation_rejects_clinical_strength_without_clinical_claim과 test_goal_prior_validation_rejects_forged_policy_claim_type은 내부 정책을 임상 근거처럼 표시하지 못하게 한다. test_runtime_goal_priors_preserve_claim_scope_and_validate와 test_stored_runtime_db_matches_fresh_builder는 실행용 DB에서도 같은 제한을 보존한다. test_candidate_goal_alignment_uses_registered_prior_scores는 실제 후보 점수가 등록 값 35와 연결되는지 확인한다. test_weak_or_null_evidence_is_exploratory_only는 mixed, inconclusive, null_without_deficiency 조합을 탐색 목적으로 제한한다.

tests/test_reference_ingestion.py는 출처 문서의 메타데이터와 주장을 읽어 지식 자료를 만드는 절차를 검증한다. tests/test_runtime_knowledge_db.py는 필수 테이블, 출처 연결, 중복 주장과 잘못된 출처 관계를 검사해 prior가 런타임 자료의 다른 규칙과 같은 검증 경계를 통과하게 한다.

## manifest 등록 경로와 공동 스모크 상태

구현 근거는 data/knowledge/goal_ingredient_priors_v1.json, src/wellnessbox_rnd/knowledge/goal_priors.py, src/wellnessbox_rnd/efficacy/service.py, src/wellnessbox_rnd/knowledge/runtime_db.py, data/knowledge/reference_knowledge_base_v1.json, data/knowledge/runtime_knowledge_db_v1.json이다. manifest의 원문 경로 예시는 wellnessbox-rnd/data/knowledge/goal_ingredient_priors_v1.json이다. 여섯 파일 모두 존재하고 OP-042의 자료 등록·검증·소비 경로와 맞는다.

테스트 근거는 tests/test_goal_ingredient_priors.py, tests/test_reference_ingestion.py, tests/test_runtime_knowledge_db.py, scripts/run_ingredient_mapping_goal_prior_smoke.py, data/original_plan/evidence/op041_op042_ingredient_mapping_goal_prior_smoke_v1.json이다. 저장 JSON의 goal_priors 부분은 version=2026-07-16.2, record_count=24, 아홉 covered_goals, coq10과 omega3의 heart_goal_alignment=35를 기록한다. production_operation_proven은 false다.

그러나 같은 스크립트와 JSON은 OP-041의 이전 맵 2026-07-16.1을 함께 검사한다. 현재 맵은 2026-07-24.1이고 스크립트는 이전 값을 강제하므로, 공동 스모크를 지금 실행하면 prior 검사에 도달했더라도 전체 실행은 성공 결과를 만들 수 없다. 저장 JSON의 OP-042 prior 구간이 현재 자료와 맞는 사실과, 현재 소스로 공동 스모크가 성공했다는 주장은 구분해야 한다.

## 현재 단계와 확인하지 못한 사항

현재 근거 단계는 IMPLEMENTED다. 버전이 있는 24개 레코드, 출처·주장 소유권 검사, 실행용 DB 저장, 후보 점수 소비, 세부 회귀 테스트가 요구사항을 구현한다. prior가 실제 프로덕션 추천에 배포되어 사용됐다는 운영 기록이나 외부 효능 검증은 없다. 이번 검토에서 tests/test_goal_ingredient_priors.py, tests/test_reference_ingestion.py, tests/test_runtime_knowledge_db.py의 OP-042 단언은 통과했다. OP-041의 이전 성분 맵 버전을 포함한 공동 스모크는 재실행하지 않았다.

추가로 확인해야 할 항목은 OP-041 맵 검사를 최신화한 뒤 공동 스모크를 다시 생성하는 것, 배포 식별자와 함께 실제 서비스 응답의 goal_alignment가 등록 레코드와 일치하는지 기록하는 것, 정책 점수 18·35가 추천 품질에 미치는 영향을 별도 평가로 검증하는 것이다. 이 작업이 끝나기 전에는 INTEGRATED, OPERATED, EXTERNAL 단계를 주장하지 않는다.
