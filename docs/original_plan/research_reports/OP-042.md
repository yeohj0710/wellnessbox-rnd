# OP-042 건강 목표별 후보 성분 prior와 근거를 등록한다.

## 후보 prior가 해결하는 문제

후보 성분 prior는 개인 관측값을 적용하기 전에 건강 목표와 성분의 기본 관련성을 점수로 표현한 값이다. 같은 안전 조건을 통과한 성분이 여러 개일 때 아무 기준 없이 순서를 정하면 결과가 실행마다 달라지거나 코드에 숨은 임의 순서가 추천을 좌우한다. 목표별 기본 점수와 근거를 데이터 파일에 등록하면 후보 순서를 결정한 출발점을 검토하고 버전별로 비교할 수 있다.

여기서 prior 점수는 효능 확률이나 임상적 성공률이 아니다. 등록 파일은 점수를 “후보 정렬용 점수”로 정의한다. 현재 `wellnessbox-rnd/data/knowledge/goal_ingredient_priors_v1.json`의 버전은 `2026-07-16.2`이며 24개 기록이 추천 API의 건강 목표 9종을 모두 포함한다. 점수는 표준 관련성 35점과 일반 웰니스 관련성 18점으로 구분된다. 숫자가 높다는 사실만으로 효과 크기나 복용 적합성을 주장할 수 없다.

## 점수와 근거를 함께 고정한 방법

각 기록은 건강 목표, R&D 성분 키, 점수, 근거 강도, 근거 방향, 참고 문헌 ID와 주장 ID를 묶는다. 정책 근거만 있는 기록은 `selection_policy_only`, 약하거나 결론이 섞인 근거는 `exploratory_only`처럼 사용 범위를 제한한다. 임상 주장이 꼭 필요한 근거 강도와 정책만으로 허용되는 경우를 구분해, 참고 문헌이 존재한다는 이유만으로 임상 효능을 과장하지 않는다.

`wellnessbox-rnd/src/wellnessbox_rnd/knowledge/goal_priors.py`는 등록 파일을 읽어 목표와 성분의 복합 키 인덱스를 만든다. `wellnessbox-rnd/src/wellnessbox_rnd/efficacy/service.py`의 후보 점수 함수는 선택된 건강 목표와 성분이 일치할 때 이 점수를 합산한다. 근거 ID와 주장 ID는 런타임 지식 데이터베이스의 실제 항목과 연결되어야 하므로, 점수만 따로 바꾸거나 존재하지 않는 주장을 붙일 수 없다.

## 검증에서 잡는 오류

등록기 시험은 허용되지 않은 점수, 참고 문헌과 다른 주장, 정책 문헌에 위조한 임상 주장, 아무 기록에서도 사용하지 않는 참고 문헌을 거부한다. 런타임 데이터베이스 시험은 참조 지식에서 가져온 문헌과 주장이 유효한지 확인한다. 직접 확인한 12개 참고 문헌은 모두 기준 지식 파일에 존재했고 해당 주장과 연결되어 있으며 폐기 시각이 설정되지 않았다.

스모크 검증은 24개 prior가 9개 목표를 모두 덮는지 확인하고, 심장 건강 목표에서 오메가3와 코엔자임 Q10 후보가 각각 35점의 목표 정렬 점수를 받는 경로를 실행했다. 증거 파일 `wellnessbox-rnd/data/original_plan/evidence/op041_op042_ingredient_mapping_goal_prior_smoke_v1.json`에는 등록 버전, 기록 수, 목표 범위와 사용한 12개 문헌 ID가 남아 있다. 별도 API 계약 시험은 prior 점수가 다른 신호 점수와 합쳐진 최종 후보 점수와 일치하는지도 확인한다.

## 확인 결과와 남은 한계

현재 완료 단계는 **IMPLEMENTED**다. 목표별 등록 자료, 로더, 점수 계산 연결, 참조 무결성 시험과 스모크 증거가 있다. 9개 목표가 모두 등록됐다는 것은 빈 목표 때문에 후보 순서가 무작위로 되는 문제를 막았다는 뜻이다. 반면 prior가 실제 사용자 성과를 높였거나 35점과 18점의 간격이 최적이라는 근거는 아니다.

등록 자료의 일부는 임상 결론이 아니라 선택 정책 또는 탐색적 근거에 머문다. 따라서 서비스 설명은 후보 정렬 근거와 임상 효능 근거를 구분해야 한다. 실제 추천 품질, 전문가 검토 일치도, 운영 환경의 성과를 측정한 자료도 확인되지 않았다. 향후 점수를 바꾸려면 같은 문헌·주장 무결성 검사를 통과시키고, 버전이 바뀐 이유와 순위 영향도 함께 기록해야 한다.
