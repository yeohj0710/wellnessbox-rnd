# 운영 세션과 약사 검토 절차

## 서로 다른 실제 프로필 5개를 누적하는 방법

운영자는 콘솔 H-007에서 사용자 화면을 열고 서로 다른 사람 또는 명시적으로 구분한 실제 연구 프로필을 하나씩 입력한다. 최소 5개 프로필은 연령, 목표, 복용약물 조합이 서로 달라야 한다. 각 프로필마다 설문 저장, 추천 실행, 후속평가 저장, 약사 검토 대기열 생성까지 실제로 실행한다. 자동 생성 데이터나 버튼을 누르지 않은 가상 기록은 운영 영수증으로 만들지 않는다.

세션을 시작하기 전에 `scripts/report_operational_session_readiness.py`를 실행해 현재 누적 유효 세션 수, 서로 다른 실제 프로필 수, 대기 약사 초안 수를 확인한다. 한 프로필의 전 경로를 마친 뒤 운영 영수증을 확정하고 다음 프로필로 넘어간다. 콘솔 H-007은 누적 세션 수와 서로 다른 프로필 수를 함께 표시한다.

## 권혁찬 약사의 실검토

권혁찬은 콘솔 H-003에 본인 이름을 입력한 뒤 `pending` 초안을 승인, 수정 승인 또는 반려한다. 오너 이름으로 대신 승인하지 않는다. 실제 추천 실행에서 만들어진 초안만 검토하며 대기 건수를 늘리려고 데이터를 자동 생성하지 않는다. 현재 실제 원장에 새 대기 초안이 충분하지 않으면 운영 세션을 먼저 수행한다.

## 승인 데이터로 한 번 학습하고 비교하는 방법

약사 승인 데이터가 쌓인 뒤 기존 고정 평가 세트의 파일과 해시를 보존한다. 고정 평가 세트를 재생성하거나 사례를 교체하지 않는다. 승인된 초안만 학습 입력으로 읽어 새 모델 버전을 만든다. 기존 모델과 새 모델을 같은 고정 평가 세트에 순서대로 실행하고, 추천 정확도·안전 지표·슬라이스별 결과를 같은 보고서에 전후 비교한다. 지표가 나빠지거나 안전 회귀가 있으면 모델을 교체하지 않는다.

실행 순서는 `고정 평가 세트 해시 확인 → 기존 모델 평가 → 승인 데이터 학습 → 새 모델 평가 → 전후 차이 보고서 생성 → 안전 회귀 확인 → 모델 교체 여부 결정`이다.
